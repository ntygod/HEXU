# HEXU · 合序

### 让人和 AI，一起交付。

**面向人和 AI 的研发协作工作台**

</div>

---

HEXU 将需求、任务、成员、AI 工具、模型、代码与成果连接起来，让一项工作可以跨人、跨工具、跨环境持续推进。

**不用反复解释，不用反复追问，不用四处找成果。**

它不是另一个聊天窗口集合，也不是监督开发者或强制验收的后台。保留个人工具选择，用轻量项目组织工作，把主要精力放在实际协作与成果体验上。

> **当前状态：产品规划阶段，尚未实现所述应用能力。** 文档基线为 **v1.1 · 2026-09-25**，不是软件发布版本。本轮已将产品方向调整为“轻管理、深协作、成果直观”；质量与效果评估由内部团队安排。

## 产品如何工作

**开始工作 → 继续与协作 → 查看成果和反馈 → 团队标记完成。**

从一句需求、一个问题或已有目录开始，系统带入项目、负责人和必要资料。简单任务直接做，复杂工作再补说明、拆任务与安排里程碑。

网页是团队统一入口；开发者可以继续在本地环境工作，也可选择远程节点。不需要先有完善内网、外部需求系统或统一身份服务。

## 三个核心协作动作

| 动作 | 用户体验 |
| --- | --- |
| **继续** | 在同一任务中换工具或模型，接着当前工作，不从头解释 |
| **协助** | 选一个问题、报错、文件或成果，请同事或另一个 AI 帮忙，不转交整个任务 |
| **并行** | 在独立工作分支探索不同方案、分工推进，比较成果后选择或整合 |

优先接入 Claude Code 和 Codex，保留工具与模型的实际能力差异。跨工具接续依靠代码现场与必要上下文，不承诺模型隐藏状态无损迁移。

## 完整产品范围

| 工作区域 | 主要内容 |
| --- | --- |
| 工作台 | 我的工作、团队目标、待回复事项、最近成果 |
| 项目 | 轻量需求、任务、成员、资料、约定、依赖和里程碑 |
| 任务工作区 | 人与 AI 协作、上下文、代码、终端、预览和工具接续 |
| 成果 | 功能预览、文件、变更说明、反馈、继续与完成记录 |

任务工作区从任务直接进入，不是另一套独立的 AI 任务系统。工具、模型、节点、账号与集成在需要时就地选择，集中维护放在资源设置中。

## 默认轻量，必要边界清楚

任务默认 **待处理 → 进行中 → 已完成**，等待反馈、受阻和暂缓按需显示。创建时自动带入负责人和归属，不要求先写完整 PRD、安排验收人或上传测试报告。

团队按自己的方式标记完成、反馈和重新打开。检查记录、CI、内部评估与发布链接可以关联，但不是平台强制门槛。

任务完成、AI 执行结束和实际发布是不同事实。权限、保存变更、正确停止、防止误覆盖和状态准确仍属于基础能力，不因流程变轻而取消。个人探索不会自动向团队公开全部历史。

## UI 与产品状态

UI 与核心功能同步设计，重点是工作台、任务工作区和成果页。日常首页不以宣传画面或无依据的百分比代替工作；工具切换不是几个 Logo 的并排展示。

此前会话中的 UI 概念图只作风格探索。当前已有页面与交互规划，尚未据此完成高保真可点击原型或前端实现；本轮没有重新生成设计图。

## 自研与复用

HEXU 自主设计产品、领域与体验，不预设 fork 某个完整平台。Git、数据库、编辑器、终端和原生 AI 能力可以合理复用，具体组件按许可证、维护成本与实际支持范围选择。

本轮仅修改 Markdown 文档，没有添加应用代码、选定软件许可证、更改仓库可见性、部署服务或接入公司模型账户。
