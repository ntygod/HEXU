# 04｜信息架构与 UI/UX 设计

> 规划基线 v1.0 · 2026-09-25 · 本文是设计目标与低保真结构，不是已完成的高保真设计或前端实现。  
> [返回入口](../../README.md) · [管理层概要](00-executive-brief.md) · [功能需求](03-functional-specification.md)

## 1. 设计命题

**让首次看到 HEXU 的人理解它的价值，让每天使用 HEXU 的人减少负担。**

产品不能因为内部使用就忽略视觉，也不能为了演示好看制造虚假进度。第一印象来自清晰的目标、真实的成果和一致的界面；长期信任来自状态准确、操作可预期和异常可恢复。

用户应先看到工作，再看到工具；先看到需要判断的事项，再看到完整日志。AI 是执行者之一，不是所有页面的视觉主角。

## 2. 品牌和视觉方向

主品牌：**HEXU · 合序**。描述：**AI 研发协作平台**。主标语：**让人和 AI，一起交付。**

推荐气质为专业、明亮、克制、有秩序。避免赛博装饰、机器人墙、无意义光效和满屏大数字。不通过复制其他产品商标或完整视觉资产建立品牌。

### 建议的设计变量

以下数值是待原型验证的建议，不是已经批准的视觉规范。

| 项目 | 建议基线 |
| --- | --- |
| 主色 | 靛蓝 `#4F46E5`，用于主要操作和选中态，不用于所有图表 |
| 浅色背景 | `#F7F8FA`；内容面板 `#FFFFFF` |
| 主文字 | `#182230`；次要文字 `#475467` |
| 语义色 | 成功 `#067647`、警告 `#B54708`、错误 `#B42318`，实际组合需检查对比度 |
| 深色模式 | 独立色板，不简单反相；主要面向长时开发工作区 |
| 字体 | 优先系统中西文字体，代码使用等宽字体；不依赖未经许可字体文件 |
| 字号 | 正文 14–16，辅助信息不低于 12；标题 20–28，数字等宽对齐 |
| 间距 | 4 的倍数，主要内容间距 16／24／32 |
| 圆角 | 常规组件 8，主要面板 12，避免所有区域都胶囊化 |
| 动效 | 普通过渡约 120–180ms，支持减少动态效果设置 |

人使用头像和姓名；AI 使用工具图标、模型和执行标签。重要记录标明“人工确认”“AI 建议”“系统检测”或“状态未知”。语义色必须配文字／图标，不依赖颜色单独表达。

正文对比度建议至少 4.5:1，键盘焦点必须清晰；这些是验收目标，不构成已通过任何无障碍认证的声明。

## 3. 信息架构

```text
HEXU
├── 工作台
│   ├── 我的工作：当前任务、个人探索、最近项目
│   ├── 团队概览：目标、交付、风险
│   └── 待我处理：确认、授权、接手、验收
├── 项目
│   └── 项目详情
│       ├── 总览
│       ├── 需求
│       ├── 任务：列表／看板／依赖
│       ├── 决策与规则
│       └── 交付
├── 交付：待验收、已验收、发布记录
├── 知识：项目规则、决定、模板与检索
└── 资源与设置
    ├── 执行节点
    ├── 工具、模型与账号引用
    ├── 成员、权限与预算
    └── 集成、审计和数据管理
```

全局提供工作空间切换、搜索、通知和个人菜单。默认视图可按角色设置，但切换视图不会提升权限。个人探索与团队任务要有明确归属提示，避免误发到团队。

一级导航不直接展示所有十二个功能模块。工具与模型在任务需要它们时出现，配置入口放到资源区。

## 4. 通用布局

桌面侧栏建议约 216–232px，可收起；顶部保留项目、导航与搜索。管理页面留白充分，开发页面可选择紧凑密度。

任务工作区在足够宽度下支持可调整三栏：任务上下文、AI 协作、代码／成果。小于约 1280px 时，右侧成果切为标签或抽屉，不能把三栏都挤成难读窄列。小于约 768px 时，优先查看、评论、验收和授权，不搬入完整终端编辑体验。

宽度断点和密度需要在真实设备验证；保留用户调整结果，提供重置布局。

## 5. 页面设计

### P01｜工作台与管理概览

**目的：**迅速知道目标、成果和需要处理的问题。关联 HX-F10。

主要内容为当前目标、关键项目、待决策事项与近期交付。成果卡片展示具体内容、有效验收状态和预览入口，而不是只显示任务数量。

```text
┌ HEXU ─ 工作空间 ───────────── 搜索 ─ 待我处理 ─ 个人 ┐
│ 导航 │ 当前目标：本次迭代交付订单管理改进            │
│      │ [需要我确认 2] [待验收 1]   查看统计口径      │
│      ├──────────────────┬──────────────────────────┤
│      │ 项目与里程碑     │ 需要处理                  │
│      │ 订单导出         │ 字段范围待确认 → 查看差异 │
│      │ 状态、负责人     │ 测试环境不可用 → 查看原因 │
│      ├──────────────────┴──────────────────────────┤
│      │ 最新成果：订单导出预览 [查看功能] [去验收]    │
└──────┴─────────────────────────────────────────────┘
```

计数仅来自真实记录。没有有效数据时用说明和创建入口，不使用零值图表填满页面。演示模式明确显示“演示数据”。

风险卡片包含事实、推断标记、影响、责任人和下一步。禁止只有“风险较高”却无出处。不能用在线时长、消息量或 Agent 数量排名成员。

### P02｜需求与方案页

**目的：**把自然语言整理为可以确认的工作。关联 HX-F02、F03。

原始材料与整理后的需求并列或可切换。AI 补充内容突出“待确认”，需要确认的问题集中在右侧或顶部，不穿插几十个连续弹窗。

显示目标、范围、非目标、验收项、版本与确认人。主操作随状态变化：整理需求、请求确认、确认版本、生成任务建议。拆分结果先作为建议列表，再由负责人安排执行。

修改正式版本时，打开变更比较，显示新增／删除、理由和受影响任务。确认按钮应描述动作，例如“确认需求 v2”，而不是笼统的“确定”。

### P03｜任务执行工作台

**目的：**不离开任务就能理解目标、协作与结果。关联 HX-F04、F05、F06。

顶部固定任务名称、真人责任人、当前操作者、执行环境、工具与模型、运行状态。信息优先级低于目标的技术标识可展开。

```text
任务：订单导出  | 责任人：演示成员甲 | 环境：个人节点
需求 v2 · 代码检查点 c17 · Claude Code / 已验证模型配置
[运行中]  [请求停止]  [换工具继续]  [交给同事]  [更多]
┌────────────────┬────────────────────┬──────────────────┐
│ 目标与验收项   │ 关键执行时间线     │ 代码／预览／测试 │
│ 已确认决定     │ 当前动作与输出     │ 变更文件         │
│ 依赖与阻塞     │ 需要用户回答的问题 │ 实际页面         │
│ 上下文清单     │ 输入与附件         │ 验证记录         │
└────────────────┴────────────────────┴──────────────────┘
```

默认时间线展示计划、关键动作、错误、产物与问题；原始日志可展开。不要以逐 token 动画代替有意义进度，也不把一个正在运行的 spinner 表述为功能完成百分比。

工具与模型选择器说明当前账号、可用能力和变更影响。不支持原地切换时明确“停止后创建新执行”；运行尚未停止时接力按钮进入检查流程，而不是直接启动另一个写入者。

未提交改动、外部编辑、缺少上下文、模型限额和失联在顶部有可定位提示。复制、打开 IDE、复制验证命令是辅助动作，不挤占主要任务操作。

### P04｜交接检查页

**目的：**把交接做成可验证动作。关联 HX-F06。

采用分步侧栏或全页：选择接手者／工具 → 检查现场 → 审阅交接包 → 发布与接手确认。

检查项包括原执行是否停止、代码检查点是否可用、未包含文件、环境与权限、敏感信息和变更后的数据发送范围。每项显示通过、待处理、无法验证及原因。

交接包允许编辑，同时保留生成来源。接受方可预检、拒绝并说明缺少条件；发布不等于接手成功。

清楚区分“交出操作权”和“转移任务责任”。默认不转移责任人，除非用户明确选择并取得接收确认。旧运行无法确认停止时，只提供安全替代，例如独立副本检查，不显示强制接管的便利入口。

### P05｜团队协作与依赖视图

**目的：**看到相互影响，而不是监视个人。关联 HX-F03、F06。

默认是任务列表或看板，提供成员筛选和依赖视图。依赖图仅在能帮助理解关系时展开，避免数百节点造成视觉噪声。

每项展示责任人、当前执行者、输入输出约定、阻塞和最近的已确认变化。影响范围重叠是提醒，不显示“无重叠＝安全”。

决定传播以“已通知／负责人已确认／运行上下文已更新”区分。成员可以批量处理相关提醒，但重大变更仍需明确选择受影响任务。

### P06｜待我处理

**目的：**统一人的关键介入点。关联 HX-F10、F11。

按需求确认、权限、交接、验收和异常分组。列表展示为什么需要我与影响范围；打开后给出足够依据再操作。

权限面板必须显示操作对象、环境、来源任务、有效期与允许范围。高风险操作不能只显示“Agent 需要帮助”。过期、撤回、已消费和上下文不匹配请求不能继续点击批准。

支持稍后处理、订阅与通知降噪。自动过期不等于自动批准；重大操作不通过批量“一键同意”掩盖细节。

### P07｜验收与交付页

**目的：**非开发者也能检查成果，同时保留技术依据。关联 HX-F09。

主要区域展示实际页面、接口样例或文件；另一侧为需求版本和验收清单。下方提供变更摘要、测试与审阅证据、已知风险和版本记录。

证据显示未运行、通过、失败、需复核，不能用一个绿色总图标隐藏缺失项。代码发生变化时突出“当前版本尚未重新验证”。

“接受结果”“退回修改”“批准发布”是不同动作。接受剩余风险需要有权限的人明确记录，不默认勾选。预览关闭或失效显示真实原因和替代产物入口。

### P08｜节点、工具与运行资源

**目的：**接入方便，但权限边界清楚。关联 HX-F01、F11。

节点卡片展示归属、个人／团队类型、系统、健康、最后确认时间、支持工具及授权范围。连接向导解释什么会同步、谁能使用和如何撤销。

工具卡片展示已验证版本、支持能力和限制。账号以引用和身份摘要展示，不显示完整密钥。不提供默认合并个人凭证池的设置。

节点失联显示最后已知状态，不能直接显示空闲。权限撤销和升级包含对正在执行任务的影响说明。

## 6. 所有页面必须覆盖的状态

| 情况 | 应显示的内容 | 禁止的反馈 |
| --- | --- | --- |
| 未开始 | 清楚的开始入口与必要准备 | 假数据图表、空白无引导 |
| 加载／同步 | 正在获取哪部分信息，已有数据时间 | 全屏阻塞所有已可用信息 |
| 运行中 | 当前阶段与最后确认时间 | 无依据的完成百分比 |
| 等待用户／授权 | 需要谁处理、问题与后果 | 长时间只显示“运行中” |
| 请求停止 | 正在停止、最后确认、必要风险说明 | 点击即显示“已停止” |
| 节点失联 | 状态未知、最后确认、可采取动作 | 自动判成功或自动重试副作用 |
| 权限不足 | 缺少哪种权限和合适的申请路径 | 泄露无权资源详细内容 |
| 部分能力不支持 | 支持范围与可行替代 | 保留可点击按钮后静默无效 |
| 证据过期 | 哪项变化导致需复核 | 沿用旧绿色通过标记 |
| 执行失败 | 可定位错误、已保留产物、恢复选择 | 只有错误码或清空全部现场 |

## 7. 文案与交互约定

使用“任务”“执行”“交接”“验收”等稳定术语，不交替使用多个模糊同义词。原生工具的 thread、session、turn 放在技术详情，不要求普通用户理解。

建议文案：

- “执行已结束，等待验收”，而不是“全部完成”。
- “节点离线，状态未知；最后确认于 14:32”，而不是“任务失败”。
- “准备交接：缺少可访问的代码检查点”，而不是“交接成功”。
- “预计费用，尚未与账单核对”，而不是“实际花费”。

删除默认优先归档，有恢复能力的动作说明期限。不可逆删除、发布、扩权等明确说明影响；普通低风险编辑不制造过度确认。

日期显示用户时区并允许查看绝对时间。重要版本与证据不能只用“刚刚”“昨天”等相对时间定位。

## 8. 无障碍与国际化

中文优先，产品术语建立中英文映射，内部标识统一英文。布局允许更长译文，不能把文案写死在固定宽度按钮里。

键盘可完成搜索、任务切换、评论和主要确认；焦点顺序合理；弹窗返回原焦点。所有状态、图标按钮和表单有可读名称。不能仅靠拖拽完成分工，提供替代操作。

支持缩放、减少动态效果和合理的目标点击尺寸。代码与终端采用不打断阅读的状态通知，不持续向辅助技术播报每个 token。

## 9. 向管理层展示的完整脚本

使用虚构的“订单按月份导出”项目。先从首页展示目标，再打开需求原文与确认版；展示两位成员在不同工具中推进相关任务；演示一次真实或明确标记的模拟交接；最后进入功能预览和验收。

演示不依赖每次模型都生成相同代码。原型阶段使用明确标记的模拟状态；实际产品演示应使用已准备且可复现的测试仓库和有效证据，不用回放内容假装实时执行。

页面要讲清“目标 → 协作 → 结果”，不需要在首次演示中展示所有节点配置和完整日志。

## 10. 设计交付与验收

设计阶段应产出：信息架构、主要用户流、五个核心页面的高保真方案、交接与授权弹层、组件状态、浅／深色变量、关键响应式布局与可点击原型。

高保真方案至少覆盖 P01、P02、P03、P04、P07；P05、P06、P08 不能只留菜单，需要在对应功能实施前完成详细设计。

验收不仅检查截图，还要完成：第一次提出需求；找到待处理事项；切换工具前识别风险；理解失联状态；找到有效验收证据。设计不能把未实现能力包装成真实成功。关联 HX-AT20。
