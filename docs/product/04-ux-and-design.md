> [返回入口](../../README.md) · [产品概要](00-executive-brief.md) · [功能规格](03-functional-specification.md) · [本轮调整](09-planning-revision.md)

## 1. 设计命题

**第一次看到时理解价值，每天使用时顺畅推进工作。**

工作是视觉主体，工具是参与者。管理者看目标与成果，开发者看任务与现场，双方基于同一数据。简单工作不经过复杂表单，高级能力有清楚入口，不以删掉能力换取表面简洁。

本轮三项重点：任务与 AI 执行合一；继续、协助、并行成为明确动作；成果页从验收中心转为预览与反馈。理论取舍见 [08](08-decisions-risks-and-sources.md)。

## 2. 已确认设计与参考的边界

已确认的暗色青色任务工作台为 [Workbench W1](../design/README.md) 基线，并保存[可交互参考](../design/workbench-reference.html)。Figma 11 页方案选择性贡献求助材料卡、交接摘要／变更／待办／环境和团队管理信息结构；不替换任务一体化主骨架，不沿用企业注册前置或“完成并验证”等交互语义。截图和演示均不证明真实执行能力。

| 概念图问题 | 后续设计要求 |
| --- | --- |
| 登录后首页出现大幅山景与开始使用按钮 | 品牌画面留在官网或首次欢迎页，日常首页进入实际工作 |
| 大量数字与无依据百分比 | 改为当前任务、待回复、阻塞和近期成果；计数说明口径 |
| 任务与 AI 工作区分成孤立入口 | 同一个任务直接进入执行工作区，不维护两套记录 |
| 模型、工具、代码平台和 Docker 混排 | 分开执行工具、模型配置、集成与运行资源 |
| 团队页侧重在线与离开 | 侧重负责事项、参与关系和请协助入口 |
| 多工具只有标签，没有工作动作 | 显示继续、协助、并行及结果如何回到当前任务 |
| 不一致的日期、示例模型和状态 | 使用统一虚构数据，模型来自已接入配置，标注演示状态 |

## 3. 品牌与设计系统

品牌：**HEXU · 合序**。标语：**让人和 AI，一起交付。** 描述：面向人和 AI 的研发协作工作台。

采用暗色优先、青色强调、紫色识别 AI 的专业工作台，完整提供浅色主题。保持克制、有秩序，以可读层级和工作内容建立质感，不采用机器人墙、赛博装饰或无意义光效。具体规则和语义值由 [W1](../design/README.md) 与 [tokens.css](../design/tokens.css) 统一维护。

| 变量 | 已确认基线 |
| --- | --- |
| 主色 | 深色青色 `#00F0FF`，浅色主动作 `#0369A1`；主按钮使用配套前景色 |
| 页面／面板 | 深色 `#0D1117` / `#161B22`；浅色 `#F8FAFC` / `#FFFFFF` |
| 主要／次要文字 | 深色 `#E6EDF3` / `#9BA8B9`；浅色 `#182536` / `#52637A` |
| 状态 | 绿、琥珀、红配文字和图标；不只靠颜色区分 |
| 排版与密度 | 紧凑正文 13px、舒适 14px；次要标签 12px；任务标题 18–20px；页面标题 20–24px |
| 间距与圆角 | 4px 基础刻度，分组单位 8／12px；控件 6px、面板 8px、弹层 12px |
| 字体 | 系统中西文字体，代码等宽；不依赖未经许可的字体文件 |
| 主题 | 深色默认，浅色使用独立前景／背景配对；不简单反相 |
| 动效 | 建议 120–180ms 的轻量反馈，支持减少动态效果 |

具体尺寸可按可读性调整，不另建一套页面配色。人使用头像与姓名，AI 使用工具标识与配置标签。计划、摘要和说明标明 AI 建议或人工修改，不展示原始思考链，不把机器输出伪装成人工决定。

## 4. 信息架构

```text
HEXU
├── 工作台
│   ├── 我的工作
│   ├── 团队概览
│   └── 待我回复／处理
├── 项目
│   └── 项目详情
│       ├── 总览
│       ├── 需求与任务：列表／看板／按需依赖图
│       │   └── 任务工作区：协作、代码、预览、成果
│       ├── 资料与约定
│       ├── 成员与里程碑
│       └── 项目成果
├── 成果：跨项目查看、反馈与版本
└── 资源与设置
    ├── 执行工具与模型配置
    ├── 本地／远程节点
    ├── 成员、账号引用与访问范围
    └── 集成、费用与维护
```

全局提供搜索、工作空间切换、通知与个人菜单。知识以项目内使用为主，跨项目检索通过搜索进入，不要求用户另行维护大型知识后台。

任务工作区是从任务进入的深层工作区域，不是与任务平行的第二个系统。个人探索与团队任务明确标识归属；切换视图不提升权限。

## 5. 布局与响应式

桌面壳层采用全局顶栏、约 48px 导航轨、可收起的约 180–220px 上下文导引栏、任务主工作区及按需旁路抽屉。管理页面留白充分；开发页支持紧凑／舒适密度和可调整面板，保留布局偏好。桌面与 Web 共享组件，客户端职责见 [ADR-0008](../engineering/adr-0008-client-surfaces.md)。

任务页默认“过程／讨论＋代码／终端／预览”，输入与调度区位置稳定。目标、资料、协助和成果按需展开；宽屏才固定第三个面板，约 1024px 优先收起辅助导航，约 768px 以下切换或堆叠内容，以查看、讨论和回复为主。不将全部视区硬挤成窄列，也不把编程布局复制到每个管理页面。

主要动作在当前任务就地完成。继续与协助一键可发现，并行在工具栏或相邻菜单中清楚可见；高级账号、策略和节点配置放到次级面板。

## 6. 八类页面

### P01｜工作台与团队概览

**关联：HX-F03、F09、F10。**

个人首页显示继续工作、等待自己回复的事项和最近成果；管理视图显示项目目标、正在推进的工作、阻塞与里程碑。管理视图不是另一个信息录入入口。

```text
┌ HEXU · 合序 ─ 工作空间 ────────── 搜索 ─ 通知 ─ 个人 ┐
│ 工作台 │ 我的工作  /  团队概览                       │
│ 项目   │ 本次目标：订单管理改进                     │
│ 成果   ├───────────────────┬───────────────────────┤
│        │ 继续工作           │ 需要你回复            │
│        │ 订单导出 · 进行中   │ 导出字段范围 → 回复   │
│        │ 当前执行已结束     │ 接手邀请 → 查看       │
│        │ [继续任务]         │                       │
│        ├───────────────────┴───────────────────────┤
│ 资源   │ 最近成果：导出页面预览 [查看] [反馈]        │
└────────┴───────────────────────────────────────────┘
```

不使用假数据填满空页面。不默认显示成员产能排行、在线时长或精准完成率。可显示“3 项进行中、2 项待回复”，但说明这些是工作状态而非质量评分。

### P02｜需求与任务组织

**关联：HX-F01、F02、F03。**

新建入口主要是一行标题或自然语言输入，自动带入项目和自己。说明、附件、协作者、日期和子任务可展开补充。

复杂需求提供原始材料与整理后的说明，AI 建议可逐段编辑与采用。保存自动记录历史，不默认弹出“提交审批”。从选中内容生成任务建议，人可修改、删除或批量安排。

列表和看板共用任务数据。默认待处理、进行中、已完成；待反馈作为按需视图，受阻显示原因。依赖图只在有实际关系时展示；看板拖动同时提供键盘和菜单操作。

### P03｜任务研发工作区

**关联：HX-F04、F05、F06、F08。产品最重要的日常页面。**

顶部显示任务、负责人、当前执行工具、模型配置、节点和真实运行状态。任务、执行、代码三类事实分别显示，例如“任务进行中 / 本次执行已结束 / 本地未提交修改”；没有对应 Git 或发布事实时不填充状态。技术标识在详情中展开。下面的示意仅说明内容关系，视觉与响应式按 W1 实现。

```text
订单导出   ·  任务进行中   ·  负责人：演示成员甲
Claude Code / 当前模型配置  ·  我的电脑  ·  本次执行已结束
[继续 ▼]  [请人或 AI 协助]  [并行探索]               [成果]
┌──────────────┬──────────────────────┬────────────────────┐
│ 目标与上下文 │ 协作过程             │ 代码 / 预览 / 文件 │
│ 项目资料     │ 人的说明与回复       │ 变更摘要           │
│ 团队约定     │ AI 计划，可直接编辑  │ 运行中的功能页面   │
│ 当前工作记录 │ 当前动作与结果       │ 结果说明与反馈     │
│ 可收起       │ 必要日志可展开       │                    │
│              │ [补充要求或提问…]    │ [分享成果]         │
└──────────────┴──────────────────────┴────────────────────┘
```

**继续菜单：**继续当前工具、用另一工具继续、交给同事。模型在所选工具支持的配置中选择，不设置一个假装兼容所有工具的通用下拉框。

**协助入口：**可从选中消息、报错、文件、diff 和预览进入；选择同事或 AI、说明问题、预览分享内容。回应以内嵌线程或侧栏呈现，不打断主任务，不改变负责人。

**并行入口：**输入分支目标与工具，展示每条分支的工作区、执行和成果。对比视图支持选一条继续或选择性整合，不用结果数量代替质量。

AI 计划和摘要支持局部编辑、忽略与重新生成。运行中补充信息按实际能力显示已送达或待下一轮；不能提交后假装即时生效。

### P04｜继续、协助与接手面板

**关联：HX-F05、F06。替代原默认正式交接检查页。**

| 场景 | 默认交互 | 展开处理的条件 |
| --- | --- | --- |
| 同机换工具 | 简短说明沿用目录与任务上下文，选择后开始 | 写入未结束、权限或配置变化 |
| 临时协助 | 选择参与者、问题与分享范围 | 目标无访问权，或要求修改活动现场 |
| 跨成员接手 | 工作摘要、接收者、接手按钮 | 代码不可恢复、缺权限、缺环境 |
| 跨节点恢复 | 选择检查点和节点，自动预检 | 缺文件、工具不支持、原写入未知 |

常规路径不显示全屏绿色检查清单，不每次要求填写一份交接材料。详细上下文始终可以查看与编辑；实际问题显示原因和可采取动作。

接手操作与责任转移可在同一面板表达，默认只接手操作。无法确认旧写入结束时，不提供伪装安全的“强制接管”。

### P05｜团队协作与项目视图

**关联：HX-F03、F06、F08。**

显示任务、负责人、参与者、相关约定和等待原因，支持按成员与项目筛选。成员卡片展示所负责事项和“请协助”，不以在线状态作为工作表现。

从讨论选择“设为项目约定”，填简短标题和适用范围即可保存。相关变化在任务中提醒，区分“资料已更新”和“当前执行已收到”；不把每次编辑变成所有人的确认任务。

依赖视图提供选择任务、查看输入输出和跳到讨论的操作。潜在文件冲突是提醒，不用“无重叠”显示绝对安全。

### P06｜待我回复与必要操作

**关联：HX-F10、F11。**

按提及、协助、接手、成果反馈和执行授权分组。展示为何找我、相关任务和下一步，不建设与实际工作脱节的审批中心。

普通问题支持行内回复；重复原因合并；例行进展可静默或汇总。安全授权显示资源、动作、执行环境和有效范围；预批准的有限操作不反复打扰，超出范围再询问。

过期、已处理或上下文变化的授权不能继续批准，技术限制以具体原因说明。

### P07｜成果与反馈

**关联：HX-F09。替代原默认验收中心。**

```text
订单导出 · 最新成果 · 版本与来源
┌────────────────────────────────┬────────────────────┐
│ 功能预览 / 样例文件 / 代码差异  │ 本次做了什么       │
│                                │ 已知限制（可选）   │
│ 可直接查看的实际结果           │ 同事反馈与回复     │
│                                │                    │
├────────────────────────────────┴────────────────────┤
│ [提出修改] [继续处理] [标记完成]  更多：报告／发布链接 │
└─────────────────────────────────────────────────────┘
```

成果可以在任务进行中分享。自动生成的说明可修改；测试报告、CI、内部评价和发布记录折叠为可选附件，不以缺报告阻止完成。

标记完成记录操作者与时间；有活动执行时提示是否同时停止，并保留真实状态。之后可重新打开任务。旧成果保留版本，新成果不会自动撤销历史完成。

预览失效显示原因与文件、截图等替代入口，不展示虚假的可用页面。完成任务、完成执行、代码已上线使用不同标签。

### P08｜资源与设置

**关联：HX-F01、F05、F11、F12。**

执行工具、模型配置、集成与节点分区展示。工具卡片说明版本和可用能力；账号只显示身份摘要与受控引用，不展示密钥。

节点显示个人／团队归属、系统、健康、最后确认时间和授权范围。添加节点解释数据同步与撤销方式；私人节点不因管理员身份自动可用。

费用显示实际、报告、估算或未知；不以未知为零。模型和工具可以在任务中就地选择，只有维护配置时才进入此页。

## 7. 通用状态与文案

| 情况 | 建议表达 |
| --- | --- |
| 执行正常结束 | 本次执行已结束，可以查看结果或继续处理 |
| 任务完成 | 某成员于某时间标记完成；不写“系统验收通过” |
| 请求停止 | 正在停止；确认前保留真实执行信息 |
| 节点离线 | 连接未知，最后确认于具体时间 |
| 上下文变化 | 项目约定有更新；选择补充发送或下次使用 |
| 协助基于旧版本 | 此建议基于先前代码版本，查看对应内容 |
| 交接缺材料 | 尚缺可恢复代码，展示补充方式 |
| 能力不支持 | 当前配置不支持原生恢复，可基于已有材料新建会话 |
| 费用缺失 | 暂无可用费用信息，而不是 ¥0 |
| 无数据 | 提供开始工作入口，不填充假成果 |

错误信息保留用户草稿、已生成变更和恢复入口。不可逆删除、权限扩大、发布等说明后果；普通低风险编辑不制造重复确认。

## 8. 可用性、组件与国际化

中文优先，稳定使用“任务、继续、协助、并行、接手、成果、完成”等术语；工具内部 thread、session、turn 放在技术详情。日期按用户时区显示，详情可查看绝对时间。

建立任务行、状态标签、参与者、上下文引用、执行事件、成果卡片、回复线程、能力选择器、接手面板与授权提示等组件。普通、空、加载、错误和禁用状态一起设计。

键盘可完成任务切换、搜索、回复和主要动作；焦点可见，弹层返回原焦点，图标按钮有名称，长文本可缩放，状态不只靠颜色表达。默认展开动作与高级入口之间的关系清晰可发现。

## 9. 展示脚本与设计产出

统一演示“订单按月份导出”：首页看到目标 → 输入需求 → 在任务中用 Claude Code 推进 → 请同事或 Codex 协助 → 必要时换工具继续 → 查看预览并反馈 → 团队标记完成。

演示采用虚构资料并标注演示数据；不把预录日志或模拟结果说成实时执行。重点是目标、协作与成果，不必展示所有资源设置。

设计交付包括工作台、任务工作区、成果页、项目页、继续／协助／并行／接手面板、组件与响应式状态。W1 已保存任务工作台参考和 tokens，应用迁移及未实现业务仍按工作项推进。后续由内部团队评估，不在产品中新增设计评审或验证系统。
