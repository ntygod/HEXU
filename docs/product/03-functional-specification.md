## 1. 阅读规则

每个模块说明用户目标、行为边界与验收条件。`HX-Fxx` 为功能编号，`HX-ATxx` 为跨模块验收场景。业务事实、AI 建议与系统检测必须区分。

“支持某工具”至少意味着明确启动、输入、状态、权限、取消、产物、失败和恢复的能力范围；只有能打开一个终端，不算完整支持。

下列“必须”指功能启用时必须满足的条件。实施顺序在 07，不能以阶段较早为理由省略权限和状态真实性。

## HX-F01｜团队、项目与起步

**目标：**没有现成管理系统也能开始；新成员能知道项目目标和如何参与。

提供基础账号、邀请、工作空间、项目、成员与角色。工作空间是成员与权限容器；项目承载目标、仓库、规则、需求和交付。可先创建需求，稍后连接仓库；开发执行必须拥有可访问的代码基线。

项目可以连接多个仓库，保存运行与验证入口、环境要求、主分支约定及资料。通过经授权的仓库扫描生成配置建议，用户确认后启用；扫描不能自动执行仓库脚本或安装插件。

引导检查 AI 工具可用性、账号配置、仓库权限、节点系统、磁盘与必要环境。缺少条件逐项提示，不把部分接入标为全部完成。组织登录服务是可选集成，不是首次使用前提。

**验收：**无外部需求系统时完成项目与需求建立；未授权者不能进入项目；缺失工具有明确提示。关联 AT01、AT10、AT16。

## HX-F02｜需求中心与版本

**目标：**从自然语言进入工作，不让未经确认的假设变成承诺。

支持文字、图片和附件，保留原始输入。AI 提供结构化目标、范围、非目标、验收项和澄清问题，用户可逐项修改与确认。讨论不自动改变正式需求。

需求包含确认人、责任人、优先级、关联项目、验收项与版本。正式确认产生不可覆盖的版本快照。版本修改展示差异、原因和受影响任务；字段小修与范围变化可以有不同确认要求。

确认人可以撤回未执行提案或批准新版本，但不能删除此前确认历史。新版本使相关执行和验收需要重新评估，不能无声替换运行中的上下文。

**异常：**确认权限不足、确认人缺席、附件不可读、AI 整理失败时，保留原始材料并允许人工继续。

**验收：**AI 自增需求保持建议标识；需求变更能追溯版本并影响相关工作。关联 AT02、AT03。

## HX-F03｜任务规划、依赖与责任

**目标：**知道谁承诺做什么、依赖什么、怎样算完成。

任务可来自需求拆分、人工创建或个人探索转入。团队任务进入可执行状态前必须有目标、真人责任人和验收方式；可使用简短模板，非强制长文档。

分开记录责任人、当前操作者、AI 执行配置与验收者。支持子任务、优先级、里程碑、影响范围、输入输出约定和依赖。依赖须包含被等待的具体结果与版本，而非只有“等某人”。

提供列表、看板和依赖视图；不默认要求故事点或复杂敏捷流程。AI 建议的拆分、估算与调度需要接受后才成为计划。

阻塞是任务的附加标记，记录原因、解除条件、需要谁行动和下一次提醒。修改负责人不会自动中断或迁移现有运行。

**验收：**任意团队任务能找到真人责任；依赖循环得到提示；冲突提示不被当作安全证明。关联 AT03、AT08。

## HX-F04｜个人探索与研发工作台

**目标：**开发者一个人使用也有价值，不被强制填表或更换 IDE。

个人探索可以直接选择目录、工具和目标开始，形成私有任务及执行记录。转入团队时，预览并确认发布内容、项目关联和真人责任人，不公开全部旧记录。

任务页提供需求和规则摘要、AI 协作、当前执行、代码差异、文件查看、终端、功能预览和验证结果。面板按需展开，支持外部 IDE 打开同一工作区。

工作区记录仓库、分支、基线、节点、未提交变更和资源占用。手工编辑或外部工具产生的改动标记为外部变化，归属以可验证记录为准，不编造谁修改了代码。

保留会话草稿、常用工作配置、最近任务、全局搜索与快捷命令。未经支持的历史会话可作为附件关联，但不能宣称已经完整导入其执行状态。

**验收：**个人任务可在选择性共享后转团队；停止、失败、未知有不同显示。关联 AT04、AT17、AT20。

## HX-F05｜多工具、多模型与执行配置

**目标：**同一个任务可用不同工具持续推进，不把用户锁在一个模型。

优先接入 Claude Code 和 Codex；工具、模型、账号引用、权限配置、运行环境与任务分别建模。可用组合来自实际探测和适配测试，不硬编码永久排行榜。

四种工作模式：单工具持续执行；跨工具接力；固定版本独立复核；独立工作区并行探索。结果以任务关联，不混合成一段无法追溯的聊天。

同工具继续优先使用有效的原生会话引用；跨工具继续创建新的 Run，并附交接上下文和代码检查点。原生状态、未提交文件、系统依赖不能迁移时必须说明。

运行配置可复用并版本化，包含模型、工作方式、工具允许范围、最大迭代与预算。运行开始后保存有效配置快照；工具或模型改变至少生成新的配置边界，不能让历史记录跟着变化。

提供人工选择与可解释的路由建议；自动兜底只有在预先批准的工具、账号、数据发送范围和预算内生效，否则先确认。不能因额度不足静默换到个人付费账号。

**验收：**不支持的能力明确降级；同工具恢复与跨工具接力行为区分；停止未确认时不转交共享写入权。关联 AT05、AT06、AT14。

## HX-F06｜团队协作、交接与变更传播

**目标：**人、工具和环境改变后，工作仍可接续。

提供围绕需求、代码和验收项的评论、关注、提及和订阅。共享执行可先只读查看；控制权、授权权和可见权分离。

交接包包含目标、需求／决定版本、代码基线与检查点、已完成与未解决事项、尝试及结果、验证记录、环境要求、未包含文件和敏感内容检查。AI 可生成建议，交出方确认后发布。

交接有准备、待接手、已接受、拒绝、撤回和过期状态。接手者必须验证权限、可恢复性与工作区安全条件。转移当前操作者和转移真人责任人是独立动作。

同一受管工作区默认一个写入型执行者。并行写入用独立工作区；读者也要知道自己读取的是活动现场还是固定版本。外部进程无法完全受平台约束时标明范围。

决定变更时，计算显式关联任务与风险线索，发送给负责人。界面分开显示已通知、已确认和运行使用的新上下文版本。不能从文件不重叠推断没有语义冲突。

**验收：**两台电脑可完成检查点交接；无权限时不悄悄接手；旧写入未停止时不开始同现场新写入。关联 AT03、AT06、AT07、AT08。

## HX-F07｜AI 工作流与有界自动化

**目标：**把可靠分工自动化，而不是扩大不可控的并发。

工作流由有输入、输出、权限和完成判据的步骤组成，支持串行、并行、依赖和人工节点。步骤执行形成 Run，仍归属于可追踪任务。

可使用需求分析、实现、复核、测试等模板；团队能配置步骤和工具，不固定某模型永远承担某角色。模板更新不自动改变已开始实例。

Agent 间通过带来源、任务与版本的消息和产物协作。消息不是授权；权限取交集而非并集。一个 Agent 不能指挥另一个绕过自己被拒绝的操作。

提供迭代、并发、时间、预算与失败重试边界。具有外部副作用的步骤不因超时直接重试；先核对实际结果。分歧、循环或缺少验收依据时转人工。

**验收：**达到上限停止并解释；没有人类授权来源的危险动作不执行；重复事件不重复发布。关联 AT09、AT13、AT22。

## HX-F08｜项目知识、规则与决策

**目标：**共享仍然有效的知识，而不是把所有聊天堆进一个库。

分层管理项目规则、已确认决定、任务临时上下文、个人偏好和原始记录。每项重要知识包含来源、范围、版本、确认人和有效性；失效内容保留历史但不作为默认约束。

任务开始时生成上下文清单，记录包含、排除、摘要和截断内容；受权限限制的资料不能通过检索或摘要泄露。引用权限撤销后重新检查后续访问，不承诺已发送给模型的内容可以被收回。

AI 可提炼候选经验，发布为团队规则前需批准。冲突规则需要标示和裁决，不能依赖最近更新时间自动决定哪条更权威。

提供带出处的项目问答、相关任务检索和工作模板。模板与工具扩展启用前要检查权限及运行行为。

**验收：**旧决定不覆盖新决定；无权内容不进入搜索结果和模型上下文；摘要可以回到可访问来源。关联 AT03、AT17、AT19。

## HX-F09｜验证、验收、发布与反馈

**目标：**从“输出了代码”走向“结果被检查和接受”。

运行项目配置的构建、测试和静态检查，保存命令、退出状态、产物、环境、时间、代码与需求版本。没有 CI 时可由执行节点运行；没有执行的检查显示未执行。

代码审阅、业务验收和发布为不同记录。验收必须引用有效证据，指定验收者接受、退回或接受明确的剩余风险。Agent 可总结，不直接生成自己的正式验收。

Web 项目提供受保护预览；其他项目提供 API 样例、文件或运行报告。预览使用独立不可信内容域和权限策略，不向被预览应用泄露平台凭证。

新代码或需求改变相关验收前提时，将证据标记需复核。历史接受仍保留，但不能计入当前版本有效交付。PR 合并可以触发检查，不能自动代表业务验收或生产发布。

发布记录包含环境、版本、批准者、结果和回滚方案。人工发布可以手动登记并注明证据来源；不把人工登记伪装成自动检测。数据恢复与代码回滚独立。

**验收：**修改后旧证据失效；非开发者可对真实产物验收；未通过必要授权不能发布。关联 AT11、AT12、AT13。

## HX-F10｜注意力队列、管理与成本

**目标：**让人处理例外，并看见真实交付。

待处理队列聚合需求确认、授权、交接、依赖阻塞、审阅和预算例外。每项说明责任、原因、影响、时间和动作；过期请求不能继续批准。

管理视图展示目标、里程碑、有效验收、关键风险和实际成果。进度口径可查看，范围变更同步影响分母。无依据时显示缺少信息，不让 AI 编造比例和日期。

成本记录区分估算、工具报告和实际账单，标明币种、时间、计价依据与来源；不可获取显示未知而非零。恢复会话的累计用量需去重。成本分析不用于人员排名。

预算上限有软硬区别：平台能停止派发后续工作，但已发出的模型请求和未返回用量可能导致超额；只有提供方和适配器确实支持时才承诺硬限制。

**验收：**例外到正确处理者；重复提醒合并；费用不重复累计；管理数据可追溯。关联 AT14、AT15、AT20。

## HX-F11｜执行节点、权限、安全与运维

**目标：**不用先建设成熟内网，也不让远程协作变成任意执行入口。

支持个人节点和团队节点、本地和远程环境。提供注册、能力检查、撤销、升级、健康诊断和最后确认状态。节点主动建立受认证连接，禁止要求用户公开原生控制端口。

任务授权、节点使用权、操作系统权限和外部资源凭证分别控制。默认最小权限，不集中共享个人账号，不把所有 shell 命令自动批准作为便捷默认。

授权绑定动作、工作区、任务、运行、有效期和策略版本。撤销、到期、上下文改变或请求已被消耗后不能再次使用。拒绝要作用于真实执行，不只是界面状态。

执行状态与观测状态分离；失联后显示未知，恢复时核对进程和事件。终止要覆盖受管子进程；无法证明停止时禁止同现场接管。

提供日志过滤、数据保留、导出、归档、删除权限、备份恢复与审计。成员离开时撤销访问和未来任务派发，并明确已运行任务和本地残留数据的处理范围。

**验收：**授权拒绝可验证；断网不重复危险操作；跨项目隔离；备份恢复经过演练。关联 AT09、AT10、AT13、AT19、AT21。

## HX-F12｜外部集成、搜索与扩展

**目标：**复用现有系统，但不把连接外部系统作为开始使用的条件。

优先覆盖代码仓库与 PR／MR、可选 CI、通知渠道和已有需求系统。支持标准 Git 工作流；特定托管平台功能按连接器能力显示，不承诺所有 Git 服务功能对等。

外部对象以平台、实例、对象 ID 和版本标识；明确导入、只读关联或同步方向。Webhook 验签、去重与处理乱序；外部不可用时显示过期状态，不覆盖最新本地事实。

全局搜索按用户权限过滤需求、任务、决策和产物，结果带来源。通知仅发送必要摘要与授权链接，不默认附完整日志或代码。

扩展必须声明所需权限、数据访问和执行能力，使用版本化接口与测试；安装插件或 MCP 配置不等于授权任意执行。

**验收：**断开集成后原生任务仍可使用；重复 Webhook 不重复建任务或发布；敏感记录不出现在无权搜索和通知中。关联 AT15、AT17、AT18、AT19。

## 2. 跨模块不可违反的规则

1. 一项团队任务有一个明确的真人责任人；任务可以有多个操作者和 Run。
2. 任务可见性不会自动授予节点执行权，也不会自动公开个人探索历史。
3. 运行配置、代码检查点与验收证据都需版本化；历史不能随当前设置一起改变。
4. AI 建议、人工批准、检测结果和未知状态必须可区分。
5. 修改任务负责人、重新运行和恢复原生会话是不同动作。
6. 平台默认不执行未经授权的破坏性操作，也不把自动重试当作外部副作用幂等性的保证。
7. 不以 Agent 结束、测试未报错或 PR 合并代替正式验收。
8. 所有发布到团队的摘要都遵守原资料访问权限，不能用 AI 绕过信息权限。

## 3. 完成定义

每项功能上线须有正常流程、异常流程、权限检查、状态映射、可观测记录与用户界面。演示性假数据必须标注；尚未接通的按钮不可显示真实成功。

验收使用 07 的场景矩阵，设计使用 04 的页面与状态要求，状态含义以 05 为唯一口径。
