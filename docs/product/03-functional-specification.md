# 03｜功能需求规格

## 1. 产品默认值

**轻管理、深协作、成果直观。**

创建任务只需一个标题或目标，归属与负责人从当前用户、项目和目录自动带入。需求说明、子任务、截止日期、里程碑和检查报告均可随后补充。不要求先完成正式需求审批、指定验收人或设置质量证据才能开始。

默认任务流程为“待处理 → 进行中 → 已完成”，待反馈、受阻和暂缓按需显示。任务完成由团队成员或明确启用的自动规则决定，不由 AI 自报成功决定，也不绑定平台强制验收。

以下十二个编号延续原规划，便于追踪，但不对应十二组菜单。产品效果、代码质量和内部检查方法由团队决定，见独立的[内部评估说明](../engineering/internal-evaluation.md)；该说明不是用户工作流程。

## HX-F01｜团队、项目与起步

**目标：**没有成熟内网、需求系统或统一身份服务，也能开始协作。

提供账号、邀请、工作空间、项目、成员和基本访问范围。用户先选择“开始个人工作”或“进入团队项目”，不要求先创建组织架构或一组虚拟员工。

项目保存目标、成员、关联仓库、资料、约定和里程碑；一个项目可以关联多个仓库。尚未连接仓库时允许讨论、整理需求和规划，实际代码执行时再引导连接目录或仓库。

成员电脑通过执行器接入；向导说明将同步哪些信息、谁能使用节点、如何撤销。平台可读取经授权的项目信息并提出启动配置，但不得仅因扫描仓库就执行其中脚本或安装插件。

个人任务负责人默认自己；项目任务默认创建者，允许先保留待分配事项。启动实际团队执行时不出现纯 AI 的责任主体，必要信息自动带入而不是新增一张责任表。

## HX-F02｜需求与工作说明

**目标：**把零散想法整理清楚，不把写需求变成使用门槛。

支持文字、图片、附件及粘贴讨论。保留原始材料，AI 给出可编辑的说明、建议范围、拆分与关键问题。用户可以局部修改或采用，不必只能全盘批准或重新生成。

简单问题直接成为任务；复杂工作可以建立独立需求说明，关联多个任务。需求与任务不是必须先后填写的两张表。

人工保存自动保留修订。AI 建议有明确来源，默认不静默改写共享说明。重要变更在相关任务中显示差异和影响提示；普通编辑不弹出多级确认，不自动阻止所有运行。

“预期结果”“不做什么”和示例是可选的辅助结构，不要求统一格式。团队需要正式审批时可关联其已有流程，但不建设默认的需求审批中心。

## HX-F03｜任务、分工与工作流

**目标：**随时知道在做什么、谁在推进、哪里需要帮助。

任务支持真人负责人、参与者、当前操作者、子任务、标签、优先级、可选目标日期与里程碑。负责人和当前操作者可不同，但普通界面只突出必要信息。

提供列表和看板，按项目、成员、状态和等待原因筛选；依赖视图按需展开。依赖可以从“等待接口定义”这样的简短关系开始，需要时再附约定或代码引用。

默认不要求故事点、工时填报、固定迭代或复杂流程设计。可选提示正在进行的任务数量、长时间未推进的工作和等待原因，不据此评价个人产能。

AI 拆分先作为建议列表；人可直接编辑、批量安排或只采用部分。改派任务不会停止原执行，也不会迁移个人电脑上的文件。

已完成任务可直接重新打开或建立后续任务。完成无需报告；若仍有运行，提供“同时请求停止”或“仅标记任务完成”，并准确展示剩余运行状态。

## HX-F04｜个人探索与任务工作区

**目标：**一个人用也方便，协作时不用重新整理一套工作记录。

可从本地目录、项目任务、搜索结果或一个问题启动。个人探索默认不在团队进度中出现；转团队时预览并选择共享内容，不自动公开全部原生会话。

任务详情直接进入实际工作区，不另建孤立的“AI 工作区”任务系统。工作区集中呈现目标、上下文、人与 AI 的协作过程、代码差异、文件、终端和预览，面板可收起。

用户可打开外部 IDE，继续使用熟悉的工具。平台仅记录有依据的外部变化，不承诺追踪所有历史会话或编造修改者。

提供最近任务、草稿保留、全局搜索、快捷命令和常用执行配置。长日志默认折叠为重要步骤、当前动作与问题；允许查看原文，不用逐 token 动画替代进展。

对正在运行的任务可以补充要求。适配器支持即时输入时送达，不能即时改变的说明进入下一轮；界面标明“已发送”“待下次使用”或“不支持”，不假装已经执行。

## HX-F05｜多工具、多模型：继续、协助、并行

**目标：**保留原生工具优势，减少跨工具重新开始的成本。

优先接入 Claude Code 和 Codex。选择器依次表达执行工具、可用模型、账号引用和运行位置；不把模型、Git 托管和 Docker 作为同一类资源。组合来自实际接入能力，不写死永久模型排行榜。

### 继续

保留在原任务中，选择“用另一工具继续”。同机、原写入已结束、权限与现场满足条件时，自动整理必要上下文和当前变更，使用原目录开始新执行，不强制生成正式交接文档或推送提交。

跨工具创建新 Run；同工具优先继续有效原生会话。不能恢复时明确使用新会话。模型切换遵循原生支持范围，记录配置变化，不承诺模型内部状态无损迁移。

原执行未结束、目标节点不同、材料缺失或数据发送范围变化时才打开针对性处理界面。不得在同一现场直接启动第二个写入型 Agent。

### 协助

从一段消息、报错、文件、diff 或预览发起“请人或 AI 协助”，默认只分享必要材料。可以选择同事，也可以选择另一个工具与模型；任务负责人和主执行者不变。

支持独立建议、错误分析、方案讨论与可选代码审阅。AI 协助默认只读或使用隔离副本，不因邀请获得活动现场写入权。需要实际改代码时显式进入并行分支或接手。

回应回到同一任务，用户可以采纳、局部修改、继续追问或忽略，不自动成为团队决定。

### 并行

在同一任务下建立边界清楚的方案分支或子工作。每条分支显示共同起点、目标、工具、状态和成果；修改代码的分支有独立工作区。

并排比较说明、代码和预览，用户可选一个继续，或选择性整合。选中方案不自动合并全部代码或停止其他执行；操作与后果分别说明。

### 共通规则

常用配置保存工具、模型、上下文偏好和有限权限，不保存裸密钥。自动兜底仅限预先允许的账号、数据范围和预算。额度不足不能静默代用其他成员的账户。

临时协助和并行增加的费用应在可获得范围内提示；不可获取时显示未知，不伪造精确报价。

## HX-F06｜成员协作、接手与变化提醒

**目标：**共享必要的工作信息，不要求共享所有私人过程。

任务支持评论、提及、关注、共享输出与参与者视图。重要结论可以直接“设为项目约定”，选择范围后保存，不再跳转到审批系统。

跨成员接手时，系统准备工作说明、代码检查点、已完成与剩余事项、必要环境和未包含文件。交出方可编辑，接收方点击接手时自动检查；只对缺失或冲突项要求处理，不反复展示全绿检查表。

负责人转移是可选动作，可在接手界面一起选择，默认只改变当前操作者。接手不转交原操作者的模型账号、仓库凭证或生产权限。

同一受管工作区默认一个写入者；只读查看不代表控制权。旧电脑离线且无法确认原写入结束时，可以基于已有检查点另建副本，不能假装接管原进程。

约定变化提醒相关人员，显示是否已发送至当前执行或留待下一次使用。文件重叠仅是协作线索，不等于完整语义冲突判断。

## HX-F07｜可复用协作方式与有界自动化

**目标：**把常见工作方式变成可重复使用的配置，而不是要求建立虚拟公司。

允许将“整理材料—实现—汇总结果”等组合保存为模板，支持串行、并行、依赖与需要人回复的节点。模板是高级能力，不是首次开始工作的前置条件。

步骤具有明确输入、输出、工具、权限及停止条件。既可使用 AI，也可安排真人参与；不固定哪个模型永远负责规划或编码。模板变更不静默改变正在运行的实例。

保留并发、时间、预算和迭代边界。出现持续失败、循环或分歧时停止并交人处理；外部副作用超时后先核对结果，不盲目重试。

Agent 之间传递的是任务相关材料和产物，不是自动升级的权限。用户能编辑步骤、跳过非必需步骤、请求停止和继续；不可逆动作仍受其实际授权约束。

## HX-F08｜项目资料、团队约定与当前上下文

**目标：**让上下文自然跟随工作，不让用户维护一个庞大的记忆后台。

用户主要看到三类内容：项目资料、团队约定、当前工作记录。集中知识入口可按需提供，但日常使用发生在项目与任务中。

启动、继续、协助和并行时，系统根据目标准备必要材料。可展开的“当前上下文”显示来源、摘要及未包含内容，允许补充或排除；用户不必每次手工重选全部资料。

共享约定保留来源和修订。新的运行使用当前版本，运行中的变化按工具能力补充或提示下次使用。AI 提炼经验先作为建议，人可以直接编辑并保存为约定或模板。

检索、摘要、分享和发送给模型均遵守原有访问范围；不得通过摘要泄露不可访问的原资料。不同工作分支按需要获取上下文，不默认将全部聊天广播给所有 Agent。

## HX-F09｜成果、反馈与完成

**目标：**同事和老板不必阅读终端，就能看到做了什么并给出反馈。

成果包括功能预览、代码变更、文件、接口样例和可编辑说明，可在任务进行中发布多次。成果保留来源、版本、讨论和关联任务；不是只有“任务关闭后才能生成”的档案。

主要动作是“查看成果”“提出修改”“继续处理”“标记完成”。反馈可关联页面、文件或具体变更，并选择追加到原任务或建立后续任务。

项目检查命令、CI、人工评估或测试报告都是可选内容：团队可运行、关联或上传，平台如实显示来源和适用版本。没有报告不阻止任务完成，不建设默认的证据覆盖率、独立验收中心或强制审批链。

由有编辑权的成员标记完成，记录操作者、时间与可选说明。自动完成仅按明确启用的项目规则执行并标注来源。Run 结束只显示本次执行结束。

结果更新保留历史；旧检查记录不能冒充新版本结论，但不自动把已完成任务退回或强制重验。是否继续由团队决定。

发布记录、预览链接和部署入口按需关联。真正发布时检查执行权限；完成任务、PR 合并与上线分别呈现，不相互冒充。预览与主站身份隔离，不能把平台凭证暴露给预览代码。

## HX-F10｜工作台、提醒与成本

**目标：**打开就知道接下来做什么，管理者无需另找人拼凑进度。

个人视图突出当前工作、等待自己回复的事项、最近项目与成果。团队概览突出目标、正在推进的工作、阻塞原因、里程碑与可查看成果；不是 Agent 监控墙。

待处理合并提及、协助、接手、反馈和必要的执行授权。每项说明为何找我、影响哪项工作、可以做什么；相同原因去重，支持稍后处理和关注设置。

状态来自任务、运行、讨论和已有集成，不要求额外填汇报表。计数注明含义：任务完成数不是质量通过数，执行数不是产能。没有依据不生成精确完成百分比或预测日期。

成本按项目、任务、工具和来源汇总，区分实际账单、工具报告、估计值与未知。恢复会话累计数据去重；预算提示不承诺已发请求零超额。不使用 token、在线时长或 Agent 数量给成员排名。

## HX-F11｜执行节点、权限与维护

**目标：**连接本地和远程环境，同时保留清楚的控制边界。

支持个人与团队节点、注册、能力发现、撤销、升级、健康信息和最后连接时间。执行器主动连接服务，不要求将原生终端或 Agent 控制端口裸露到公网。

任务访问、节点使用、操作系统权限和外部凭证分别控制。可设置有限范围的常用授权，减少低风险操作重复询问；超范围时在任务内处理，不增加通用审批中心。

拒绝、过期或撤销授权必须作用到真实执行。停止状态等待真实确认；断网显示未知，恢复时核对进程和事件，不重复启动同一操作。

提供必要的日志过滤、归档、数据导出、备份恢复及诊断。平台不可用时，用户仍能找到本地代码并使用原生工具；恢复后显示可识别的外部变化。

这些是软件基础能力，不是新增业务验收步骤。内部测试和上线评估由团队安排。

## HX-F12｜集成、搜索与扩展

**目标：**接住已有工具，不要求先采购或配置另一套系统。

支持 Git 与 PR／MR 关联，可选接入 CI、通知、需求系统和发布记录。每类对象明确只读关联、导入或同步方向，避免同一任务在多处无约束修改。

代码事实以 Git 为准；平台工作状态以 Task 为准；外部检查和发布记录保留其来源。Webhook 验签、去重并处理乱序，外部失联时显示最后同步状态。

全局搜索覆盖有权限的任务、资料、约定、讨论与成果。外部通知只发送必要摘要与受权限保护的入口。

扩展声明权限、数据范围和能力；不因添加插件或 MCP 就授予任意执行。断开外部集成后，原生项目与任务仍可使用。

## 2. 产品不建设什么

不建设独立产品实验平台、员工效能排名、强制质量证据中心、默认多级需求审批、默认正式交接审批或必须配置的虚拟组织架构。

不取消代码预览、可选检查、人工反馈、历史版本和基本权限；只是让这些能力服务于工作，不成为每项工作必经的制度。

## 3. 文档与实现关系

状态以 05 为准，界面以 04 为准，能力建设顺序以 07 为准。功能实现应包含真实错误与恢复反馈；未实现或模拟能力清楚标识。旧版 HX-AT 矩阵不再作为产品流程的来源，评估安排由内部团队管理。
