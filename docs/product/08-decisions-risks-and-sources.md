## 3. 尚未确认的信息与处理方式

| 未知项 | 当前规划如何处理 | 在什么动作前必须确认 |
| --- | --- | --- |

| Windows／macOS／Linux 比例 | 完整目标支持按能力接入，不声明已实现全平台 | 执行器打包与首批支持矩阵确定前 |
| 既有 Git 服务与仓库结构 | 多仓库概念、标准 Git 路径优先 | 仓库集成实现与权限试验前 |
| 模型账号与付费主体 | 账号引用独立，不默认共享订阅 | 真实模型接入与试点前 |
| 可用服务器、域名与网络 | 允许云或自管部署，HTTPS 与身份验证为底线 | 公网可访问部署前 |
| 敏感代码与数据发送范围 | 最小同步、显式授权、日志过滤 | 上传代码／日志或调用外部模型前 |
| 中文和其他语言需求 | 中文优先、结构预留国际化 | 设计定稿前 |
| 公司技术栈和维护人力 | 技术选型仅为建议，避免冻结版本 | 建立应用骨架与排期前 |
| 日志和审计保留期限 | 分类管理，不默认无限保存 | 团队正式启用前 |
| 商标、域名与开源策略 | 保留为待决定项，不做可用性承诺 | 正式对外发布或授权分发前 |

这些未知项不阻止完整产品规划，但会影响排期、支持范围和部署准入。后续不能用未经核实的默认值替代组织授权。

## 4. 风险清单

| 风险 | 后果 | 预防或验证方式 |
| --- | --- | --- |
| 只做统一工具入口，缺乏真实协作收益 | 用户仍需在聊天里交接和汇报 | 用跨工具、跨人、验收的真实任务验证，不看 Agent 数量 |
| 为规范化增加过多表单 | 开发者绕过平台，管理数据失真 | 个人轻量起步、按风险增加约束，测量新增操作负担 |
| 把管理可见性做成监控 | 降低信任与采用，暴露个人信息 | 共享承诺和成果，私人探索选择性发布，不做人员排名 |
| 跨工具只迁移摘要 | 新执行者丢代码或继承错误前提 | 代码检查点、来源与缺失项校验，接手确认 |
| 需求变化后旧验收仍有效 | 错误交付被标为完成 | 需求、代码、证据与接受记录全部关联版本 |
| 节点失联后立即重新执行 | 同现场并发写入或重复副作用 | 观测状态与生命周期分离，先核对旧进程与外部结果 |
| 以 worktree 代替安全隔离 | Agent 访问宿主文件、凭证或外部系统 | 操作系统、网络、凭证和执行策略共同控制 |
| 以审批 UI 代替执行权限控制 | 用户拒绝后命令仍执行 | 真实授权回路测试，检查自动批准路径与原生限制 |
| 工具接口与版本快速变化 | 接入中断、状态解析错误 | 锁定兼容矩阵，探测能力，原生契约测试与回滚 |
| 原生账号授权方式不适用于平台 | 无法合规稳定运行或费用归属不清 | 逐路径核查条款与提供方文档，不共享个人订阅池 |
| AI 自动化循环与成本失控 | 重复修改、延误与账单增加 | 最大迭代、并发、预算、超时和人工节点 |
| 界面很好看但状态虚假 | 管理决策错误，长期信任下降 | 原型与真实能力区别，异常状态和证据同时验收 |
| 直接复制源码可用项目而未核许可 | 品牌、分发或托管方式受到限制 | 复用前检查锁定提交及组件许可证，保留归属信息 |
| 自研范围不断扩张 | 运维和适配成本超过收益 | 坚守核心领域，复用基础能力，按真实瓶颈扩展 |

严重风险由 07 的阻断条件决定是否可上线，不能通过“内部工具”豁免。

## 5. 外部资料的使用边界

本次重新读取的官方技术资料如下，核查日期为 2026-09-25。它们支持接口与限制判断，不证明 HEXU 已完成集成，也不保证未来版本不变。

这里不复制整份官方文档，不把第三方宣传中的效率与安全承诺写成 HEXU 事实。实现时还需对实际安装版本执行兼容测试。

### S01｜Claude Code 程序化调用

来源：[Run Claude Code programmatically](https://code.claude.com/docs/en/headless)。

核实要点：官方提供程序化 CLI、结构化／流式输出与会话继续入口；费用输出存在估算和会话累计语义。

规划影响：避免依赖终端展示文本抓取；执行、恢复和费用统计要保留原生语义并验证。本文不锁定具体 CLI 选项组合与最低版本。

### S02｜Claude Agent SDK 概览与认证说明

来源：[Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)。

核实要点：SDK 提供与 Claude Code 相关的执行与上下文能力；文档对未经批准的第三方产品提供 claude.ai 登录或额度接入存在明确限制，并指向 API key 认证方式。

规划影响：工具技术接入和账号授权分开验证。不能因为本机已经登录就承诺可将个人订阅封装为团队共享服务。具体适用范围仍需按实际集成方式核对。

### S03｜Claude Agent SDK 权限

来源：[Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions)。

核实要点：权限由模式、规则、Hooks 和交互回调共同决定；部分自动允许的操作不会经过用户回调。

规划影响：必须验证真实执行边界，不能认为创建一个网页审批组件就控制了所有工具调用。不要把 bypass 类设置作为默认便利选项。

### S04｜Codex App Server

官方入口：[Codex App Server](https://developers.openai.com/codex/app-server)。本次读取时跳转到 [ChatGPT Learn 的 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

核实要点：提供线程、执行事件、输入和授权交互；部分方法与字段需要显式开启实验能力。

规划影响：通过适配器保留原生线程／执行映射，授权响应必须回到正确请求。默认优先已验证能力，实验接口独立标记；不将原生服务直接公开。

### S05｜Git worktree

来源：[git-worktree Documentation](https://git-scm.com/docs/git-worktree)。

核实要点：一个 Git 仓库可以管理多个工作树，并检出不同分支。

规划影响：可复用工作区能力，不必重写版本控制。安全隔离、数据库、端口、凭证和网络资源仍需另行设计，不能从多工作树推导完整沙箱。

## 6. 既有项目的参考地位

此前讨论的 Conductor、Multica、Paperclip、Emdash、Vibe Kanban、OpenHands 和 Superset 均属于产品与技术研究对象，不是本次依赖清单。

本规划不沿用此前对某个主干的优先推荐作为实施决定，也不声称任何候选已通过公司环境部署与安全测试。最终选择复用时新增决策记录，列明收益、限制和退出方案。
