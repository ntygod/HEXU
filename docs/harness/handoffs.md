# 正式接手邀请 harness

> 按需读取：修改 Handoff 发布/关闭/到期/历史、任务内接手卡，或后续接受接手。先读 [12 工作包](../development/12-handoff-sharing.md)；当前用法见 [接手邀请](../engineering/handoff-invitations.md)。

## 当前实现与边界

- [邀请契约](../../packages/contracts/src/handoffs.ts)、[状态规则](../../packages/domain/src/handoffs.ts)、[邀请事务](../../packages/db/src/handoffs.ts)、[路由](../../apps/control/src/handoffs.ts)、[抽屉](../../apps/web/src/handoffs.tsx) 支持 offered / accepted / rejected / withdrawn / expired。准备编辑留在抽屉内存，明确发布一次保存；接受另走下述持久操作。
- 仅真实账号、项目可见任务、原发送者向不同的原接收者发出邀请。绑定已确认接收的 transfer ID/hash、接收节点/用户、commit、快照指纹、材料期限与覆盖范围；不能从任务阅读权、配对、旧恢复报告或任意浏览器路径推导材料授权。
- 发布前及事务内核对当前任务/双方节点权限、固定材料和 Task revision；旧回执前仍核对当前权限。接收人仅可拒绝，发布人仅可撤回；归档不禁止这类人类协作。当前父任务权限控制列表、直接 ID、历史和 SSE，邀请不是 AccessGrant。
- 发布、拒绝、撤回、到期只改邀请的独立修订及其待接受操作，不改 Task、负责人、操作者、Run、输入材料、工作区锁或本机文件。状态、不可变事件、outbox 与原请求回执一并提交；旧回执返回最新状态，不能再次产生副作用。到期单独持久化系统事件，重启不复活。
- 摘要、剩余工作、环境说明与发布时任务标题/版本固定；后续变化只作比较提示。期限是邀请可处理期限，不是对象删除或进程终止证明。

## 接受接手与本机新核验

`received` 仅说明对象接收最后回执，`restored` 是一次历史发布结果。[接受契约](../../packages/contracts/src/handoff-acceptance.ts)、[接受事务](../../packages/db/src/handoff-acceptance.ts)、[本机核验](../../apps/runner/src/agent/handoff-acceptance.ts) 和 [接受面板](../../apps/web/src/handoff-acceptance.tsx) 要求新的现场核验再提交 accepted / 操作者变化；使用见 [接受指南](../engineering/handoff-acceptance.md)。

- 只有指定接收者发起，固定邀请/Task 修订、当前人类讨论哈希、材料、本人节点和职责选择；操作最长十分钟，并在所有 Run/接续创建事务中检查任务预约。不得并发放行新代码执行。
- 本机仅核验原接收副本已经成功发布的目录，不下载/恢复/覆盖或接受网页路径。重验原对象、恢复日志身份/计数、完整文件清单/字节/模式、父目录和当前双方授权，拒绝变化、链接、日志占用和未知写入；原模型锁永不由接手清除。
- 本机只读核验有独立日志与命名空间预约，固定包先持久化再发送。未知回执保留原包和预约，旧成功只对账原指纹；重新拿到独占日志锁后只能处理自身核验预约，不向旧 PID 发信号。未处置证据阻止删除凭证/重新配对。
- accepted、Task 操作者/修订、可选负责人历史、操作 succeeded、outbox 与回执在同一事务提交。负责人需邀请方提出、接收方另行勾选；旧任务操作者保持未知。邀请关闭原子取消等待确认，取消不能回滚成功接手。
- 任务/讨论、权限、材料、期限或写入变化在读取/周期检查/最终提交时暂停原操作，服务重启也暂停；恢复权限不复活。文件验证失败只回传有界类别，不上传路径、名称、代码、凭证或错误正文。
- 成功表示本次接手提交，不表示持续文件可用、完整 Git 仓库、目录执行授权、已启动模型或跨电脑部署。只读核验与控制事务不是分布式原子事务，也不是 OS 沙箱。

后续切片范围只在 [22](../development/22-next-delivery.md) 维护。仍共用一个 Task，不新建平行 AI 会话系统，不加质量报告门槛，也不复制发送者凭证。负责人可选转移和操作者切换是不同语义。

## UI 与验证

固定表单基线；临时读错保留，明确撤权或身份/空间变化清除。未知写确认克隆的原 body/key，不能用刷新后的修订重写原请求。已发布卡片按当前权限读取，深浅色和窄屏使用 W1 tokens。
