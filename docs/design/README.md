## 1. 本次确定什么

HEXU 同时服务于**个人多工具、多模型编程**和**团队 AI 编程协作**。以任务为统一入口，让目标、讨论、代码现场、接续与成果连续存在。

采用已确认的**暗色优先、青色强调、任务一体化研发工作台**。吸收 Figma 方案中的求助材料组织、交接信息和项目管理结构，不整体替换为其灰紫色主视觉，不把任务和 AI 会话拆成两个工作系统。

本文件规定设计语言，[tokens.css](tokens.css) 是稳定的设计引用入口，转向 [UI 包中的唯一运行源](../../packages/ui/src/tokens.css)；[可交互参考](workbench-reference.html) 用于观察布局和操作意图。参考的[可编辑源](workbench-reference.fragment.html) 保留演示内容；其按钮、模型、金额、终端、原型状态和尺寸不是生产能力或接口定义。发生差异时，以产品行为、本文件和实际能力契约为准。

W1-01—09 的呈现层已接入真实应用。`App.tsx` 只保留路由与全局命令入口；任务、讨论、输入、执行、账号、团队、工作台、项目、成果、资源和搜索分别拥有明确的组件与样式文件。旧 `styles.css` 已删除，`foundation.css` 仅承担基础排版与通用布局，旧配色变量别名已移除。业务能力与实际回归结果见实现进度。

参考 HTML 可在浏览器单独打开，不需要启动 HEXU。它由片段导出，预览外壳只用于文档展示；图标／提示使用固定版本的 Lucide 1.17.0、Floating UI core 1.7.3 / dom 1.7.4 CDN 资源，不加入应用依赖。离线时图标可能不可用。修改参考时保留片段并重新导出 HTML，不把预览外壳或模拟状态代码复制到生产应用。演示只保存本地交互偏好，不连接业务 API、节点或模型。

## 2. 风格与使用重心

- 默认深色，提供完整浅色主题；青色只用于主操作、当前选中和焦点。
- 紫色识别 AI 工具与建议，不代替成功、权限或任务状态。
- 通过字号、留白、分隔线和信息分组建立层级，少用大面积彩色卡片、光效和重复指标。
- 编程界面紧凑，项目、成果、团队页面保留阅读空间；不把每页都做成多窗格 IDE。
- 个人可从问题或授权目录开始，不要求企业邮箱、团队注册或团队服务器。团队入口加入邀请、共享和项目权限。
- 人是真人负责人或协作者；AI 是工具与执行参与者，不计入真人成员数，不建立虚拟员工等级。

## 3. 色彩、文字与密度

颜色数值以 [运行 tokens](../../packages/ui/src/tokens.css) 为单一来源，设计目录的引用入口不再复制一份数值。以下是关键配对；迁移时不得只替换背景而沿用不适配的文字颜色。

| 语义 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| 应用底色 | `#0D1117` | `#F8FAFC` | 工作现场背景 |
| 面板 | `#161B22` | `#FFFFFF` | 导航、抽屉、编辑区域 |
| 次级表面 | `#1C222C` | `#F0F4F8` | 输入与局部分组 |
| 分隔线 | `#30363D` | `#DCE3EB` | 面板和控件边界 |
| 主要文字 | `#E6EDF3` | `#182536` | 正文和主要信息 |
| 次要文字 | `#9BA8B9` | `#52637A` | 来源、说明和辅助信息 |
| 主动作／其文字 | `#00F0FF` / `#062126` | `#0369A1` / `#FFFFFF` | 青色按钮必须使用配套前景色 |
| AI 标签文字 | `#BC8CFF` | `#9333EA` | 工具、AI 建议 |
| 成功／等待／危险文字 | `#3DD6A0` / `#F4BD62` / `#FF8590` | `#0C805B` / `#925D00` / `#C63242` | 同时附文字或图标 |

状态图形使用绿 `#10B981`、琥珀 `#F59E0B`、红 `#EF4444`；小字号文字使用上表的可读色，不直接套用品牌或状态图形色。AI 紫色基色为 `#A855F7`。代码增加、删除有浅色背景及 `+ / −`，不能只靠红绿区分。浅主题主动作由初始参考的 `#0284C7` 收深为 `#0369A1`，与白字对比度约 5.93:1；深主题青色与配套深字约 11.90:1。

UI 使用系统中西文字体，Inter 仅在可用时采用；代码使用系统等宽字体，可回退至 Consolas。JetBrains Mono、Fira Code 属于可选字体，不自动新增下载依赖。

| 项目 | W1 默认 |
| --- | --- |
| 正文／控件 | 紧凑 13px，舒适 14px；说明正文行高约 1.6 |
| 次要标签／代码 | 12px；仅时间、行号等非必要元数据可降至 11px |
| 页面标题 | 20–24px；任务紧凑标题 18–20px |
| 字重 | 正文 400，标题和强调 500–600 |
| 间距 | 4px 基础刻度；紧凑分组单位 8px，舒适分组单位 12px |
| 控件／面板／弹层圆角 | 6px / 8px / 12px |
| 操作尺寸 | 桌面常规控件至少 32px；触控有效区域约 44px |
| 动效 | 120–180ms；尊重减少动态效果设置，不用持续动画代替进展 |

密度切换调整间距、行高和操作尺寸，不隐藏重要状态。常用文字以可读性优先，不靠缩小字体解决拥挤。

当前外观偏好沿用 `hexu-theme` 并增加 `hexu-density`，只保存设备外观信息，覆盖登录前后界面。已有有效浅／深色选择保留；新访客或无效值默认深色、紧凑。导航导引栏的桌面收起状态按模式、用户和空间隔离保存；窄屏展开是临时状态，不覆盖桌面偏好。

## 4. 信息架构与面板

逻辑入口保持工作台、项目、成果、资源与设置。任务可从项目、最近工作或搜索直接进入。执行历史属于任务；可以检索会话，但不另建平行的 AI 任务库。

任务工作区由以下区域构成：

| 区域 | 内容与规则 |
| --- | --- |
| 全局顶栏 | 个人／团队空间、全局搜索与命令、连接摘要和个人入口 |
| 全局导航轨 | 主要区域；图标有可访问名称和提示，保持低视觉权重 |
| 上下文导引栏 | 当前项目、任务、资料、约定与成果，可收起 |
| 任务头 | 目标、负责人、分享范围；任务、执行、代码分别显示状态 |
| 主工作区 | 过程／讨论与代码／终端／预览联动；面板可切换、折叠、调整宽度 |
| 输入与调度区 | 本次要求、工具、模型、环境、材料与送达方式，位置稳定 |
| 旁路抽屉 | 协助、上下文、成果、执行历史；打开后保留任务与草稿 |
| 次级状态栏 | 分支、用量来源、运行环境等，低频技术细节可收起 |

导航轨默认约 48px，导引栏约 180–220px，抽屉约 320–380px。它们是实现起点，不是要求所有屏幕同时容纳五栏。侧栏收起后，核心操作仍可从顶栏或任务内访问。

- 宽屏优先过程与结果双栏；足够宽时才固定旁路抽屉。
- 约 1024px 时优先收起低频导航或以抽屉显示辅助信息，不挤压代码和输入。
- 约 768px 以下以查看、讨论和回复为主；代码、终端、预览切换或堆叠，不固定并排三栏。
- 拖动调整面板需有键盘等价操作；保存布局偏好时按用户与空间隔离。
- 弹层和抽屉使用不透明表面。卡片不能互相遮挡，文字不能逃出容器；缩放与长中文内容也必须可读。

## 5. 主要操作的确定语义

| 操作 | 必须保留的行为 |
| --- | --- |
| 输入要求 | 区分任务讨论、即时输入、下一轮要求；不能即时送达时明确排队，不假装 Agent 已收到 |
| 换工具／模型 | 同一 Task 保留来源、目录和明确选材；按工具能力选择新会话或原生恢复 |
| 等待／停止后继续 | 显示等待、停止中、需要处理、已创建新执行；Run 创建、实际启动和模型结束分开 |
| 原生恢复 | 展示实际恢复能力与历史继承范围；取消或失败不能静默开始另一场执行 |
| 求助 | 选择问题、固定材料与版本、AI 或同事；默认不换负责人、不扩大主目录写入权 |
| 采用建议 | 可编辑、局部采用或加入下一轮；不能修改已派发材料或无声改写活动执行 |
| 并行方案 | 展示共同起点与独立现场；选择继续、文件整合、停止或放弃是不同动作 |
| 接手 | 展示摘要、代码检查点、剩余工作、环境、接收者；责任转移独立选择，不转移私人凭证 |
| 完成 | 默认文案“标记完成”；检查与报告可选，活动执行可另行请求停止，不自动部署 |
| 项目约定 | 保留版本与来源，区分已保存、下轮使用、实际送达；不把编辑即刻广播为事实 |

任务主状态沿用待处理、进行中、已完成；等待反馈是 attention。执行结束不等于任务完成；代码本地修改、提交、合并、发布各按可取得的事实显示。无数据或无能力时显示具体缺失项，不能显示假成功、无来源进度或把未知费用填成零。

执行轨迹展示计划、工具动作摘要、可共享输出和问题，不显示原始思考链、密钥或完整私人会话。历史查看不应被新消息强制滚到底部。

## 6. 对 Figma 方案的采用范围

2026-09-26 比较了 11 张 Figma 导出页面，决定采用其信息组织中的以下部分：

- 求助：问题类型、可增删的材料卡、问题描述、AI／同事选择、回应回到原任务。
- 接手：可编辑摘要、代码变更、待办、环境、接收者、责任是否转移。
- 团队与项目：轻量看板、相关动态、待回复、资料与成果入口。
- 搜索与通知：有权限的结果、清楚标题和摘要、可直接处理的提醒。

不沿用任务与 AI 会话分成两个主工作系统、企业注册作为个人前提、“标记完成并验证”、选择方案即合并主干、按 Agent 数量或成员 token 排名等做法。灰紫配色不是本次主品牌替换。导出中的卡片遮挡、小字低对比和缺少结果标题不能照搬。

Figma 参考只决定信息组织，不自动批准示例模型、隐藏会话迁移、Shell／MCP、SSH、远程部署或终端权限。参考中“本地沙箱”字样不证明真实隔离。

沿用 React/TypeScript、`packages/ui`、`packages/client` 和现有业务契约。先建立 W1 tokens 与共享控件，再逐步迁移 AppShell、TaskHeader、RunStatus、CodeStatus、PromptBar、ContextSelection、AssistanceDrawer、HandoffDrawer、VariantCompare 和 ResultFeedback。具体功能仍沿用原开发任务 ID。

## 9. 当前代码归属

- `packages/ui`：唯一语义 tokens、共享控件和状态，不在页面中另建配色。
- `foundation.css`：浏览器基础、通用表单／布局；`shell`：全局工作台导航。
- `task-workspace`、`discussion`、`prompt-bar`、`execution.css`：任务面板、草稿／讨论、输入与执行配置；`task-assignment.tsx/css`：任务头部负责人、改派/历史抽屉与冲突处理。
- `identity`／`team`：账号、空间和项目成员；`settings`／`resources.css`：能力与节点。
- `workbench`、`projects`、`results`、`work-cards`／`work-pages.css`：工作聚合、项目与成果；`project-settings.tsx/css`：基本信息、修订与冲突处理抽屉；`project-lifecycle.tsx`：同一抽屉中的归档影响、运行选择与恢复。
- `command-menu`：权限范围内的实际搜索与现有动作；`preview.css`：仅虚构订单示例。

面板宽度使用原生滑杆提供拖动与键盘操作，布局按身份／空间保存；手机在讨论和代码／成果之间切换。输入草稿只在当前身份／空间的内存中保留，刷新会清空；不把账号凭证或任务文本写入外观偏好。
