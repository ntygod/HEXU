# 10｜任务研发工作区与原生开发工具衔接

> D1 · M1—M3 · 关联 HX-F04/F05/F09 · 依赖：02、04、05、07；真实运行需 08 或 09。  
> [计划入口](README.md) · [UI 规范](../product/04-ux-and-design.md) · [成果](14-results-feedback.md)

## 1. 目标

用户打开任务即可看到目标、协作过程、代码与结果，不再跳到另一套 AI 工作区。这个页面是 HEXU 的日常核心，必须与真实执行同时建设，不只完成一个管理看板。

## 2. 页面模块

视觉与交互以 [Workbench W1](../design/README.md) 为统一基线，桌面／Web 共用边界见 [ADR-0008](../engineering/adr-0008-client-surfaces.md)。保留一个 Task 工作区，执行记录是其视图，不新增平行的“AI 会话任务页”。Figma 的求助材料卡和交接信息结构在对应功能中采用；未支持能力按实际状态显示。

`TaskHeader` 展示标题、Task 状态、负责人和分享范围；`RunHeader` 展示工具、模型配置、节点和本次执行状态；代码变更／提交／发布另按真实来源显示。主动作是继续、请人或 AI 协助、并行探索和分享成果，不把所有高级配置放成同等权重按钮。

`CollaborationPane` 展示人、AI 与系统事件；`ContextPanel` 展示资料与约定；`ArtifactPane` 切换 diff、文件、终端、预览和成果；`PromptBar` 将输入、工具／模型、材料和送达方式就近组织。宽屏可展开三栏，常规屏幕双栏加按需抽屉，窄屏切换内容，保留每位用户布局偏好。开发记录展示可共享计划与动作摘要，不展示原始思考链。

同一个任务可以有主执行、协助和分支。默认显示主工作线，相关协助以内嵌卡片进入，不把所有输出混成无法分辨来源的聊天。

## 3. 读写与实时状态

先请求 TaskDetail、当前 Run 与最近消息快照，再从服务游标订阅事件。切换任务时停止旧订阅并保留草稿，不能将后到消息写入新任务。每个消息块带稳定 ID，增量和最终消息按 ID 合并。

用户补充要求通过 07 输入 API，显示已发送、待下次使用或无法发送。普通评论和给 Agent 的执行输入在 UI 中说明对象，不把发给同事的一句讨论自动提交给所有模型。

已结束的 Run 允许查看结果或新建继续；Task 为 done 时按钮写“重新打开并继续”。授权在任务内展示范围和原因，普通问题行内回答，不跳到通用审批中心。

## 4. 文件、diff、IDE 与终端

文件与 diff 通过 WorkingCopy 和相对路径读取，执行器限制真实路径和授权根。大文件、二进制、LFS 指针、路径不可用分别提示。活跃目录 diff 标记采集时间；固定成果版本引用不可变快照，不被当前目录覆盖。

代码查看与轻量编辑可复用成熟组件。直接编辑使用文件版本/hash 进行冲突检查，必要时显示差异，不覆盖外部 IDE 的新内容。全功能代码补全、调试器和 IDE 插件市场不在本包范围。

“在 IDE 打开”通过有明确授权的执行器操作或复制路径衔接；不能假设浏览器直接打开任意本地文件。远程节点只提供可用的远程 IDE 方式，不在本机误打开相同字符串路径。

交互终端是独立 TerminalSession，带所有者、node 和 workingCopy。观察输出不等于输入权；获得可写终端需遵守 WorkingCopy 写入约束，不能和受管写入 Agent 悄悄同时操作。需要接管时先停止原写入或选择独立目录。终端流有大小限制、重连与销毁，不把输入日志默认向全团队公开。

## 5. 页面错误和恢复

节点离线保留已同步消息和成果，禁用需要在线的动作并说明；额度不足显示可用配置选择，不自动切换到别人账号；发送失败保留输入；未知过程不显示全绿完成。

权限变化先停止继续展示受限内容，再提供申请入口。外部变化只说明可观察事实，不标注未经确认的修改人。底部输入框、继续选择器和结果区不能因为长日志不断跳动。

## 7. 分段交付

针对已有 UI 的 W1 重建，按 [23](23-workbench-rebuild.md) 的 W1-03/04/05 依次重建任务面板、输入与控制、接续与恢复；W1-09 清理旧视图和状态残留。保留当前可用的 API 接入、身份／权限、事件、输入队列和来源确认，布局、组件结构可以重写。已有能力不按下列初次建设顺序重新从零实现。

先有任务+协作+只读 diff，再接真实工具和输入停止，最后补终端、预览和复杂多面板。11/14 未完成时插槽用明确空状态，不以假按钮冒充可用。

交付说明应说明哪些内容来自节点、哪些来自服务、哪些是模拟。功能质量的内部判断不转化为用户必须完成的额外流程。
