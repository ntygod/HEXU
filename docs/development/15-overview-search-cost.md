# 15｜工作台、团队概览、通知、搜索与费用

> D1 · M3—M4 · 关联 HX-F03/F08/F10/F12 · 依赖：03、04、05、07、14。  
> [计划入口](README.md) · [数据/API](18-data-api-catalog.md)

## 1. 页面目标

我的工作突出继续当前任务、需要回复的事项和最近成果；团队概览突出项目目标、正在推进、阻塞和可查看产物。数据来自实际 Task/Run/Result/讨论，不要求开发者另填一份汇报数据。

工作台不使用成员在线排名、Agent 数量排名和没有依据的完成百分比。可以显示“3 项进行中”，但标明计数是任务状态，不是质量或产能分数。

## 2. 聚合与查询

建立只读查询服务 WorkbenchQuery/ProjectOverview，不再创建可独立编辑的 progress 字段。初始实时 SQL 加合适索引；需要性能优化再用可重建投影，不让缓存成为新的权威来源。

返回 continueTasks、attentionItems、recentResults、projectUpdates、lastSyncedAt。字段携带 deep link、可用动作与来源 ID。存在活动 Run 的 done 任务仍提示执行，不能被默认完成筛选隐藏。

成员列表显示负责事项和请协助入口，不用状态“离开”暗示工作表现。日期按用户时区显示，详情保留绝对时间。

## 3. 注意力与通知

Notification/AttentionItem 从提及、协助、接手、成果反馈和必要授权生成。dedupe key 包含接收者、原因和源对象；同一原因更新同项，不为每个文本 delta 发通知。

已读、已回复、已接受交接是不同状态。已读不自动回答或批准。过期授权不能在旧卡片中继续批准，待处理入口按权威对象重新加载。

支持关注/静音/稍后、站内实时提醒；外部通知在 16 接入。消息只包含允许公开的摘要和权限链接，不能通过通知向无权成员泄露任务标题或敏感文件。

## 4. 全局搜索

搜索覆盖有权的任务、需求、消息、约定和成果，支持类型/项目过滤及稳定分页。先按租户和资源范围筛选，再生成 snippet，不能先检索全库再由前端过滤。

中文输入首先提供标题、编号、明确关键词检索；分词/语义检索可后续替换 SearchPort，不强制新建向量数据库。结果带来源与修订，点击时再次核对权限。删除和撤权需要更新索引并失效缓存。

普通协助受邀者仅能检索明确分享的快照，不因授予一个协助请求而加入整个项目搜索范围。

## 5. 用量与费用

UsageObservation 保存 provider、accountRef、nativeSession/Run、来源、计量范围 incremental/session_total、时间区间和可取得用量；金额使用高精度小数与币种，不用浮点累计金额。

Dedup key 以提供方记录 ID 或稳定事件 ID 为基础。会话累计值需同一身份的 baseline；基线缺失、回退或重置时标记未确定并保留原值，不盲减。模型 token 不是金额，没有价格与账单来源时费用为 null。

CostView 区分 billed/reported/estimated/unknown，汇总说明未计入项，混合币种不直接相加。预算软阈值可以提醒，平台控制后续派发；未报告和已发请求可能产生额外费用，不能宣称绝对零超支。

费用范围可以只给本人或相应管理权限查看，不能自动形成员工排名。

## 7. 不在本包实现的东西

不做产品 A/B 实验平台、收益因果分析、员工工时和效能排行榜。内部团队可以自行评估使用效果；HEXU 只提供自然产生的工作记录与必要导出。

自动生成项目摘要属于可编辑帮助，必须带来源，不编造预计交付日期或“项目已验证通过”。
