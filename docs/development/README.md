## 这套文档如何使用

产品文档回答“做什么、为什么”；本目录回答“在哪一层实现、先后依赖是什么、具体要交付哪些代码和界面”。不另建一套产品范围，不恢复 v1.0 的强制验收、证据中心或多级审批。

UI 开工同时读取 [Workbench W1](../design/README.md)；桌面宿主、Web 或执行边界改动同时读取 [ADR-0008](../engineering/adr-0008-client-surfaces.md)。两者是已确认方向，应用迁移与桌面分发仍是未交付工作，不以参考演示更新功能完成状态。

按新设计重新开发前端时，先读 [23｜W1 前端重建与旧 UI 清理](23-workbench-rebuild.md)。它补充原任务的 UI 子任务、代码接管关系与删除条件，不替换 102 项总账，也不要求从零重写已有业务。

**轻管理、深协作、成果直观。** 默认任务只有待处理、进行中、已完成；核心动作是继续、协助、并行。质量和效果由内部团队评估，开发计划中的错误处理、权限和基本回归属于实现工作，不是新增用户流程。

D1 初次提交只建立计划。现已开始实现；文中拟定目录、接口、表名和命令不一定全部存在，当前子集以源代码、根 README 与进度页为准。原生工具适配尚未接通时不得把模拟器计作真实能力。

## 文档层级与变更规则

产品 v1.1 决定行为边界；开发计划细化实现，不得反向增加业务门槛。跨模块字段、路由、错误码和事件以 01、18 为统一草案，已经落地的契约以源代码同步维护。原生工具接口以锁定版本的官方文档及适配器实现为准，不能把 HEXU 自定义方法名当成原生 API。

工作项使用 `HX-DEV-计划号-序号`，例如 `HX-DEV-11-03`。01—17 每份六项，共 102 项；00、18、19、20、21 是总览、参考或进度，不重复计数。工作项中的前端、后端、执行器是职责，不是已经配置的人数。

技术建议见 01 和 20；本轮实际采用 TypeScript/npm 与本地 SQLite 预览，详见 [ADR-0001](../engineering/adr-0001-local-preview.md)。这不是 PostgreSQL、多用户或远程执行已经实现的声明。具体运行版本由 package.json 与 package-lock.json 记录。

## 完整目标

个人可直接开始；团队可组织需求；Claude Code 与 Codex 可在同一任务接续；人和 AI 可以临时协助；成员可接手；独立方案可并行比较；成果可查看、反馈、标记完成；本地和远程都能工作；日常维护不锁住代码。

“内部评估交给团队”不等于取消停止操作、权限检查和数据保存，也不等于把测试管理重新做成 HEXU 的产品模块。说明见 [内部评估边界](../engineering/internal-evaluation.md)。

本轮原生执行增量见 [21｜实现进度](21-implementation-status.md)；具体环境与能力边界见 [原生使用说明](../engineering/native-execution.md)。真实进程测试、协议替身与真实提供方调用分开记录。
