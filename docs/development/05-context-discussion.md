# 05｜讨论、项目资料、团队约定与上下文

> D1 · M1—M4 · 关联 HX-F02/F06/F08 · 依赖：04 基础、03 权限。  
> [计划入口](README.md) · [继续与协助](11-continuation-assistance.md) · [数据/API](18-data-api-catalog.md)

## 1. 交付目标

用户在任务里讨论、上传资料、保存约定；系统在执行和协作时准备必要材料。用户可以查看和修正上下文，但不需要维护一个复杂的知识后台。知识集中入口不是首次工作的前提。

## 2. 三类内容及其权威性

项目资料包括说明、文件、仓库引用和外部链接；团队约定是有权限成员主动保存的共享规则；当前工作记录包括任务说明、选定讨论、运行摘要、成果和未解决问题。

分别保存 sources/source_revisions、agreements/agreement_revisions、discussion_threads/messages、ai_drafts、context_bundles/context_items。AI 草稿没有用户保存的权威性，原始输出不能自动改成项目约定。已有内容更改保留修订，普通编辑不走审批。

消息 `authorType` 区分 human/agent/system，带来源 Run 或用户。模型自己写“负责人已批准”只是内容，不会触发权限和业务状态。评论编辑保留必要活动记录，不把工具事件伪装成成员发言。

## 3. 上下文装配管线

装配输入是 taskId、目的 start/continue/assist/parallel、受邀主体、所选引用、目标工具配置与数据范围。先权限过滤，再选择版本、去重、截断和总结；不得先抓取全空间材料再让模型“自行忽略无权内容”。

优先保留用户当前要求与必要约定，然后任务资料、最近工作摘要和相关文件。上下文预算是配置值，不假装工具有统一窗口。超过预算时标记 omitted/truncated，不能默默丢掉关键限制。引用以稳定资源 ID、revision、哈希与可读标题记录。

可先使用确定性拼装和用户写的摘要；AI 总结是可选增强，用相同受管执行和费用记录。总结失败回退到原始摘录，不阻断已有材料的普通工作。发送前再次检查权限和目标提供方范围。

ContextBundle 保存实际发送快照。新的约定不自动覆盖活跃 Run；提供“补充发送”或“下次继续时使用”，实际送达状态来自 07/适配器，不把进入数据库当作已被 AI 理解。

## 4. 讨论与局部采用

`POST /tasks/:taskId/messages` 写消息，可带附件和提及；`POST /projects/:projectId/agreements` 接受 sourceMessageId 和适用范围；`POST /tasks/:taskId/context-bundles` 准备快照。统一路由见 18。

用户选择一句讨论“设为项目约定”，在一个轻面板里编辑并保存。相冲突约定显示差异和来源，不能仅以更新时间替代人的选择。

AI 计划或需求草稿采用某段时，提交源草稿版本与目标 expectedRevision；冲突保留用户编辑并展示差异。采纳建议不等于执行 shell，也不会自动授予模型新权限。

附件先通过通用上传完成，再关联到任务。限制大小、类型与渲染方式；HTML/Markdown 默认安全渲染，链接不是后台任意抓取指令。远端导入使用 16 的受控连接器。

## 6. 共享与保留

发送给另一个成员或模型前只准备被选中的内容。协助专用快照与完整 Task 访问权分开，详见 11/12。权限撤销后阻止新的读取和发送，不承诺能收回已经给到外部模型的文本。

主界面只展示项目资料、约定和当前工作。引用清单、哈希与截断原因放在可展开详情；底层正确并不要求用户每次勾选几十项。检索增强在 15 扩展，基础上下文不依赖向量数据库。
