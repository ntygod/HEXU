# 05｜讨论、项目资料、团队约定与上下文

> D1 · M1—M4 · 关联 HX-F02/F06/F08 · 依赖：04 基础、03 权限。  
> [计划入口](README.md) · [继续与协助](11-continuation-assistance.md) · [数据/API](18-data-api-catalog.md)

## 1. 交付目标

用户在任务里讨论、上传资料、保存约定；系统在执行和协作时准备必要材料。用户可以查看和修正上下文，但不需要维护一个复杂的知识后台。知识集中入口不是首次工作的前提。

## 2. 三类内容及其权威性

项目资料包括说明、文件、仓库引用和外部链接；团队约定是有权限成员主动保存的共享规则；当前工作记录包括任务说明、选定讨论、运行摘要、成果和未解决问题。

分别保存 sources/source_revisions、agreements/agreement_revisions、discussion_threads/messages、ai_drafts、context_bundles/context_items。AI 草稿没有用户保存的权威性，原始输出不能自动改成项目约定。已有内容更改保留修订，普通编辑不走审批。

消息 `authorType` 区分 human/agent/system，带来源 Run 或用户。模型自己写“负责人已批准”只是内容，不会触发权限和业务状态。评论编辑保留必要活动记录，不把工具事件伪装成成员发言。

## 3. 上下文装配管线

装配输入是 taskId、目的 start/continue/assist/parallel、受邀主体、所选引用、目标工具配置与数据范围。先权限过滤，再选择版本、去重、截断和总结；不得先抓取全空间材料再让模型“自行忽略无权内容”。

优先保留用户当前要求与必要约定，然后任务资料、最近工作摘要和相关文件。上下文预算是配置值，不假装工具有统一窗口。超过预算时标记 omitted/truncated，不能默默丢掉关键限制。引用以稳定资源 ID、revision、哈希与可读标题记录。

可先使用确定性拼装和用户写的摘要；AI 总结是可选增强，用相同受管执行和费用记录。总结失败回退到原始摘录，不阻断已有材料的普通工作。发送前再次检查权限和目标提供方范围。

ContextBundle 保存实际发送快照。新的约定不自动覆盖活跃 Run；提供“补充发送”或“下次继续时使用”，实际送达状态来自 07/适配器，不把进入数据库当作已被 AI 理解。

## 4. 讨论与局部采用

`POST /tasks/:taskId/messages` 写消息，可带附件和提及；`POST /projects/:projectId/agreements` 接受 sourceMessageId 和适用范围；`POST /tasks/:taskId/context-bundles` 准备快照。统一路由见 18。

用户选择一句讨论“设为项目约定”，在一个轻面板里编辑并保存。相冲突约定显示差异和来源，不能仅以更新时间替代人的选择。

AI 计划或需求草稿采用某段时，提交源草稿版本与目标 expectedRevision；冲突保留用户编辑并展示差异。采纳建议不等于执行 shell，也不会自动授予模型新权限。

附件先通过通用上传完成，再关联到任务。限制大小、类型与渲染方式；HTML/Markdown 默认安全渲染，链接不是后台任意抓取指令。远端导入使用 16 的受控连接器。

## 6. 共享与保留

发送给另一个成员或模型前只准备被选中的内容。协助专用快照与完整 Task 访问权分开，详见 11/12。权限撤销后阻止新的读取和发送，不承诺能收回已经给到外部模型的文本。

主界面只展示项目资料、约定和当前工作。引用清单、哈希与截断原因放在可展开详情；底层正确并不要求用户每次勾选几十项。检索增强在 15 扩展，基础上下文不依赖向量数据库。

## 7. 已交付的 05-02 文本/链接切片

项目资料现有独立模型、稳定 ID、类型、原文/URL、内容指纹、修订、创建/更新者和删除标记；迁移 13 不补造旧资料。读取需当前项目访问，写入需 edit/manage；当前记录、不可变修订、项目 outbox 与回执同事务，重放重新检查权限。删除可恢复且保留历史，不改变既有 Task/Run/Operation；归档仍可人工维护。

W1 项目资料标签页提供列表、搜索、正文/链接阅读、编辑冲突、原请求确认、修订历史、删除/恢复及稳定深链接。HTML 为原文，链接不自动抓取；来源信息按需展开。网络错误保留编辑草稿，权限撤销和身份/空间变化清除；草稿只在内存中。

05-02 仍为部分实现，附件上传/存储和仓库连接未交付。约定与明确选材由下列切片接入；不得从已保存资料推断已向模型送达。用法与 API 见 [项目资料](../engineering/project-sources.md)，实际检查见 [21](21-implementation-status.md)。

## 8. 已交付的 05-03 讨论约定切片

当前项目公开讨论经成员编辑并明确保存为项目约定，保留原任务/消息、源指纹、节选、作者与人工发布者。系统消息、私有或跨项目来源拒绝直接发布；源版本变化须重新核对。项目约定可修改、停用/启用，或用新约定明确替代同项目的有效版本；新旧两份记录/关联、修订、项目变更版本、outbox 与回执同事务。

W1 有讨论发布入口、项目标签页、任务内查看及停留期间变化提示；保留当前权限、固定编辑基线、原请求确认和历史阅读位置。原 Project/Task、Run/Operation 材料和目录锁不被改写。05-03 仍部分实现，持久提醒、任务子范围约定及完整模型送达联动仍缺；明确选材见下节，实际检查见 21。

## 9. 已交付的 05-05/06 明确选材切片

原生与本人节点可选择同项目资料/有效约定，固定引用、修订和哈希；初始不额外选择材料。全文或有界开头摘录显示遗漏量，补充材料限 10000 字符、16 项，超限报错。私有任务不带入项目材料，链接不抓取。新增界面的确认同时绑定当前人工上下文和选材版本。

ContextBundle 与 Run/Operation、派发和回执原子提交；节点等待固定完整输入，原生等待固定补充材料并保留停止后重建代码摘要的原语义。创建、等待协调、最终事务和启动前复核选材，版本失效暂停且保留原材料/停止请求/未知锁。已获许可的工作不被假装收回或自动重试。

W1 提供目录搜索、摘录、预算、原请求确认和运行快照；真实 spawn/running 事件才记启动，保存、ACK 或许可不等于模型收到。05-05/06 仍部分实现，自动推荐/总结、持久偏好、协助/并行目的和实时送达仍缺。下一项按 22 推进 05-04；接口见 [材料快照](../engineering/project-materials.md)。

## 10. 已交付的 05-04 草稿采用切片

当前任务已有 AI 回复可明确整理为草稿，保留来源指纹、独立修订与作者；未选择内容不丢失，草稿没有约定权威性。最多 16 个不重叠片段可追加/替换同任务说明或同项目资料正文，草稿/目标版本、当前权限、共享范围和长度同时检查，采用前后记录、修订、事件和回执同事务。私有草稿不能写项目资料或其他任务。

W1 入口、编辑、片段与目标比较、冲突、暂时读故障保留和原请求确认已接入；任务说明采用暂停待接续而不改变活动运行或目录锁。独立需求/成果目标、自动生成、富文本和批量采用仍缺，05-04 保持部分实现。下一步按 22 推进真人有限协助；用法见 [AI 草稿](../engineering/ai-drafts.md)。
