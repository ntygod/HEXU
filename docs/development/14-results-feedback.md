# 14｜成果版本、功能预览与团队反馈

> D1 · M1 基础、M3 完整 · 关联 HX-F09 · 依赖：04、05、07、10 的页面/结果接口。  
> [计划入口](README.md) · [UI 目标](../product/04-ux-and-design.md) · [API](18-data-api-catalog.md)

## 1. 目标

用户无需读终端即可看见功能、文件、说明和代码，并反馈、继续或标记完成。成果可在任务进行中分享，完成也不要求先生成正式成果档案。报告与发布链接是可选关联，不建设质量证据中心。

## 2. Result 与版本

Result 是成果容器，ResultRevision 保存不可覆盖的版本：task、来源 Run/人、类型、说明、文件/预览/diff 引用、代码基线、创建时间与访问范围。类型支持 text/file/diff/preview/api_example/link，可组合多个附件。

发布新版本不覆盖旧评论的目标。反馈锚点包含 resultRevisionId、文件路径/范围或页面标识；源变化后标记“此反馈基于先前版本”，不自动否定历史完成。

创建接口接受已存在且有权使用的附件引用，不让任意对象存储 key 变成可访问文件。AI 总结是可编辑草稿；成员发布时保存实际内容，不捏造“测试全部通过”。

## 3. 基础版本先行

M1 先实现文字、文件和只读 diff 的 ResultRevision、任务内成果卡与分享范围。这样 13 可以复用数据结构，不等待完整在线预览和所有 UI 完成。

M3 加入功能预览、版本切换、反馈锚点和项目成果汇总。没有可运行 Web 应用时使用文件/接口样例，不强制每项任务都开一个端口。

## 4. 预览架构

PreviewSession 关联 node、workingCopy、用户明确选择的启动配置/服务、端口、允许的访问范围和生命周期。启动开发服务器是获授权的执行动作，不能因网页截图需要就自动执行未知仓库脚本。

本地电脑主动连接服务的预览隧道，服务只代理登记过的 node+port，不接受用户任意 URL 作为通用代理。转发请求校验访问者、会话有效期、方法/头范围；不能借预览访问云元数据或其他私有服务。

预览使用与主站身份分离的 origin。推荐独立预览域或配置等效隔离，预览凭证短期、只对当前 session 有效；HEXU 主站 Cookie 与长期 token 不发送给被预览应用。鉴权链接尽量一次性兑换成受限会话，不把长期凭证放进 Referer 和日志。

iframe 仅作展示容器，不是唯一安全隔离。用户可在独立窗口打开；转发 WebSocket/HMR 需同样鉴权。节点休眠、进程停止或隧道断开显示失效原因，保留文件/截图入口，不显示缓存画面冒充实时可用。

## 5. 反馈与完成

成果页主区是预览/diff/文件，侧区是做了什么、讨论与版本。主要动作提出修改、继续处理、标记完成。反馈可变为原任务追加要求或新 follow-up task，由用户选择，不自动复制一堆任务。

标记完成调用 04 的同一完成命令，记录成员与时间；报告缺失不阻挡。活动执行仍存在时提示停止选择，状态保持真实。后续继续明确重新打开。

检查报告保存原来源与代码版本，不成为统一 Evidence 体系。ReleaseReference 记录链接、环境、来源和可获取状态；完成 Task 不自动发布，PR 合并不冒充上线。

## 7. 数据与操作注意

大文件下载走短期鉴权，删除与归档不立即销毁仍被引用的版本。非文本产物不要在浏览器执行来源不明的 HTML；允许的主动内容放在受隔离预览里。

未知发布状态显示未知。管理员与老板看到的是有权限的成果，不自动获得节点的 shell 控制权。内部团队怎样评估产品和成果质量不进入本页面的必经流程。
