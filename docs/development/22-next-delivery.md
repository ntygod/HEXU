## 下一项：HX-DEV-06-03/04、07-02、10-03、12-02 接手现场进入实际研发

PR #17—#22 已全部合入 main；其后已经补齐本机接受确认、当前操作者和可选负责人移交，不重新实现这些切片。下一项解决：接收目录仍只是普通文件副本，当前节点没有该目录的 Git/执行登记，用户不能从“已接手”直接推断可以启动模型。

目标：接收者用自己的原身份明确把选定现场准备为受管 Git 工作区，单独授权工具/目录，然后从同一 Task 创建真实的新 Run。模型实际启动、提供方成功与任务完成仍分别记录。

## 本轮范围

1. 从本人已确认的接手记录和本机不透明目录引用定位原目录。重新检查当前任务/项目/节点权限、原文件和目录身份、现场变化及未知写入；浏览器不得注册任意路径或传入可执行文件名。
2. 明确处理原副本缺少 Git 元数据/祖先的事实。若准备有限 Git 现场，先展示范围并取得本机同意，只操作本次拥有的元数据；不执行原 hooks/filter、脚本、网络或覆盖用户改动。不能把有限历史称为完整原仓库。
3. 目录登记与模型执行各有明确授权。保留旧凭证、检查点/接收副本及原生会话的绑定；不能通过改写旧票据、目录列表或身份把旧授权扩展到新目录。必要的新登记记录应有独立修订、原请求回执和撤销规则。
4. 复用现有 Node/Run/dispatch/工作区锁与工具策略，验证当前目录/权限/策略再创建新 Run。默认使用接收者自己的新会话，不复制发送者账号或原生历史；失败不隐式重建、改派或重复付费。
5. 在原任务展示实际可用的新现场与明确缺失项，沿用 W1 继续/执行面板。登记 ACK 不是模型启动，启动也不是模型成功。支持刷新的持久状态，保留部分准备失败和未知进程的现场。

首个切片继续限定同服务、同项目、同机 Linux；用协议替身验证实际进程/文件/HTTP机制，不把它写成真实账户联调或跨平台支持。
