下一项补齐现有对象副本不能交给另一个明确授权节点的缺口。**首个切片限定同一个 team-local 控制服务、同一项目、同机回环的两个明确节点**；用于验证受控传输与独立接收，不声称已支持跨电脑部署、Handoff 接受或模型执行。

## 本轮范围

1. 原任务当前有权者选择固定保留材料和接收节点，明确说明包含的单提交、期限、数量、排除项及已提交敏感内容风险；不能从项目阅读权或旧恢复报告推导材料传输授权。
2. 源节点本人逐次同意读取/发送，接收节点本人单独同意接收。固定来源和目标绑定，复查双方当前项目/任务/节点权限；接收者使用自己的凭证，绝不复制源节点状态库、模型账号或完整 HOME。
3. 设计有界传输清单、对象字节与安全临时存储。类型、哈希、数量、总字节、序号和完整闭包全部核对后才可用；不把未完成上传或对象指纹当成已收到材料。访问控制、保密与期限必须随传输实现，不提供公开下载路径。
4. 接收为独立私有对象副本，不执行 checkout/filter、脚本或模型，不直接落入工作目录。目标恢复仍需重新预检和本机明确写入/发布，不能继承源节点旧路径授权或绕过现有边界。
5. 记录中断、撤销、到期、固定回执与可重复对账。仅清理本次明确创建的传输材料，不删除源副本/已恢复目录；旧回执不能复活撤销。相应材料状态回到原 Task 检查点区域，不新增第二套任务或质量审批。

先完成能真实收发和拒绝越权的有界纵向切片，再扩展规模。只读模拟载荷、直接复制 SQLite 或手工更改绑定不能算作传输实现。
