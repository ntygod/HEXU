## 下一项：HX-DEV-12-03/05/06 接受接手与操作者切换

从 `codex/handoff-offers` 的最新已验证提交继续。它承接 PR #17—#21 的预检、实际恢复、结果回报、受控传输和接收端恢复；这些能力尚未合并 main，不能从 main 旧代码重新实现。当前已有邀请发布、拒绝、撤回、到期与历史，接受接手尚未开放。

目标：让指定接收者在确认自己的当前恢复现场、身份和写入冲突后，明确接受同一 Task 的工作。接受成功只表示接手提交，不表示新 Run 已开始或原进程已经迁移。

## 本轮范围

1. 从一份仍有效的 offered 邀请开始，固定邀请/Task 修订、接收者、节点及 transfer/hash。当前双方权限、材料期限和任务变化均在动作前及最终提交前重新检查；已关闭邀请不能复活。
2. 补接收节点本机的新现场核验与明确同意。复用原私有副本、原恢复日志和排他目录规则；历史 received/restored 报告不是当前文件证据。浏览器不能提供任意路径或借发送者旧授权自动写入。
3. 明确受管目标目录与原/新写入者状态。未知旧进程继续保留锁；节点离线、心跳超时或停止请求不能当作终止确认。普通文件副本不升级为完整仓库；需要源/目标补充条件时给出真实可操作说明。
4. 将接受操作的意图、处理中刷新/取消/重启与结果对账持久化，再在版本校验的事务中写 accepted、当前操作者、事件和回执。失败不改操作者、不自动重复恢复或付费执行；固定材料与原现场保留。
5. 在同一个任务接手抽屉展示处理状态与实际缺失项。负责人默认不变；可选责任转移若进入本轮，须由接收者另行明确接受并复用现有改派规则，不能捆绑或隐式扩大访问。

首个切片仍限定同服务、同项目、同机 Linux 节点。不引入强制质量报告或新的任务/AI 会话系统，不自动启动模型。
