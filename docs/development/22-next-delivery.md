# 22｜下一步交付：先完善持续工作，再进入跨电脑协作

更新：2026-09-26（UTC+8）。E2b2 实现本机回环上的独立节点本人授权执行。账号、配对、目录与执行的基本链路已有，但不等于完整团队平台。

## 当前落点

同一 Task/Run 已有控制服务到独立进程的派发、一次性许可、输出和停止。节点默认只有摘要，本机 enable-execution 才增加模型读文件与共享输出权限。首期仅本人派发，不把项目成员身份变成节点控制权。保守恢复可能需要明确重新建一次未启动执行，但绝不重复启动旧命令。

## 下一批 E2b3：任务持续工作与恢复体验

优先衔接 `07-04` 的下一轮要求队列、`11-01/02` 的节点同目录继续，以及 `08-03 / 09-02` 的原生会话映射。目标是在一个任务中看过结果后继续修改，不用重新组织工作说明。明确区分新会话接续与原生 resume，不能只复制会话 ID 就称为恢复。

先复用已经安全的节点新会话、固定目录和一次性派发：在来源已确认停止时带上明确来源及选择的近期材料创建新 Run；活动执行只接收下一轮草稿或安排，不冒充已即时送达。涉及工具切换、目录/策略变化时重新确认范围。原生 resume 若需要工具能力或敏感会话目录，另作明确版本/账户边界，不自动兜底。

同时完善 unknown 的节点本机诊断和待处理列表，保留启动/停止证据，避免用户只能从运行卡抄 ID。任何简化恢复界面都不得删除占用或自动终止旧 PID。

## 跨电脑协作的前置

远程 TLS/WSS、Origin/设备认证、防重放、连接代次、正式 PostgreSQL 和备份迁移、真实部署初始化需要成组交付；不单独放开监听地址，也不把反向代理当完整上线。`03` 的邮箱验证/找回密码、项目编辑归档和角色管理仍需按清单补齐。

指定他人使用节点必须有本机授予的主体/项目/目录/工具/预算 scope，不能由空间管理员代授。临时协助需要选择性快照和有限 AccessGrant，跨成员代码接手需要不可变检查点，并行写入需要独立工作区；这些原任务没有被 E2b2 替代。

真实提供方生成联调需要授权的有效账户和非敏感试验仓库，当前继续标未完成，不把 Key 写入仓库或公共 CI。UI 随功能纵向交付；团队内部效果和质量评估不变成强制产品审批。
