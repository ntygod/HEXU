## 下一项：HX-DEV-13-01 共同起点与独立方案定义

原远端 PR #17—#22 和接受接手 PR #23 已合入 main。其后已打通同机 Linux 接手原目录的有限 Git 准备、独立本人配对、另行执行授权与同 Task 新 Run；不要重新实现接受或改写原节点目录/凭证。用法见[接手现场研发](../engineering/handoff-workspace.md)。

下一条用户路径是围绕同一 Task 定义多个方案，并明确它们共享什么起点。先做可持久、可刷新、权限正确的 WorkBranch 定义与共同材料；独立代码目录和实际调度接下一切片。不能用几个任务副本、终端或模拟结果冒充隔离并行。

## 本轮范围

1. 复用原 Task 权限/修订、检查点与材料模型，固定共同目标/说明和选定提交；不从 HEAD、当前目录摘要或变化中的资料推断相同起点。可先限定项目任务和已发布的单提交引用，明确未包含的内容。
2. 同一事务创建有界的多个 planned WorkBranch，记录共同起点、各自名称/目标、创建者和修订；幂等结果、事件和 outbox 原子保存，旧回执前核对当前权限。
3. W1 任务内展示方案定义和准备状态，编辑草稿固定基线，临时读取故障保留，降权清除编辑。刷新读取原记录，不重新建方案；未创建独立工作目录前不显示可执行或虚构产物。
4. planned 阶段可明确放弃，保存独立历史；不能改变 Task 状态、停止其他 Run、删除目录或自动调用模型。只有代码现场/Run/Result 实际建立后，才推进后续 active/ready/selected 语义。
5. 核对部分创建、并发版本冲突、幂等、撤权、刷新与边界值。后续 13-02 复用目录准备和 Node 派发；每条代码分支独立 WorkingCopy，选择方案不等于整合代码。

首个定义切片不启动并行付费执行；后续代码路径继续限定同服务、同项目、同机 Linux。真实提供方联调与跨平台交付分开记录。
