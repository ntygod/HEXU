# 22｜下一步交付：从节点身份进入受管任务执行

更新：2026-09-26（UTC+8）。E2b1 已交付独立进程配对、节点身份、项目范围、实际目录摘要和有界摘要重放。不是完成了团队 AI 执行。

## 本轮为什么先做到这里

原 06-01/02/03 的最小可用边界需要真实的本机确认、持久化身份、主动连接与撤销。先建立这个边界，避免登录用户或空间管理员直接继承服务器的目录和模型账户。目录摘要是可见的实际使用路径，不用假 Run 或模拟命令声称任务已执行。

E2b1 的传输是回环 HTTP 请求，不是最终 WSS；spool/ACK 只保存有界摘要。它可以在同一机器上独立于控制服务重启，但不支持跨电脑，不自动取得任何原生工具权限。

## 下一切片 E2b2：一项任务在获准节点执行

主线是 `07-01/02/03/06` 联动 `06-04/05/06` 和既有 08/09 适配器。保留同一 Task/Run 数据模型，不在节点造一套团队任务系统。

先明确节点所有者授予“本人执行/指定项目成员执行”的具体能力，以及目录、工具、账户引用、编辑范围、时间与费用边界。当前项目目录摘要可见性**不得直接变为执行授权**；网页不能添加路径、CLI 参数或替换本机账户。

控制服务在事务内建立 Run、输入快照和 dispatch outbox。节点落盘 accepted 只代表接单，preparing/running 必须由实际进程确认。每个命令绑定唯一 dispatchId 和 generation，本地用受管工作区锁与启动记录防止重放导致重复模型调用。

目录有未确认旧写入者时不释放给新任务。停止请求、自然完成、断线、凭证撤销、控制服务重启和节点重启须走明确状态，不能靠“心跳离线”推断进程停止。进程创建前后的非原子窗口要保留 unknown/需要核对，而非再次 spawn。

UI 在现有任务工作区选择具备实际授权的节点和工具，展示配置、来源、真实启动和停止结果；任务完成仍不依赖测试报告。节点身份和摘要页面复用，不另建执行管理审批中心。

## 仍需独立安排

正式远程 HTTPS/WSS 部署、PostgreSQL/备份迁移、系统凭证存储、跨平台进程管理、工具打包升级和有效账户模型联调尚未完成。跨机器接手需要不可变检查点，协助需要选择性材料与有限授权，并行需要独立工作区，不能用当前目录计数替代这些能力。
