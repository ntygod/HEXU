# 22｜下一步交付：先完善持续工作，再进入跨电脑协作

更新：2026-09-26（UTC+8）。E2b3 实现本机回环上的独立节点本人授权执行。账号、配对、目录与执行的基本链路已有，但不等于完整团队平台。

## 当前落点

同一 Task/Run 已有控制服务到独立进程的派发、一次性许可、输出和停止。节点默认只有摘要，本机 enable-execution 才增加模型读文件与共享输出权限。首期仅本人派发，不把项目成员身份变成节点控制权。保守恢复可能需要明确重新建一次未启动执行，但绝不重复启动旧命令。

## 下一批 E2b4：节点接续 Operation 与恢复体验

本轮已落地下一轮队列与源执行已结束后的手动同目录接续。下一步将节点路径对齐既有 preview 的 Operation：明确 wait/request_stop、固定来源与选材、持久化预约、等待时取消、确认停止后的再次核验、Run 关联原子提交。自动接续须在提交时明确授权；新要求不能悄悄改变已经授权的材料。

不要把本轮 201+Run 的节点接续直接称为 202 Operation；节点与 preview 的不同恢复机制需要明确适配。未知写入者、服务重启、节点撤权和本机策略更改依然不自动重跑。

原生 resume/steer 是独立交付：需要按照实际工具版本和账户边界核对会话存储及恢复协议。当前所有接续仍使用新会话。有效账户真实生成待授权的非敏感环境联调，不能用复制 session ID 或替身成功代替。

## 跨电脑协作的前置

远程 TLS/WSS、Origin/设备认证、防重放、连接代次、正式 PostgreSQL 和备份迁移、真实部署初始化需要成组交付；不单独放开监听地址，也不把反向代理当完整上线。`03` 的邮箱验证/找回密码、项目编辑归档和角色管理仍需按清单补齐。

指定他人使用节点必须有本机授予的主体/项目/目录/工具/预算 scope，不能由空间管理员代授。临时协助需要选择性快照和有限 AccessGrant，跨成员代码接手需要不可变检查点，并行写入需要独立工作区；这些原任务没有被 E2b3 替代。

真实提供方生成联调需要授权的有效账户和非敏感试验仓库，当前继续标未完成，不把 Key 写入仓库或公共 CI。UI 随功能纵向交付；团队内部效果和质量评估不变成强制产品审批。
