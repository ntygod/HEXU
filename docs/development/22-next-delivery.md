## 下一项：HX-DEV-12-02 本机恢复结果的任务内可见性与对账

已有本机提交引用、独立对象保留和只读恢复预检；[PR #18](https://github.com/ntygod/HEXU/pull/18) / `codex/checkpoint-restore-write` 在 PR #17 基础上增加 Linux 本人两次确认的暂存写入、持久对象/实际文件重验、`RENAME_NOREPLACE` 排他发布、本机进度与明确清理。使用见[新目录恢复](../engineering/checkpoint-restore.md)。分支尚未并入 main，不能从 main 的旧能力或旧批次继续重做。

当前恢复证据仅在本机日志/CLI：任务页面不会显示新的恢复结果，也没有通过恢复自动创建服务端 Operation、接受 Handoff、转移操作者或启动模型。下一项让原任务在当前权限下看见**有界、明确来源、可追踪的恢复结果**，不把最后一次节点报告当作连续可用保证。

## 本轮范围

1. 设计并实现有界的本机恢复结果元数据：原保留请求、节点/任务绑定、恢复记录身份、计划/结果指纹、数量、时间和实际状态；不上传路径、文件名、对象字节或凭证。
2. 发布前复核当前原节点/原任务权限。恢复结果、顺序回执与任务 outbox 原子保存；幂等重放不能绕过撤权、反转后续状态或触发本机重新恢复。
3. 本机先持久保存待确认报告，再发送；断线/丢失回执只对账原结果。区分暂存已核验、文件已发布、日志/同步未知、已取消与已清理，不从目录存在或旧日志推导 restored。
4. 在现有 Task 检查点区域展示最后报告、来源与边界。恢复写入和目标选择仍由本机逐次明确授权，浏览器不取得任意路径写入能力。
5. 处理当前权限变化、未知回执和刷新读取；真实 Git/HTTP/SQLite/CLI 与受影响浏览器流程使用独立临时材料，不使用主业务数据库。

只读预检不是写入许可；恢复完成不是模型执行或任务完成。本次不为成功结果再增加质量报告/审批流程，也不重建 W1 或第二套 Task/Run/Operation 系统。

## 不在这次完成范围内

跨电脑对象传输、远程部署、LFS/子模块实体、祖先历史、多仓库、补丁/未跟踪文件、remote identity、正式 Handoff 生命周期，以及恢复目录的模型执行。单提交输出不是完整 Git 仓库；发布不表示接管原现场。中断暂存的原位续写及未知发布的自动修复仍不能擅自开启。
