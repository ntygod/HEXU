## 1. 重建范围

旧仓库已经有真实页面、表单、身份恢复、权限反馈、事件更新、输入队列、等待接续与 Codex 恢复选择。它不是只有静态样式的空壳。

按 W1 **重新开发呈现层的布局、组件和交互组织**，不要求沿用旧 DOM、CSS、页面分栏或弹层结构。已有 API 接入和状态规则可以保留或迁入新组件；它们不是因为位于 `.tsx` 文件中就可以一起删除。

用户进一步确认：以整套新 UI 替换旧 UI，不在旧页面上继续叠加新样式。页面和组件按新工作台重新组织，旧页面、布局与 CSS 在本次 W1-03—09 全部接管并删除；中间提交只作为实施步骤，不把新旧混搭当作最终交付。W1-01/02 新基础保留，接口、身份权限、事件、输入和执行／接续行为迁入新页面。

新界面接管一个流程后，在同一切片删除已失去引用的旧视图和样式。旧实现由 Git 历史保留，不长期维护 `old-ui` 应用、第二套 Task 页面或两条产品入口，也不先清空 `apps/web` 再重新拼接业务能力。

## 2. 现有代码的处理方式

| 代码入口 | 可以重建／替换 | 必须保留或明确迁入新实现 |
| --- | --- | --- |
| `apps/web/src/App.tsx` | AppShell、工作台、项目、TaskPage、成果页、设置、搜索的布局与视觉；可按实际页面拆文件 | 原路由与任务 ID、真实查询和动作、查看／编辑区别、任务完成与执行状态的分离 |
| `apps/web/src/styles.css`、`packages/ui/src/tokens.css` | 旧配色、尺寸、页面选择器；以 W1 共享 tokens 和密度替换 | 浅深色、可读性、焦点和响应式；仅删除不再被使用的旧变量和规则 |
| `packages/ui/src/index.tsx` | Button、Dialog、Avatar、状态组件和图标的视觉实现 | busy／disabled、可访问名称、弹层 Escape 与返回焦点、Task／Run 的不同语义 |
| `identity.tsx`、`team.tsx`、`nodes.tsx` | 登录、空间、邀请、成员、配对和节点展示 | 会话恢复、权限撤销、切换身份／空间清空旧数据、节点可见性与控制权的区别 |
| `state.tsx`、`packages/client/src/index.ts` | 为新组件拆出必要的状态与展示代码 | 真实请求、当前空间、错误处理、修订与幂等语义、SSE 及访问撤销处理；不要复制第二套客户端 |
| `native.tsx`、`node-execution.tsx` | 工具选择、配置、材料确认和运行状态的视图组织 | 实际能力、源执行／目录、材料版本、选择范围、费用确认、明确重开、原生恢复与新会话的分流 |
| `next-inputs.tsx`、`continuations.tsx`、`node-continuations.tsx` | 集成到稳定输入区和按需抽屉／进度卡 | 作者编辑／撤回、queued／attached／started 区别、202 Operation、固定材料、等待取消、needs_attention 和历史 |
| `forms.tsx`、`preview.tsx` | 表单视觉、虚构订单预览的呈现方式 | 已有创建／编辑／评论／成果行为；旧 demo-preview 引用需有明确兼容展示，不修改或清空用户数据库 |
| `tests/e2e` | 随新布局调整定位方式和操作步骤 | 原行为断言；不能删掉权限、停止、接续、恢复用例来让新 UI 通过 |

`apps/control`、`apps/runner`、`packages/contracts/domain/db/identity/adapters` 的业务与协议能力不因视觉重建被删除。确需契约变化时只调整本次功能涉及的边界，并同步原工作包；不为了复刻演示而修改 provider 的真实状态。

### W1-01｜共享视觉基础

将设计 tokens 映射到应用的共享实现，明确默认深色与用户已保存的主题偏好如何处理，提供 compact／comfortable。重建 Button、输入、状态标签、Dialog／Drawer 和 EmptyState；两个主题的前景与背景配对一起迁移。

完成依据：真实页面已经消费 W1 变量；控件在正常、忙碌、禁用、错误和键盘焦点状态可用。可以短期保留必要的旧变量映射，但记录消费者并在对应切片结束后移除。

### W1-02｜应用壳层

替换旧侧栏和页头，沿用现有项目、任务、成果与设置路由。空间／身份切换保留当前隔离机制。全局命令入口复用真实搜索与已有动作，不另造会话任务列表。

完成依据：刷新和直接 URL 可进入原任务；空间切换与撤权后不残留旧数据；窄屏收起导航后仍有入口。此项不以安装 Electron／Tauri 为前提。

### W1-03｜任务工作区

TaskPage 按 W1 重新组织为任务头、过程／讨论、结果面板及输入插槽。分别显示业务状态、Run 状态与实际可取得的 Git 信息；现有消息、成果、原生事件和 diff 迁入新面板。

完成依据：两种模式都能查看各自合法数据，讨论与结果回到同一任务；历史阅读不被新消息抢走位置。节点当前不提供的远程 diff、终端或真实预览不能用演示内容填充。

### W1-04｜输入与工具控制

迁移既有真实工具／节点选项、模型配置、只读／编辑模式与任务说明。将下一轮要求整合到输入区和队列视图，保留本人编辑／撤回、修订冲突和使用记录。普通讨论、下一轮要求与执行请求有明确区别。

完成依据：保存下一轮要求不改变活动执行或已排队命令；未选择的要求不进入新执行；失败保留草稿；项目只读状态和节点所有权仍控制操作。模型与节点组合来自能力，不照抄原型中可任意切换的示例配置。

### W1-05｜接续和原生恢复

重建材料选择、发送文本预览、wait／request_stop、进度、取消和 needs_attention 提示。继续保留 preview 与 node 的实际协议差异。E2c1 的 Codex 恢复必须明确继承原生历史、使用受支持来源，不能与等待新会话混为一条隐式路径。

完成依据：原有 202 Operation 等待／取消／刷新和明确恢复流程在新 UI 中可操作；上下文、来源、目录、策略变化仍使确认失效；恢复失败不静默新建。开始前重新读取远端实际能力，不假定后续 Claude 恢复一定不存在或已交付。

### W1-06｜身份与团队界面

按新视觉重建现有账号、空间、邀请和项目成员管理。复用 IdentityGate 与请求作用域，不降低后端权限。个人与团队目标入口按 ADR-0008 组织，正式纯个人模式尚无实现的部分明确记录，不把 preview 示例身份改称真实个人账号。

完成依据：登录、退出、会话撤销、加入／切换空间、成员撤权、项目只读／编辑流程保持有效。新图中的 SSO、邮件找回等只在对应原任务真实接入后开放。

### W1-07｜工作台、项目与成果

围绕继续工作、待回复、项目任务和实际成果重建页面；新建／编辑任务、说明、评论、完成／重开和成果反馈接原 API。成果说明与版本只展示已保存的数据，缺少不可变版本能力时不伪造历史。订单示例保持明确的 preview 标识和兼容入口。

完成依据：列表／看板使用同一任务状态；完成无需报告，活动执行继续可见；成果回复保留在原任务；team-local 空数据不自动填充虚构项目、成员或成果。

### W1-08｜资源与搜索

重建工具能力、节点配对／摘要／撤销、已授权执行范围及搜索结果。模型账户、节点在线和执行状态分别表达。搜索继续按当前主体和空间过滤；未实现的完整费用账本或资料搜索不展示假数值。

完成依据：配置缺失和不可用有具体原因；节点查看权不等于发起权；直接搜索／链接和撤权后的页面均沿用已有访问边界。

### W1-09｜收口与删除

逐页替换时即可删除失去引用的旧呈现代码；此项清理最后的过渡映射、重复样式和临时入口。核对键盘焦点、弹层返回、长内容、空／错误／断线、主题与窄屏。保留默认 preview 的模拟能力及真实 team-local 的业务路径。

完成依据：默认应用入口全部使用新页面，旧 UI 无消费者；接口和领域未出现第二套状态来源；原浏览器行为检查已按新交互更新且执行结果有记录。不要仅凭截图确认或删掉失败用例。

## 4. 删除规则

1. 先由新页面接管原路由和可用行为，再删除本次已替代的旧组件、CSS、无消费者的导出与资源。
2. 同一文件含视图和业务逻辑时，先迁出仍需要的行为；不能按文件名或“UI 目录”整块删。
3. 不保留长期运行的旧 UI 开关、重复任务库或并行 API 客户端；恢复旧视觉可查 Git 历史。
4. 不删除用户数据、迁移、provider、会话记录、权限或有效测试来配合新外观。
5. 每批变更记录已替代入口、删除内容、实际验证和剩余范围；先同步远端，避免覆盖其他人正在交付的 provider 能力。
