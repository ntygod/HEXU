# 2026-09-30：已有文件写回底层检查点（未接用户入口）

此独立工作树接续新父目录切片，只实现后续明确写回需要的本机原语与包装器。没有启用修改/删除应用请求、CLI或页面入口，不能据此声称13-05已有文件写回已交付；未与正在验收的PR29混合。

## 有界机制

- 调用方将固定目标父目录与另行明确选定的私有备份目录分别固定为目录描述符；备份必须同一文件系统、本人0700，目标父目录不可被组/其他用户写入
- 普通已有文件先按原inode、完整Git blob、模式、单链接和稳定时间戳核验；仅0600/0644/0700/0755且无扩展属性的文件，8 MiB以内。特殊权限、ACL/xattr、链接与其他文件类型拒绝
- 替换使用匿名inode写入并核对新字节，保存到排他的私有材料槽，再以Linux `RENAME_EXCHANGE`交换；原文件完整inode进入备份。普通读写可见性不扩大，执行位按明确来源与原读取权限调整
- 删除以`RENAME_NOREPLACE`移入空备份槽，不unlink。无copy或普通rename降级；源/两父目录均同步，并在原生组件和节点包装器中核对实际落地身份与哈希
- 原子rename不是按内容条件的compare-and-swap。未来入口必须明确确认其他写入者停止，持有原工作区锁并先持久化精确意图；不合作写入者仍可能在最后核验与rename之间竞争。被检测的变化、同步失败、退出或未知材料保留两处现场，不逆向交换、不删除、不自动重试
- 备份目录选择/排他创建、固定候选的明确授权、现有应用日志/阶段与整体验证尚待接入。包装器注释中的调用前提不能冒充这些上层约束已经交付
