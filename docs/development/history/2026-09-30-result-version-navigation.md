# 2026-09-30：固定版本浏览器用例的加载竞态

## 远端失败证据

最新main`a3ae2e8`的[CI 36658556183](https://github.com/ntygod/HEXU/actions/runs/36658556183)工程检查通过，Chromium123通过/1失败；失败是“方案固定版本可查看来源、保留失败事实，旧反馈和刷新始终锚定原版本”。[浏览器job日志](https://github.com/ntygod/HEXU/actions/runs/36658556183/job/109708027161)确认构建和Chromium安装成功，属于实际浏览器断言失败，与本地socket权限阻止启动不同。

通过授权GitHub只读接口下载[工件11073368344](https://github.com/ntygod/HEXU/actions/runs/36658556183/artifacts/11073368344)，ZIP的SHA256为`99ee784c16dfb65936fa390d2f5223e5813ba29035e9ca28a6ed9d551ab71bc1`，与上传日志精确相同。离线读取trace数据，没有启动浏览器或trace服务。

## 确定的原因

trace中的实际顺序：

1. 点击v2链接后，旧反馈`toHaveCount(0)`通过；加载界面没有任何反馈也满足这个否定断言
2. `call@3515`的`allTextContents()`返回空数组，表示版本选择器尚未加载。该读取不等待选项出现
3. 测试对空数组`find(v1)`得到undefined，但TypeScript非空断言不会在运行时补值；`call@3517`记录实际传给`selectOption`的条件是`options: [{}]`
4. 选择器随后出现，空条件匹配默认首项v2，返回的值也明确是v2。之后等待v1 URL十秒自然失败

因此已证实的是测试同步/选择条件错误，不能仅据这个失败声称产品版本导航损坏。失败PNG为空白是测试finally已经执行`goto('about:blank')`后拍摄，trace仍保留失败前的页面；它也不能作为产品白屏的证据。

## 修正

- 从实际保存的v1/v2链接读取完整固定URL和revision ID，并显式核对导航
- 用受控请求屏障让v2详情保持加载态，断言加载提示存在、版本选择器尚不存在，再释放请求；没有固定sleep或放宽超时
- 等待选择器的实际值等于v2，且v2正文可见后，才检查旧反馈缺席
- 按已固定的v1 revision ID选择，不从易失标签列表计算条件；返回后同时核对URL、选择器值、旧正文和旧反馈，保留原刷新断言

未修改产品页面、权限、路由逻辑或测试重试次数。
