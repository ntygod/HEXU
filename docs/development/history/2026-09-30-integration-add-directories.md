# 2026-09-30：实际新增应用支持新父目录

在独立本地工作树中接续PR29已发布基线，扩充实际ADD-only应用到缺少父目录的路径。原目录已有文件的修改/删除仍不支持，13-05保持部分实现。

## 用户路径与实现

原Task选择新增普通文件，在本人节点再次APPLY确认后，可创建其必要的新父目录，再逐项排他写入文件。共用原应用记录、工作区锁、阶段报告、只读状态与保留结算；不新增第二套恢复系统。

- 从完整固定目标与所选新增文件规划新目录，保留目标独有文件，检查选择并集、大小写/NFC与文件/目录碰撞；最多256个新目录、目录相对路径累计64 KiB，超预算在写入前拒绝
- 先冻结原祖先，再保存所选文件意图及目录意图；复用已有私有空暂存与Linux不覆盖目录发布原语，记录暂存身份后才发布，不使用可覆盖rename或接管后来出现的目录
- 新目录保存完整身份并在后续核验中按0700模式检查；完整核验原目标树与本次目录/文件的精确并集，不将其他未跟踪内容当作产物
- 中断可能只创建目录而没有文件；此时保留原锁、目录/暂存和意图，不续写/清理。新本机状态显示已创建目录与未确认目录意图；Task文件计数明确不含目录
- 原停止确认覆盖全部integration-add/restore-publish子进程或孤儿进程；保留结算不扫描或删除当前目录，也不把应用改成成功
- 旧文件-only日志不补造目录归属；新格式的目录字段必须成对存在、严格有界且受原选定文件范围约束。缺少新格式恢复上下文失败关闭
