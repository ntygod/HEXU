## 本轮实际交付

| 能力 | 实际范围 |
| --- | --- |
| 节点接续 Operation | `POST /tasks/:id/continuations` 对 node 返回 202、Location 和持久记录；普通 `/runs` 仍是 201+Run |
| 等待/停止后继续 | 用户明确选择 wait 或 request_stop；只有原节点执行确认终态后才沿原任务/节点/目录创建新会话 |
| 固定材料 | 保存本次确认的完整发送文本、选中要求版本与执行策略；等待期间新模型输出不补入，原目录中的实际文件保留 |
| 预约与幂等 | 每任务/节点只允许一个活动安排；普通 Run 入口也检查预约。重放返回同一操作当前状态 |
| 原子派发 | 新 Run、dispatch、所选要求绑定、来源、Operation→Run 与幂等/outbox 在同一事务提交；最终检查时取消仍能阻止派发 |
| 变化处理 | 人工讨论、任务、所选要求、节点权限或策略变化时暂停并保留材料；唯一由源执行启动导致的 todo→in_progress 修订不误当人工变更 |
| 取消与恢复 | 取消不撤销原停止请求或文件修改；等待过期不释放进程占用。服务重启把待接续转为需要处理，不自动恢复付费计划 |
| 页面 | 沿原目录继续抽屉、原执行处理选项、任务接续进度卡、取消、历史材料和重新配置入口，保留浅深色/窄屏布局 |

“已创建新执行”仅表示 Run 已保存，不表示节点已接单、模型成功或任务完成。所选下一轮要求在等待期间仍可由作者修改或撤回，但会使安排需要重新配置；它们只在派发事务中绑定，在实际 spawn 后标记随新执行启动。

## 材料与权限边界

本轮采用**固定材料快照**，而非自动吸收来源后续输出。安排等待时，只有已展示的来源摘录被纳入；要带入最终输出，应在原执行结束后重新配置或再发起接续。目录内容由源执行正常改变，节点启动前仍核对本地目录身份和独占占用；不是 Git 检查点或隐藏会话迁移。

安排以本人节点授权执行，并逐次重查当前项目权限与节点所有权。项目编辑成员可取消待接续以停止后续工作，只读不能取消。退出账号不等于撤销已明确授权的安排；关闭页面也不取消。成员/节点撤权后不能继续派发。

两个模式仍仅监听回环地址。同机本人执行不是跨电脑团队服务。原生 resume/steer/即时输入、他人节点使用授权、完整 AccessGrant、WSS/HTTPS 部署、PostgreSQL、系统凭证存储、Windows、远程 diff/终端/预览、协助/接手/并行仍未完成。

**有效账户真实模型生成仍未联调。** 本轮使用虚构账号/Key、协议替身、真实 HTTP/SQLite/独立进程和临时 Git；不将这些结果称为真实提供方成功。文件工具策略不是 OS 沙箱。
