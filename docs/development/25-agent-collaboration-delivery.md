本页把新的产品目标拆成可领取的工程切片。切片序号用于描述依赖和 PR 范围，不是新的工作项 ID；一个切片可组合多个原 `HX-DEV`，同一原工作项也可跨多个切片。原 102 项的编号、标题、完成依据和剩余目标保留，状态只写 19。本页不另设领取/完成总账，不替代 22 选择当前下一项。

## 1. 首个产品里程碑

**成员甲的 Agent 在原生工作过程中找到成员乙开放的一项远端专业能力，双方完成求助、澄清和成果返回；甲的 Agent 使用结果继续原工作，过程与结果回到同一 HEXU Task。**

最小产品范围为两个真实成员、两个不同提供方或独立实现的 Agent、一个项目 Task、一项只读专业能力、有限文本/结构化输入输出；至少一端在真实远端环境。乙使用甲原本没有的、允许用于协作的项目知识或工具。人提供起始目标和预授权，不搬运中间问答，也不手动把乙的答案粘回甲。

“本地 MCP 能取件”“外部回复能保存”“两个人各问一个聊天窗口”分别是技术进展，均不单独完成这个产品里程碑。首轮不需要完整仓库迁移、源目录写入、多层转委托、通用工作流、所有厂商连接器或桌面安装包。

框架入口和人的工作台共用领域服务。Agent 身份、端点、能力和执行配置分开；最小协作支持接受、拒绝、澄清、限定范围调整和返回结果。三项能力事实分别保存：提供方支持程度、HEXU 接入程度、当前授权/环境可用性。

## 3. 切片 1：身份、能力和预授权入口

**交付：** Agent 参与身份关联真实所有者；一个身份可关联端点与能力，凭证轮换不变成另一个协作者。工具偏好仍属于 AgentProfile。登记可从本人资源设置或受认证命令完成；不需要创建虚构成员。

- 能力目录先做项目范围内的确定性筛选与固定能力，不做语义推荐、全员广播或公开市场。
- 区分可发现、可请求、可读材料、可执行与可产生外部影响；首轮仅授予一项文本专业协助。接收者可预先允许指定项目/参与者自动接受，记录费用主体、有效期和并发范围。
- 能力同时显示提供方支持、适配完成度、当前授权/环境条件；待验证能力不可呈现为真实可调用。
- 凭证使用独立连接身份，不沿用浏览器 Cookie、节点令牌或管理员 Token；来源主体来自认证上下文，正文不能自称某成员。撤权、端点更新和旧回执均按当前权限处理。

**实现入口：** `packages/contracts`、`packages/domain`、`packages/db`、`packages/identity`、`apps/control`；资源入口沿用 `apps/web` 与共享 client。新文件按领域命名，最终名字由 18 和源码统一，不先建空包或新服务。

**必要检查：** 一个所有者多 Agent、两个所有者分别授权、不可发现对象不泄露、端点身份伪造、撤权后旧键重放、能力不可用的动作反馈。给后续切片交付固定 DTO、授权查询与测试夹具。

**前置探测同时完成：** 选定首轮甲/乙的实际原生入口、版本、输入/输出/等待方式、平台和费用主体，记录哪些需实际账户验证。默认甲走 HEXU MCP 工具入口，乙优先选择具备稳定接收/查询接口的开发者或自建 Agent；若实际端点使用 A2A，则以薄适配映射。无需先实现所有协议；不绑定 dots/Muse 个人实例能被反向唤醒的假设。

## 4. 切片 2：请求、固定材料与双向协商

**交付：** 甲或有权成员发起有限 Assistance；乙可接受、拒绝、请求澄清或提出不扩大权限的范围调整；甲在授权内补充并继续。单次问题不另建 Task。

- 先支持已有消息摘录及获授权项目文本资料的固定版本；每轮补充新建输入修订，保留对方已经使用的版本。只发必要内容，不导出原生完整会话。
- 协作信封关联 Assistance 和双方参与身份，保存请求 ID、原因关联、输入/授权版本、送达观测及远端映射。Assistance 管理协助业务状态；Run 管理真实执行。不能再造一套与二者竞争的可写完成状态。
- 接受、拒绝、澄清、回答是有类型的回应。拒绝和等待材料不记为 provider 故障；未知投递不记为已接受。
- 接收者只获得该请求的材料和回复范围；无父任务访问权时隐藏父 Task/Project 标识与标题。乙能在自身获准资源中工作，但输出向甲披露还需满足资源的共享范围。
- 创建请求、回应、修订、有限授权、回执及 outbox 原子保存；同键异包拒绝，未知结果查询原请求。材料过期或授权变化时停止进一步发送并保留可恢复记录。

**实现入口：** [协助契约](../../packages/contracts/src/assistance.ts)、[协助存储](../../packages/db/src/assistance.ts)、[选材](../../packages/db/src/project-materials.ts)、[HTTP](../../apps/control/src/assistance.ts)。浏览器提供最小发起/回应及范围查看入口。

**必要检查：** 当前权限先于回执、相同请求/回应去重、澄清与补充的修订竞态、有限接收者不读父任务、输入变化不回写旧成果、撤销后不能继续取件/回复。沿用现有真人与 Claude 协助回归。

<a id="slice-3"></a>

## 5. 切片 3：Agent 原生入口与接收适配

**交付：** 甲在原生工作过程中调用 HEXU 工具查找目标并请求协助；乙在所有者开放的接收入口取件/被派发并返回回应。两个入口复用相同领域服务。

- 最小逻辑工具面为发现能力、读取获准材料、提出请求、回应/澄清、查询本人相关请求、取消。名称及 schema 统一维护在 18；受管执行启动不隐藏在读取工具内。
- 本地先用 stdio MCP 桥到回环服务；远程由切片 5 提供独立认证传输。MCP 桥只映射领域动作，不包含另一套身份、任务或状态存储。
- 乙侧明确实际接收机制：可调用端点，或所有者配置的受控取件进程。只有存在实际运行主体才能写“自动取件”；用户手动回到原平台取件作为兼容方式，不作为首个自主协作里程碑的最终路线。
- 自动接受仅使用已有预授权。实际运行在乙自己的受控环境，提供方凭证不交给甲或控制服务；仅返回允许共享的答案与来源。
- 远端 request/job/session 标识与本地请求持久关联。受管启动才有真实 Run；外部执行用外部引用和观测，不伪造进程或成功 Run。
- 原有 Claude 纯文本 assist 的禁工具/禁 Hooks/MCP 边界保持。新协作入口独立授权与实现，不能放宽旧模式来临时跑通演示。

**实现入口：** `packages/client` 或独立薄桥、`apps/control` 协作入口、`packages/adapters` 的实际端点映射；需运行原生工具时使用独立接收进程/受管 Runner 的既有进程与日志边界。先核对 [提供方 harness](../harness/providers.md)，不推断 Windows 原生执行已支持。

**必要检查：** schema 与权限错配、客户端/服务版本不匹配、接单 ACK 丢失不重复创建模型工作、重启只核对未知结果、错误/拒绝分类。协议替身与真实模型往返分别记录。

## 6. 切片 4：结果回接与原工作继续

**交付：** 乙返回文本或结构化结果，甲的 Agent 自动取得并用于原关联工作，用户不转述回答。记录哪条回应/成果版本成为哪次后续工作的输入。

- 甲可在当前原生执行中有界等待/查询；需要跨回合时使用提供方实际支持的继续方式。不得假装已经实现所有工具的 steer、后台唤醒或原生恢复。
- 首轮使用一种明确的回接方式，等待时限和查询频率有界。甲离线时保存结果并显示待恢复；恢复核对原关联，不自动重放未知付费启动。
- 短回答可直接是已保存 Assistance 回应；需要独立版本/反馈的输出关联 ResultRevision。两种输入均保留来源、输入版本与实际消费关联，不以模型一句“已采用”直接修改共享约定。
- Agent 在授权内使用回答继续，与人明确采用到 Task 说明是不同动作；继续能力不应依赖先点“采用”。保留现有人工采用界面，并增加可信外部来源分支，不能伪装满足成功 assist Run 条件。
- 回应不自动完成 Task、改负责人或写本地主目录。取消请求、取消未来回接、请求停止已启动执行分别记录；无法确认的外部执行保持未知。

**实现入口：** [协助采用](../../packages/db/src/assistance-adoption.ts)、[成果版本](../../packages/db/src/result-revisions.ts)、已有接续/Operation 与所选原生适配。补充消费引用，不建立第二套成果表。

**必要检查：** 回应恰好关联正确请求/版本、重复送达不重复继续、撤权/输入变更发生于继续前、原 Agent 使用结果的可观察后续输出、取消/离线/超时。首次完成只需无代码写入的专业回答消费，不扩展到源目录整合。

## 7. 切片 5：最小远端通信与恢复

**交付：** 两个成员在不同设备/环境上使用同一受认证协作服务，完成有限协助的真实往返。该能力只覆盖已交付接口，不宣称整个团队部署或远程节点包完成。

- 独立的远程部署配置使用 HTTPS、明确来源/代理信任、真实身份、受限 Agent 凭证与持久数据；preview/team-local 继续保持回环限制。不能只移除回环检查或用临时隧道发布现有版本。
- 根据切片 3 选定的入口实现远程 API/端点认证；若提供远程 MCP，则实现实际客户端所需的授权与资源校验。第一条路径不要求同时支持 MCP HTTP、A2A 和全部 WSS 节点协议。
- 个人设备主动外连或取件，不暴露任意原生控制端口。服务只掌握本次协作状态和被选材料，不接收模型密钥、整个 HOME 或私人会话。
- 请求/回应持久化、来源验证、重复/乱序处理、重启核对、撤销与到期一起交付。只读查询可以重试，结果未知的付费创建不可重发。
- 提供最小配置说明、备份/恢复演练和有界诊断；不为首轮预先建设 Kubernetes、多实例调度或自动升级平台。

**实现入口：** 控制服务配置/身份、现有 db/outbox 与新的协作端点、部署与检查脚本。修改任何当前网络边界时同步 ADR 和相关 harness；正式存储选择按现有工程条件确定，不能重建用户数据。

**必要检查：** 实际两端通信、无授权访问拒绝、撤销后的长连接/查询、回调来源与重放、共享服务重启、数据恢复和旧请求核对。记录实测系统、配置和支持范围，不把 SSH 可登录算作完成。

## 8. 切片 6：任务内体验与需要人处理的事项

**交付：** 原 Task 显示协作目的、实际双方、阶段、等待原因、有限材料和返回成果；重要问题能由有权成员就地回复。

- 每个前序切片提供对应最小界面，本片收口跨入口状态、刷新、深链接与恢复；继续复用 W1。
- 消息往返折叠在请求内；主时间线只投影请求、需人决定、成果与继续。不得把技术调用次数显示为交付进度。
- 显示“已送达”“已接受”“待澄清”“远端已有成果/本地待继续”“停止未确认”等实际含义，保留状态来源和最后确认时间。
- 能力目录位于资源设置或协作选择器；不要求用户维护 Agent 组织图。范围内自动协商不逐条弹确认，超出授权或业务分歧才请求人处理。
- 通知先覆盖这条协作链的持久待处理与去重，不等待整个工作台、检索和费用模块完成。

**实现入口：** `apps/web` 协助/工作区/工作台/成果、`packages/client`、`packages/ui`；复用现有资源与抽屉，tokens 仍为唯一来源。

**必要检查：** 原生入口与 Web 看到同一记录、两种身份的有限可见范围、刷新/断线保留输入、旧身份迟到响应不污染、键盘与受影响屏宽。只扩展当前旅程的浏览器检查。

## 9. 切片 7：真实闭环与交付记录

使用明确授权的测试账户和可丢弃项目，在两端运行两个独立 Agent。甲执行一个需要接口解释的小任务；乙只开放允许共享的项目接口知识，先提出一个必要澄清，再返回回答；甲使用结果生成后续实现说明或其他可检查产物。全程无人工搬运中间材料。

记录最小事实：双方真实身份与实现、实际通信路径/版本、请求与澄清关联、使用的材料版本、返回结果、甲继续的可观察行为，以及已知费用/未知费用。不提交真实凭证、私人会话或真实数据截图。

异常验证只覆盖本链：拒绝、离线等待、撤权、响应丢失后核对、重复回应。基础工具在本机跑通、跨设备跑通、真实模型跑通与正式部署支持分别陈述，不因其中一项成功提高其他项状态。

结果写入实现历史，19 只回写实际涉及条目的证据/剩余，21 更新真实可用范围，22 指向后续切片。完成本里程碑不等于完成所有 03/11/16/17 原工作项，也不为用户增加质量报告门槛。
