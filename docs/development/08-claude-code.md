# 08｜Claude Code 适配器开发

> D1 · M1—M2 · 关联 HX-F04/F05/F11 · 依赖：06、07 的契约与宿主能力。  
> [计划入口](README.md) · [公共协议](18-data-api-catalog.md) · [官方依据 S01—S04](20-technical-decisions-sources.md)

## 1. 目标与接入选择

实现一个 ClaudeAdapter，为 HEXU 提供发现、开始、结构化输出、继续、补充输入、必要授权、停止与可获得的用量。界面显示 Claude Code，不把它简化成只调用聊天模型。

建议以官方 TypeScript Agent SDK 作为需要完整交互的实现路径；本机 CLI 程序化调用作为能力受限的兼容路径，不强制同时维护两套完整引擎。实际采用哪个路径由 08-01 根据公司允许的账号方式和已安装工具决定，并写入兼容记录。不会把 CLI 登录自动兑换成任意第三方 SDK 共享额度。

官方 SDK 提供与 Claude Code 相关的 Agent 循环、工具和上下文能力；程序化 CLI 提供结构化输出。它们是集成依据，不是 HEXU 已完成接入的证据。详情与授权边界见 20 的原始文档。

## 2. 包与公共输出

`packages/adapters/claude-code` 只实现原生映射，通过执行器的 ProcessHost、CredentialRef 和 WorkspaceHost 使用环境，不直接操作中央业务数据库。

`discover()` 返回工具/SDK 版本、支持路径、可用模型配置来源、原生恢复、运行中输入、授权响应、停止、附件与只读执行等 capability。每项区分 supported/partial/unsupported/unverified，并给出限制原因。未提供完整模型目录时使用明确配置/原生默认值，不伪造“全部可选模型”。

共用 AdapterEvent 输出：会话关联、消息、工具动作摘要、输入请求、授权请求、用量和结束结果。原生 system/assistant/result 等事件名称以锁定 SDK 为准；新增类型原样保存受控引用，不直接崩溃或吞掉授权事件。

## 3. 开始与恢复

开始前校验 Run 归属、cwd、工作区写入权、有效上下文、账号引用和允许的工具配置。默认不无声继承未知仓库 Hooks、MCP 和个人插件；需要继承时记录来源与用户授权范围。

SDK 调用保持异步流，保存原生 session ID 及 node/account/config 范围。相同工具且会话仍有效时按原生恢复能力继续；跨工具输入只能是 ContextBundle 与当前代码现场。每次开始新的 HEXU Run，不能让模型配置改动覆盖旧记录。

恢复被拒、会话不存在或目录不一致时，将可恢复材料交给用户选择新会话，不在后台假装原生恢复成功。错误中可展示诊断摘要，不回显密钥和完整本地私有路径。

## 4. 用户输入、权限与停止

锁定版本支持流式输入时将追加消息送入现有执行，返回原生确认后的 delivered；仅支持下一次输入时进入 queued_for_next_turn。澄清问题在任务内显示，不与权限请求混为一谈。

权限通过实际原生规则、Hooks/回调和宿主隔离共同约束。官方文档说明自动允许路径可能跳过部分回调，因此不能只注册 canUseTool 就宣称控制了全部操作。不得以 bypassPermissions 作为默认便利配置，也不能把仅提示“请不要写文件”当作真实只读边界。

将原生请求 ID 和 process generation 映射到 ActionAuthorization。用户拒绝、请求过期或 Run 结束时，对应原生操作不得继续。有限预授权策略来自项目/节点配置，不从聊天文本推断。

停止优先使用锁定 SDK/CLI 的中断能力，等待结束事件；必要时由 ProcessHost 处理受管进程树。协议结果错误、退出异常与主动取消要区分，退出码零不触发 Task.done。

## 5. 用量与结果

记录 input/output/cache 等实际可取字段、原生报告范围、原生会话、费用币种与来源。CLI 或 SDK 返回累计值时，以同一身份与会话的水位计算增量；重置或无法确定基线时显示未确定，不能简单重复相加或把负值截零掩盖变化。

结果包括文本与变更引用，不自动提交代码、推送或标记团队任务完成。由 10/14 展示给用户。

## 7. 完整支持的展示方式

资源页写实际支持的版本与能力，不用一句“已接入 Claude”覆盖所有组合。没有真实授权账号时先使用 01 的假适配器，记录未接通；不得在此文档或 UI 里虚构测试通过。

开发只需为实际支持范围实现必要回归，具体内部评估由团队安排。这个适配器不新增独立产品审批流程。
