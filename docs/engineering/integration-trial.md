# 在独立目录试应用选中文件

本机命令可将完整固定目标副本与明确选中的来源新增、修改、删除组合成一个**新的私有目录**。这是可检查的候选文件材料，不会覆盖原目标，不把 IntegrationOperation 记成 completed，也不会启动代码、脚本或模型。

## 前提与命令

先完成[固定成果整合预检](integration-preflight.md)。只接受完整、未省略计划里的无冲突 `add` / `modify` / `delete`；未选择的变化和冲突保留目标一侧。已选择实际应用的操作不能再创建新试应用。

```sh
npm run build:server
npm run runner:integration-trial -- \
  --operation <整合ID> \
  --state <原节点状态目录> \
  --target /absolute/path/to/new-private-trial \
  --files '["src/new.ts","src/existing.ts","obsolete.txt"]'
```

输出路径必须规范、绝对且不存在，其父目录安全可写，并处在所有已登记代码目录及节点私有状态之外。Linux 本人节点和普通 Git 原目录是当前支持范围；不初始化新 Git 仓库、不修改原 HEAD/index，也不登记新 WorkingCopy。

命令展示固定成果版本、共同起点、源提交、原目标提交/恢复副本、原代码目录、新私有目录和所选路径。输入 `TRIAL <整合ID>` 才同意创建并排他发布这份独立材料；这一次确认不允许随后写回原目标或分享材料。

## 材料与核验

- 从完整保留对象或已确认接收副本生成候选，不从截断 diff、显示文本或正在运行的来源目录拼补丁
- 重新验证共同起点、源/目标全部对象、图覆盖率、快照指纹与原计划；原目标必须保持与固定提交完全一致，不能有未跟踪/忽略文件或已知/未知写入者
- 保留所有未选择的目标文件；选中删除只从候选中省去文件，选中修改替换候选字节，新增所需父目录只在候选内创建。二进制和普通文件可执行位受完整对象核验
- 候选组合后仍拒绝符号链接、子模块、LFS、歧义路径、大小写/NFC碰撞和文件/目录冲突
- 发布前重新核对当前本人/Task/节点权限、来源与恢复副本期限、原目标、完整持久对象和暂存目录字节。当前状态变化导致保留暂存、拒绝发布，而不是自动重算或采用新版本

选择最多80个文件、48 KiB路径JSON；完整候选展开最多50,000项（含根目录）、64 MiB，单文件最多8 MiB、深度64、路径4095字节，清单也有独立64 MiB上限。同一个blob出现在多个路径时逐路径累计展开大小。每个节点最多保留1000条本机试应用记录。

目录和可执行文件仅本人可访问（0700），普通文件0600。候选文件内容及清单只保存在本机，不上传绝对路径、文件名、正文或新的共享观察；现有Task/Run/Result和整合报告保持不变。

## 状态、重复和中断

先保存固定绑定/清单和写入意图，再在输出父目录创建独立暂存；逐项保存真实所有权、字节和数量。发布使用固定父目录描述符及Linux不覆盖重命名，不能退化为普通rename/copy覆盖。

结果JSON中的 `ready` / `materialState: published` 只说明这次独立材料曾核验并发布；`trialOnly: true`、`applied: false`、`writeAuthorized: false` 始终保留。它不是当前输出持续可用、原目标已应用或代码质量通过的证明。

再次运行同一输出路径/身份/操作/选择时，先核对当前访问权限，然后只返回历史证据，不读取候选、重新捕获材料、重写或自动发布。旧非终态只记 `interrupted` / `unknown`。不同选择不能接管旧路径记录，即使目录已由操作者移走。检查新的候选需要另一个明确的新输出路径。

取消、进程退出、对象损坏、父目录变化或发布/持久回执不确定均保留证据和现场。暂存可能是输出父目录内的 `.hexu-restore-<本机试应用ID>`；命令不会自动删除、回滚、搜索或接管它。发布成功但最终日志未知时，也不能根据目标存在猜测成功。

试应用命令和断开/重新配对共用本机进程守卫。尚有暂存、写入或未知证据时，断开/重新配对拒绝删除原凭证；已核验发布的历史及明确没有材料的失败历史允许继续。目前没有试应用暂存的清理或保留结算命令，不能把旧整合应用的恢复命令用于这份独立材料。
