# 本机检查点恢复到全新目录

HX-DEV-12-02 的 Linux 本机普通文件切片。在已有[只读预检](checkpoint-restore-plan.md)基础上，增加**明确暂存写入、重新核验、排他发布、持久进度与明确清理**。这不是 Handoff 接受、跨电脑传输、完整 Git 克隆或模型执行许可。

## 构建与使用

使用 Node 24 + npm。Linux 源码构建还需要本地 `cc` 和 libc 开发头文件；`build:server` 编译仓库内的窄接口发布助手。缺少编译器会明确失败，不自动安装或下载工具。助手不要求 root、不接受命令正文、不会运行源仓库脚本。

```sh
npm ci
npm run build:server
npm run runner:restore -- \
  --request <保留请求ID> \
  --state /path/to/private-state \
  --target /existing/parent/new-directory
```

`--request` 为已成功保留并确认发布的对象副本请求 ID；`--state` 必须是原节点配对状态。目标必须是规范绝对路径，最后一级不存在，全部父目录不经过符号链接。直接父目录必须属于当前 OS 用户、不能被组或其他用户写入；当前只接受 Linux 上 ext 系列、XFS、Btrfs、tmpfs、overlayfs 的语义。macOS、Windows、NFS/FUSE/网络文件系统等明确不支持。

终端显示完整来源提交、期限、目标、范围及已提交敏感内容警告。输入 `RESTORE <保留请求ID>` 后重新核验权限、原凭证/目录绑定及实际对象，才创建本次专属的 `.hexu-restore-<恢复记录ID>` 暂存目录。它位于目标的同一个父目录，权限 0700，不是原工作区或节点状态目录的别名。

按计划写入并同步普通文件，目录 0700，普通文件 0600，可执行 blob 0700（保留执行位但不会执行）。二进制字节不转换，不运行 checkout、hooks/filter、依赖安装、仓库脚本或模型；没有 `.git`、分支、remote、原索引或祖先历史。原 HEAD/index/脏文件/Task/Run/Operation/目录锁保持不变。

暂存核验后，显示真实完成数量、字节及计划指纹，再要求输入 `PUBLISH <恢复记录ID>`。等待确认时不持有保留库读事务。确认后重新读取并核验持久对象、原计划、当前权限/绑定/期限、父目录身份和暂存实际字节，不能直接信任先前计划或已写好的副本。

## 不覆盖发布

父目录从 `/` 开始逐级以不跟随符号链接的目录描述符固定；子目录相对已固定的描述符打开，并核对本次创建的 inode 身份。大 inode 使用精确整数，不经 JavaScript 浮点截断。移动后的源目录也通过原授权身份排除，不能把新路径当作无关目标。

发布助手只做 `renameat2(..., RENAME_NOREPLACE)` 和父目录同步：已经存在的空目录、文件、悬空链接同样拒绝。**不使用“先检查不存在再普通 rename”的替代方案**，也没有 copy/覆盖回退。内核或文件系统不支持时保留暂存并失败。原语语义见 [Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)，文件打开边界见 [Node 24 fs](https://nodejs.org/docs/latest-v24.x/api/fs.html)。

只有原语确认、目录同步、目标身份核对及本机成功记录保存完成，才记录 `restored`。发布后同步失败、回复不明确或成功日志写入失败，保留 `interrupted / unknown`，不能凭目标存在推断成功，也不自动删除目标。

## 状态、重复命令与中断

本机日志在 `<state>/checkpoint-restores/journal.sqlite`，目录 0700、数据库 0600，独立进程锁、SQLite FULL 同步。固定计划保存一次；实际创建的文件/目录身份与文件修改观察逐项记录，完成数量只在对应步骤完成后推进。日志是本机恢复证据，不是新的任务/模型会话系统，也没有伪造服务端 Operation。

```sh
npm run runner:restore-status -- --state /path/to/private-state --target /existing/parent/new-directory
```

输出 `lastRecorded` 和 `currentFilesVerified:false`。它是最后记录，不是持续磁盘可用性或当前进程存活保证。状态、材料位置和清理结果分别记录：`verified` 只表示暂存当时核验通过；`published`/`restored` 与未发布、失败、取消、未知不得混用。

同一目标已有记录时，重复 restore 只返回原记录，不重新写文件、不生成另一暂存、不自动发布或重试。新的管理进程取得独占锁后，把旧的非终态记为中断/未知，不恢复执行，不向旧 PID 发信号。成功恢复后用户的修改不会被重复命令覆盖。失败后自动重试/原位续写尚未提供；需先核对现场，新的明确恢复使用另一个全新目标。

每次写入沿用原对象/名字/50,000 条目/深度等上限，展开文件总量另限 64 MiB，写入阶段最多 120 秒，最多 1,000 条本机恢复记录。记录满时拒绝新增，不自动删除历史或用户目录。没有磁盘预留承诺；ENOSPC、进程中断、日志失败均保留真实已知进度及未确认范围。

## 取消与明确清理

拒绝首次确认不写恢复目录；发布前拒绝确认、处理到 SIGINT/SIGTERM 或发生普通故障时，保留已创建暂存而不发布。发布原语已开始后不能承诺信号会撤销发布；无法确认时按未知结果保留，不自动删除目标。SIGKILL 可能留下尚未完整记录的对象；恢复日志不能替代实际文件状态。

```sh
npm run runner:restore-cleanup -- --state /path/to/private-state --target /existing/parent/new-directory
```

输入 `CLEAN <恢复记录ID>` 后，仅清理该记录的原暂存目录。先核对完整文件清单、目录身份、普通文件身份/大小/修改观察/链接数；用户新增、编辑、替换、符号链接、归属记录缺失或父目录换位时拒绝，不先删掉其他好文件。删除逐项进行并保存进度，不使用递归 `rm`，**永不删除已发布目标、原仓库或其他恢复目录**。

清理中途失败保存 `needs_attention`；已缺失而回执未保存的材料、创建后还未来得及记身份的目录、发布未知且原暂存已消失等情况，可能需要本机人工维护。本切片不会猜测认领或遍历搜索新的位置。恢复库/对象库保留期限或控制服务撤权不授权再次读取/恢复材料，但原本机身份仍可读取自己的日志和明确处置已创建的暂存；新凭证不能管理旧记录。

## 范围与限制

仅普通 UTF-8 文件/目录、二进制、Git 可执行位；整份拒绝符号链接、LFS 指针、子模块和歧义文件名，不静默跳过后宣称完整。已经提交的 `.env` 等敏感内容可能被复制；这是提交快照恢复，不是秘密扫描或加密备份。

路径、文件名、实际内容及本机日志不上传控制服务。没有新增浏览器任意路径 RPC、恢复结果卡、跨电脑传输、正式 Handoff 生命周期或模型启动。原节点当前权限在关键阶段重新检查，但跨进程 HTTP 授权与本机磁盘提交不是分布式原子事务；本机权限/描述符防护也不是防同一 OS 用户持续恶意竞态、特权挂载或恶意内核的沙箱。
