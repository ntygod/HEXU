# 固定成果的代码整合预检

当前在同一项目/Task、同服务回环、Linux本人节点上，明确选择一个固定成果版本和目标提交，记录完整对象的文件级三方预检。代码**尚未应用**；预检不会创建Run、改变方案选择或完成Task。它也不授权将来的写入。

## 使用路径

1. 为方案结束后的代码提交记录检查点，保存带代码引用的固定成果版本。为该提交明确保留对象。成果本身不必已被方案组选中；这里的来源是用户打开的ResultRevision，之后的选择和新成果不会替换它。
2. 在本人目标节点，为目标提交记录检查点并保留对象，作为明确的恢复起点。目标HEAD、索引和所有普通文件必须匹配该提交；未跟踪、忽略内容、脏文件或未知/活动写入会阻止预检。当前仅支持注册时直接使用`.git`目录的普通Git仓库，linked worktree不在本轮范围。
3. 来源副本若不在目标节点，先按[受控传输](checkpoint-transfer.md)完成接收。预检读取接收者独立副本，不借来源节点凭证或从共享差异补齐代码。接收完成后，原保留副本删除不等于接收副本失效；双方当前权限与原清单期限仍需有效。
4. 在成果版本页或方案比较列点“准备代码整合”，明确目标提交/恢复副本和来源完整对象，确认创建只读预检。可用目标限制最近50个本人检查点、最多50个有效恢复选项；缺材料时先在检查点入口准备，不自动保留/传输。
5. 构建服务端后，在目标节点运行：

```sh
npm run build:server
npm run runner:integration-plan -- --operation <预检ID> --state <节点状态目录>
```

节点显示共同起点、来源、目标与实际本机目录。输入`PREFLIGHT <预检ID>`后读取完整对象并检查目标。预检清单只在本机显示；输入`SHARE_PREFLIGHT <预检ID>`才共享列出的文件名、对象标识、大小/模式和结论。不上传文件正文、绝对路径、密钥或账号。

共同起点的完整对象必须仍在目标授权仓库中，来自方案原起点的固定commit/tree，不读取浮动引用。来源与目标使用明确的独立对象副本；每次遍历重验Git哈希、覆盖率与快照指纹。目标恢复副本不能用旧恢复报告替代。

## 计划与状态

文件级比较采用共同起点、来源提交、目标提交三份完整快照：来源未改的文件不进入变更列表；目标和来源相同标为“目标已有”；仅来源修改可列为新增/修改/删除；双方修改同一文件一律列冲突，不自动合并文本或调用外部merge/diff驱动。组合后的完整文件树另查文件/目录、大小写与Unicode路径碰撞，保留目标独有文件。

二进制普通文件可比较标识/模式；符号链接、LFS实体、子模块、歧义路径及空子树阻止整次计划。原对象限额沿用保留/恢复：64 MiB、10000对象、50000条目及单blob8 MiB；已传输副本仍受16 MiB/2048对象限制。共享最多80个文件、48 KiB，省略数量和全部冲突数量保留，有省略不能视为完整可应用计划。

| 状态 | 含义 |
| --- | --- |
| `queued` | 浏览器已固定来源和目标，等待本人节点预检；不是执行排队 |
| `awaiting_choice` | 预检已记录，尚未应用，也没有写入许可 |
| `conflict` | 有文件冲突或共享清单省略；没有写入目标 |
| `failed` | 本人明确共享的目标变化/缺对象/不支持/预算等失败原因；原现场保留 |
| `cancelled` | 发起者取消这次预检；已有报告与历史仍保留 |

任务内“整合预检”可以重读固定版本、恢复点、清单、操作历史并取消。记录中的观察时间是当时证据，**不证明现在目录未变化**；当前副本/权限不可用会另外标明。Task编辑权限和本人节点权限分别核对；只读成员可看Task内已共享历史，不能发起或取消他人的预检。

## 回执与限制

创建/取消使用固定请求体、预期修订和幂等键。节点共享前将固定包写入私有持久日志；回复丢失只重发原包，不重新读取代码或替换报告。若服务端确认这条操作已取消且报告从未保存，本机对账结束该待发包，不能改投另一操作。已保存的报告不可覆盖，取消也不擦除它。若身份已被撤销，不能借旧回执读取/发布；无法确认的原包保持在原私有日志。

还未实现实际应用、选择文件/提交、冲突解决、文本自动合并、写入失败恢复与多来源编排。将来应用必须另行授权、重新核验材料/目标、持有持久写锁并保留恢复点；不能把本页预检、48 KiB清单或成果24 KiB显示差异当成可应用补丁。
