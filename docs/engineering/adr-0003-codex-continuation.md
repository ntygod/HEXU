# ADR-0003｜Codex 本机接入与显式接续

状态：E1b 已采用的实现取舍。日期：2026-09-25。沿用产品 v1.1 的轻量流程。

## 决定

使用 Codex App Server 的 stdio 双向协议，不使用屏幕抓取或混入 mock。每个执行拥有独立进程、原生 thread/turn 和临时配置目录；只接 API-key 内存认证。目录、模型和输入作为配置快照保留，绝不持久化凭证。

继续仍是原 Task 的新 Run。新增 sourceRunId、Git 基线/路径、上下文来源；沿用已授权目录和未提交文件，不先制造 Git 提交。停止未确认、来源过期或工作区不同则拒绝。重复请求返回原 Run，不重复调用提供方。

当前同步准备后返回 201 + Run，与最终计划中的持久化 Operation 不完全相同。先停止再点击开始，不宣称能在关闭页面后自动等待并接续。该差异见计划 11 与公共 API 总表的当前实现说明。

## 为何限定范围

本次不同时切换身份系统、数据库和节点架构，以便保留已能运行的本地体验。继续使用回环地址、单用户与 SQLite。未恢复强制验收门槛。

Codex 的沙箱策略与 Claude 文件工具规则不同，不能将 UI 的相同名称宣称为完全相同的安全能力。不开 Shell/MCP/插件，用户须提供非敏感独立目录。Codex 本轮没有美元预算实现，不复用 Claude 的预算显示。超时仍可能产生已发送请求的费用。

## 兼容性与事实

官方 Codex 0.157.0 Linux 发行包来源为 `codex-package-x86_64-unknown-linux-musl.tar.gz`，SHA256 `042f851ea3fc1083c45157520520944fc790632b53ebc580fc98eaca55862a25`，与官方 release 元数据核对。

实际无模型检查发现并修正：Hooks 为空数组映射；目录 key 应通过完整 TOML map 配置；thread/start 使用 kebab-case sandbox，而 turn/start 使用 camelCase 策略。常规用例加入对应约束。源码包未包含官方二进制。

没有使用有效提供方密钥、没有执行真实模型生成。无模型协议检查、fixture 流程和真实模型互操作是不同层级，不能混称。

## 后续

保持已验证的基本交互，逐步补原生 resume、运行中输入、受范围约束的协助与独立节点；多人认证/PostgreSQL 仍是正式团队服务的前提。未实现的能力继续在 UI 和实现进度中说明。
