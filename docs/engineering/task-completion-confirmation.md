# 完成与取消任务的当前权限和确认会话

有活动Run时，“标记完成”仍使用原确认弹窗，默认同时请求停止，也可取消勾选只改变Task完成状态。请求停止不等于执行已经停止；实际Run状态继续单独显示。

Task详情辅助区的“取消任务…”始终打开一次明确确认，用“返回”和“确认取消任务”区分关闭与业务动作。当前可编辑的todo、in_progress、done均可取消；已取消时不显示该入口，只读成员禁用。讨论、成果和已有版本保留，之后可用原“重新打开”。归档项目仍允许这项人工状态操作。取消看板继续只读，成果页不新增取消入口。

取消确认从当前Workbench的同Task全部活动Run判断，包含普通、方案和AI协助，以及stopping/unknown。已有活动时默认请求停止，可明确改为不请求停止；实际执行仍各自运行、停止中或等待终止证据，不因Task取消而伪报结束。打开时没有活动执行则固定keep并说明只改Task状态；提交前观察到新活动就使本次确认失效，须重新打开。未观察到的后来执行也不会被这个原keep请求停止。

每次打开确认固定当时Task与修订、停止选择和提交状态。当前Workbench移除Task或不再允许编辑时，弹窗与旧标题立即清除；重新获得权限只恢复入口，必须明确重新打开确认，不复活旧选择。当前确认请求明确返回未登录、禁止或对象不可访问时也清除；仍由原服务器权限检查决定能否执行。

尚未发送时，当前Task修订变化会显示提示并禁用确认，要求关闭后重新确认，不静默用新版修订完成可能已经改变的任务。已发送命令的请求正文保持原修订与选择，其自身SSE更新不冒充另一次确认；真正回执与当前页面投影仍有区别。

关闭、权限变化或新确认使旧UI会话失效。旧任务级成功、拒绝和finally只能影响所属确认，连同该确认触发的Workbench刷新都不能关闭新弹窗、改掉新选择或忙碌状态；完成与取消两类动作之间也按同样的会话隔离。客户端既有全局身份失效处理保持：401或SPACE_ACCESS_REVOKED仍会退出对应身份/空间，不承诺在局部弹窗中拦截它们。关闭弹窗不撤销已经发送到服务端的操作。忙碌时不重复发送。

完成/取消确认首次发送前，固定原Task、动作、修订、停止选择和幂等键。网络失败、5xx或无法核对的成功回执属于未知结果，停止选择保持锁定；“确认原请求结果”只重试同一个请求。Task后来已更新或活动执行变化不会把待确认包改成新请求，仍由服务端当前权限与原回执决定结果。尚未发送的确认继续受原修订和后来活动检查保护；明确冲突后需重新查看并确认，不自动重设基线。

“暂时关闭”只收起已提交请求的界面。在当前账号/空间的页面内再次操作同Task状态（包括重新打开、开始或标记完成）会先恢复原待确认包，确认结束后才能另做新动作。当前Workbench移除Task或撤销编辑权时，包括已收起的原包都清除；重授不复活，身份/空间切换和页面硬刷新也不保留此内存恢复。清除本地记录不等于撤销服务端已接受操作。

成功回执须符合原Task、目标状态和原修订加一，确认的是原操作结果，当前Task可能已有后来变化。之后Workbench读取失败仍显示原请求已确认，提供“刷新任务状态”且只发GET；不会重新发送业务请求。原stop请求在第一次实际提交时处理当时活动执行，不冻结Run ID，也不表示进程已经终止。

本切片不新增API、后端回执模型、原因输入或Run状态。原无弹窗的新鲜状态操作仍沿既有流程，本次只保证它们不能绕过同Task尚待处理的确认请求。
