# AI 草稿与局部采用

`HX-DEV-05-04` 的本机切片。草稿来自当前 Task 中已有的 AI 回复，不发起新模型调用，也不读取原生会话文件。模拟、原生和节点回复保留原来源文字，不能据此宣称经过真实模型验证。

## 使用

在 AI 回复下点“整理为草稿”，编辑标题和正文并保存。任务头部的“AI 草稿”可重新打开已保存内容及修订。草稿最长 12000 字符；过长原回复明确显示预填截断，原文仍在讨论。它没有项目约定的权威性，保存和编辑不会改变任务说明或既有执行。

保存修订后点“选择片段采用”。可选 1–16 个不重叠片段，或明确选择全文；片段按原顺序排列，中间以空行连接。预览同时显示目标现有内容和采用后正文，选择追加或替换，再点“采用所选片段”。只有当前任务说明或同项目资料正文可作为目标；资料标题、链接和归属不变。私有草稿只可采用到同一私有任务。

草稿和目标各自有固定编辑基线。另一人修改时，保留本地编辑/片段并显示当前版本，明确核对后才能采用新基线。暂时读取失败保留本地输入；撤销编辑权限、身份/空间变化或关闭会丢弃未保存编辑。HTTP 回执不确定时只能确认相同原请求，关闭不等于撤销已发送的操作。

采用记录保存草稿修订/指纹、选取范围、实际片段、操作者和目标修改前后正文/修订；未采用文字留在草稿。后续修改草稿不会反向改变已采用内容。普通采用不自动完成任务、修改负责人、发布约定、请求停止或派发付费工作。

## 权限、事务与执行

迁移 16 新增 ai_drafts、ai_draft_revisions、ai_draft_adoptions，旧 AI 输出不补造成草稿。读取沿用父任务当前权限；创建/编辑/采用需任务编辑权，项目资料目标同时需当前项目编辑权。源/目标权限在幂等回执前与事务内检查；私有、跨任务、跨项目来源或目标不能借采用扩大可见性。归档项目仍可人工协作。

目标修改、不可变采用记录、资料修订、事件与幂等回执同事务。任务说明采用会原子暂停该任务待执行的 preview/node 接续，保留原材料、已发停止请求和未知目录锁。现有 Run、派发内容、节点/账号授权保持不变；未获许可节点派发仍受原任务修订检查。资料采用使资源版本递增，已有选材按自己的启动前规则复核，固定快照不会改写。

## API 与剩余范围

- `GET /tasks/:id/messages/:messageId/draft-preview`：当前任务的 AI 回复来源与预填文本。
- `GET/POST /tasks/:id/ai-drafts`：有界列表/创建；创建提交 sourceMessageId、expectedSourceHash、title、content。
- `GET/PATCH /tasks/:id/ai-drafts/:draftId`：读取/按 expectedRevision 修改。
- `GET .../:draftId/target?kind=task|source&id=...`：目标当前正文/修订与长度上限。
- `POST .../:draftId/adoptions`：expectedRevision、ranges、mode、target:{kind,id,expectedRevision}。
- `GET .../:draftId/revisions` 与 `GET .../:draftId/adoptions`：有界修订/采用历史。

独立需求实体、成果/协助建议等更多来源和目标、自动生成草稿、富文本块编辑与批量采用尚未交付。当前草稿不是草稿偏好缓存，也不构成第二套任务/AI 会话系统。实际验证见 [21](../development/21-implementation-status.md)，下一步见 [22](../development/22-next-delivery.md)。
