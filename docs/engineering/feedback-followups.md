# 由成果反馈建立后续任务

固定版本的真人反馈（包含回复）下选择「后续任务」，可以查看这条反馈实际关联且当前可访问的任务。选择「建立后续任务」后，先核对原版本、原文、可见范围和负责人，再编辑标题、说明并明确创建。仅打开、返回或关闭不会创建任务。

## 工作内容与固定来源

标题最多160字符，说明最多12000字符，可以独立编辑；说明初始引用原反馈，提交内容由成员确认。服务另保存 feedbackOrigin：原Task/名称、ResultRevision/版本、真人消息/作者、原文/哈希和已有代码锚点。后续修改任务标题、说明、状态或负责人均不改变这一来源。来源记录不读取仓库、节点私有正文或未共享代码。

新任务复用现有Task，状态待开始，当前操作者是负责人和创建者。项目反馈只能创建原项目的项目任务；私有反馈只能创建同空间本人私有任务，没有扩范围、选其他项目或指定其他负责人的入口。原任务、状态和反馈不变，创建不启动Run、Operation、模型或授权。归档项目仍允许这类人工作业，后续执行受原归档保护。

新Task顶部可展开「来自原反馈」查看原文，分别返回原Task、原版本反馈或已有代码位置。后来发布新成果不会漂移旧链接。原反馈的后续任务列表从实际Task关系读取当前标题/状态，先按当前权限过滤，再显示最近50项；不泄露不可见目标的名称、正文或计数。

## 取消、权限与未知回执

临时草稿按当前身份/空间/原反馈存在页面会话内存；关闭可继续编辑，明确放弃可清除，硬刷新不恢复。降权清空草稿，晚到回应不得恢复旧内容。明确创建后的未知回复只确认同一来源、标题、说明和幂等键，关闭不撤销已提交动作。

当前源编辑权、范围和固定消息在回执前及事务内重新核对。Task、来源、计数器、outbox和回执原子写入。确认原请求返回同一Task的当前可访问投影，不覆盖后来编辑、不重开已完成任务；目标已不可见或丢失时不返回旧快照，也不重建。相关列表只要求源读取权，查看关系不增加创建权。

## 接口与有限范围

- GET `/api/v1/results/:resultId/versions/:revisionId/feedback/:messageId/follow-up-preview` 返回服务派生来源和同范围目标，或明确不可用原因
- POST 同基础路径 `/follow-ups` 只接受 `{title, description}`，需要幂等键
- GET 同基础路径 `/follow-ups` 返回当前可见Task摘要，不回传目标描述或重复整份来源

仅支持同Task/Result明确固定版本的真人反馈及其回复。已有member或legacy固定版本可用，旧未知作者不猜测；未指定版本聊天、系统/工具消息或超过来源12000字符预算的旧反馈不自动采用。已有有界共享代码锚点原样保留，不扩文件/预览访问或正文共享。
