# 本机检查点恢复预检（只读）

这是 HX-DEV-12-02 的恢复计划切片。它读取已明确保留、仍有效且已确认发布的单提交对象副本，核对恢复材料和全新目标目录；**不创建目标、不恢复文件、不授予写入权**。实现位于 PR #17，原本机对象保留用法见[对象保留](checkpoint-retention.md)。

## 使用

在原节点的 Linux 本机、已构建的 HEXU 工程中执行：

```sh
npm run build:server
npm run runner:restore-plan -- --request <保留请求ID> --state /path/to/private-state --target /existing/parent/new-directory
```

`--request` 是保留请求 ID，不是原提交引用请求 ID。`--state` 使用原配对状态目录；`--target` 必须是规范的绝对路径，父目录已存在且不能经过符号链接，最后一级必须不存在。不要把输出重定向到目标目录，因为该命令不会创建它。当前仅支持 Linux；macOS/Windows 预检明确拒绝，不从 Git 对象格式支持推导平台支持。

命令显示保留请求、完整提交、有效期限及目标，需本机逐次输入 `PLAN <保留请求ID>`。此确认只同意本次读取与显示计划，不同意落盘或启动模型。拒绝、取消、服务不可达、撤权或副本不确定时失败，不转入离线授权模式，也不重放保留回执。

## 结果代表什么

成功输出本机 JSON 计划，包含原请求/检查点/节点/工作区身份、不可变保留清单、目标及父目录身份观察、逐文件/目录相对路径、Git 对象 ID、文件模式、文件大小、展开总量、排除项、观察时间及计划指纹。`restored` 和 `writeAuthorized` 始终为 `false`。

文件名和目标绝对路径仅在本机输出，不发送给控制服务。终端或调用方保存输出可能暴露敏感文件名；**已提交到 Git 的 `.env` 等敏感内容并不自动排除**，计划明确 `committedSensitiveContentMayBeIncluded: true`。它排除的是不在该提交里的本机状态和账户材料，不是秘密扫描或脱敏工具。

`planHash` 可识别同一计划内容，不是授权令牌。预检不创建预约、进度日志或恢复回执；退出后没有可以自动续跑的恢复作业。计划通过不保证之后权限、目录、磁盘余量或副本仍可用，不能交给未来写入器直接执行而不重新核对。

## 支持与拒绝范围

仅接受普通文件、普通目录和可执行文件的原始 blob；可执行模式只记录在计划中，不执行或写入文件。支持 Git SHA-1/SHA-256、二进制及受支持的 UTF-8 名字。原始 commit/tree/blob 必须重新核对哈希、大小和清单，缺失或损坏不回源修补；来源工作区移走不影响独立副本的只读核验。

整份拒绝符号链接、子模块引用和 LFS 指针，不跳过后声称完整。祖先历史、`.git` 元数据、暂存/未提交/未跟踪/忽略的工作副本内容、LFS/子模块实体及模型/节点私有状态不作为输出材料。已提交而后来被忽略的文件仍属于该提交。

为首个普通文件切片保守拒绝非 UTF-8 字节、控制/格式字符、危险名字、尾随点/空格、保留设备名、同目录大小写或 Unicode 规范化冲突，不静默改名。每段最多 255 字节，含目标的完整路径最多 4095 字节；原对象保留限制继续适用。**展开后的文件总字节另外限制为 64 MiB**，重复引用同一个 blob 的不同文件分别累计。

已有文件、目录及悬空符号链接都算占用目标；与来源 root/gitDir 或节点状态目录重叠时拒绝。确认/核验过程中父目录身份变化也拒绝。这仍是只读路径观察，不是目录固定、文件系统隔离或无竞态写入证明；未来写入/发布需排他创建并再次核对，不能用预检替代。

## 状态与权限不变

现有副本数据库以只读连接和读取事务访问，不初始化新数据库，不更改清单、到期时间、顺序报告或待确认回执。等待用户确认期间不持有 SQLite 读事务；读前与返回文件清单前分别重查原节点当前权限、凭证/目录绑定、原请求、清单和生命周期状态。

命令不运行 Git checkout、hooks/filter、安装、仓库脚本或模型，不修改源 HEAD/index/工作文件，不改变 Task、Run、Operation、负责人或目录锁。控制请求只核对保留请求 ID，不把网页变成本机任意路径读写入口。
