# 核对并明确共享候选差异

候选差异挂在原 IntegrationOperation 内，比较“原目标固定提交”和“本次候选”。它不创建另一个Run或Result，不把原目录应用完成，也不授权继续执行。

## 从Task选择试应用文件

原整合记录中的“选择文件试应用”与“选择文件应用”是独立入口：

- 试应用可选完整预检中无冲突的新增、修改、删除；未选择的内容仍保留目标一侧
- 页面展示固定来源版本、共同起点、目标提交与恢复副本，选择后明确生成本机命令
- 命令中的节点状态目录与全新绝对输出路径由操作者在本机替换；页面不收集或上传这些路径，不创建节点待执行请求
- 原“选择文件应用”仍只支持已有父目录中的普通文件新增，不能用试应用勾选扩大它的范围

按[私有试应用](integration-trial.md)在本人节点确认并生成独立候选。只有本机日志已明确记录`ready` / `published`，才可进入以下差异流程；未知发布即使有目录也不能追认为成功。

## 本机先核对，再另行共享

```sh
npm run build:server
npm run runner:integration-trial-diff -- \
  --operation <原整合ID> \
  --state <原节点状态目录> \
  --trial <本机试应用ID>
```

1. 命令展示原固定输入、候选路径和完整选择清单。输入`DIFF_TRIAL <试应用ID>`才读取固定对象和候选目录
2. 重新核验原绑定、完整材料、原清单以及候选全部文件/模式/所有权；正文从已核验对象生成，不采纳候选目录中的后续编辑或额外文件
3. 在本机展示完整选择与有界前后内容。输入`SHARE_TRIAL_DIFF <试应用ID>`才允许把这一固定包送到原Task

读取确认不是共享同意。拒绝共享不会删除候选；仅生成本地差异不会把Task或原操作改成成功。已冻结差异再次显示时明确属于历史观察，不意味着重新检查了当前目录。

本机先保存精确待发包，再发送。回复未知时重试同一命令，只核对当前权限并确认原包回执，不重新读对象、扫描候选或重算内容。待发未确认时保留原节点凭证；新身份不能接管旧候选或报告。

## 页面中的不可变候选历史

一个试应用ID只对应一份不可变报告。改变选择需要新输出目录和新的本机试应用ID；同一整合可以保留多份报告，旧的选择、核验时间和正文不覆盖。

页面列出历史并固定正在查看的候选。新的报告只提示有更新，不把旧版静默换成最新版。临时读取失败保留已有详情和输入；当前Task权限丢失后清除。历史正文按当前Task访问权限读取，材料当前不可用与过去曾共享的观察分开表达。

所有候选都标明“未应用到原目录”。左右分别为原目标固定提交与本次候选，不把它显示成来源版本之间的比较或真正的Git合并提交。服务端核对报告绑定、当前权限、文件引用和有界正文哈希；完整目录核验来自原节点观察，不宣称服务端访问过本机文件。

## 预算与隐私

完整选择最多80个路径，不截断。可显示正文的差异最多40个文件，单侧文本最多8 KiB；差异最多24 KiB，整个报告最多48 KiB。大文件、二进制、预算不足和省略文件有明确标志，不把显示包当完整补丁。

最多保存100份同整合候选报告；达到上限不妨碍既有精确包对账。报告与Task通知同事务保存，原预检、应用状态、操作历史及Task/Run/Result保持不变。

共享只包含所选相对路径、所选文件前后引用/模式及获准的有界正文，没有绝对路径、inode、凭证、完整候选清单或未选目标正文。大小写/NFC成对改名保留各自准确路径；已存在的Result差异协议保持原语义。
