# 普通文字成果保存新版本

在普通文字成果最新版选择「编辑并保存新版本」。页面核对当前标题、说明和固定版本后再开始编辑；明确保存时追加同一个Result的新ResultRevision，不另建成果容器。新版本标记本次编辑者，原版本正文、作者和反馈保持不变。

## 编辑与历史

标题最多160字符、说明最多12000字符。原基线标题/说明单独保留，成员编辑的是新版本内容。保存后提供新版本链接，当前查看的旧版与旧反馈不会自动切换。历史页可明确前往最新版后修订。

普通member文字成果可以修订；来源标为legacy的普通文字，也可由当前编辑者明确保存新的member版本，旧版未知作者仍保持未知。方案当前/历史来源或持久分支关联会使此入口不可用，方案成果仍从原方案保存，不能借文字修订去掉Run/代码出处；demo-preview也不支持。

沿用现有成果保存的100版上限。达到上限时说明不能再追加；仍可查看全部已有版本和确认原请求，不借新入口扩历史分页或默认迁移旧反馈。

## 并发、草稿与回执

每份草稿固定原revisionId和版本号。另一成员发布新版本后显示新旧对照，保留本地编辑，不自动更改提交基线；用户可明确放弃旧草稿并载入最新版，再重新编辑。服务对首次写入同时核对版本号和版本ID，不能覆盖并发成果。

草稿存在当前身份/空间Provider内存，应用内切换成果按Result隔离，关闭可继续；放弃、撤权或硬刷新后不恢复。短暂读取错误保留编辑，取消的旧读取不能用迟到响应关掉新编辑器。发送后关闭不等于取消；未知回执仅确认同一原基线、标题、说明和幂等键。

原请求回执始终指向它实际创建的不可变版本。即使已经有更晚版本或达到100版，确认原请求也不追加、不返回最新版本冒充原保存。当前Task编辑权限及普通文字来源资格仍在事务前和事务内重验，撤权不能借旧回执读取或写入。晚到回应不得恢复清除的草稿或抢走用户的新页面。

## 写入范围

Result当前投影、不可变新版本、outbox和回执同事务；保留Result/Task身份与最初创建时间，不变更Task状态、负责人、执行、目录、选择、旧反馈/回复或后续Task来源。不读节点/代码、不新增分享权限、不调用模型。归档项目仍允许人工作业，原执行限制保持。

GET `/api/v1/results/:resultId/member-version-preview`返回当前可用固定版本或明确原因；POST `/api/v1/results/:resultId/versions`仅接受`expectedRevision`、`expectedRevisionId`、`title`、`body`并要求幂等键。新路由96KiB请求预算兼容最大中文/JSON转义，字符限制仍独立校验。
