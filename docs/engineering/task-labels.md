# Task 标签与精确筛选

项目可见Task可以维护自己的一组文字标签。在任务头点击“标签”，将新标签加入本次草稿、移除不需要的项，再明确保存整个集合。只读成员可查看；私有任务暂不支持，不会因此分享或枚举私有内容。项目归档和Task取消不撤销原有人工元数据编辑权；项目看板的取消列依然只读，不提供隐式状态操作。

每Task最多16个标签，每个原始输入最多32个UTF-16字符，去两端空白后采用NFC规范形式；控制字符和重复名称拒绝，名称区分大小写。标签属于Task，没有项目级目录或改名级联；改一个Task不会批量改变其他Task的同名标签。原文按文字呈现，不执行HTML或抓取链接。

输入法组合输入的 Enter 只用于确认候选文字；结束选词后再次按普通 Enter 才加入本次草稿。此输入保护为本地候选，尚未完成真实浏览器验收，见[验证记录](../development/history/2026-10-08-task-label-ime.md)。

## 保存、冲突与回执

标签有独立修订，最初为1。读写标签不修改Task正文、Task修订/时间、内容历史、已有执行或材料。表单打开后基线固定；新事件只更新当前集合与冲突提示，不替换草稿。冲突时可以明确载入当前标签，或保留自己的草稿并采用当前基线，再保存完整集合。后者可能移除别人后来加的标签，页面会明确说明。

暂时读取/保存失败保留输入。未知保存只能确认原Task、原标签集合、原基线与原操作标识；较新集合不会被旧回执覆盖。草稿和待确认包仅在当前抽屉内，关闭不撤销已经提交的保存；关闭、身份/空间/Task变更及当前权限拒绝清理本次编辑器，晚回应不能影响新会话。不会保存到浏览器存储。

## 列表与看板

项目中的标签筛选与原负责人、参与者、状态、关注内容和文字搜索取交集。可选标签只来自当前有权看到的该项目Task。使用完整规范名称精确匹配，API与列表/看板共用规则；不做子串或大小写模糊匹配。有效但没有任务使用的名称返回空结果，空值、控制字符、重复标签参数明确报错；URL保留筛选和视图，支持刷新、Back/Forward和明确清除。

保留原默认值：项目UI不含取消任务，只有明确选取消才显示只读列；API保持既有全部当前可见状态投影，状态/关注仍在项目UI筛选。筛选发生在当前访问过滤之后、游标分页之前，不扩大Workbench原有可见范围。

## API 与存储

- `GET /api/v1/tasks/:taskId/labels` 返回 `taskId/revision/labels/canEdit`
- `POST /api/v1/tasks/:taskId/labels` 严格接受 `expectedRevision/labels`，使用原 `Idempotency-Key`；回执固定本次已保存集合与标签修订
- `GET /api/v1/spaces/:spaceId/tasks?label=...` 与原查询条件取交集

迁移34创建Task标签集合、逐项关联与不可变变更事件。旧Task没有标签，也不补造历史作者/时间。实际集合变化、事件、Task范围outbox和回执同事务；无变化仅确认回执，不虚增标签修订。当前父Task访问/编辑权限在读取、旧回执前及事务内复核，独立Task标签修订不能成为访问授权。

当前标签只在Workbench/detail/list的人工读取DTO投影，不写入Task JSON。标签不是结构化attention、Requirement、依赖、里程碑或模型输入。实际验证和未完成边界见[本轮记录](../development/history/2026-10-08-task-labels-recovery.md)。
