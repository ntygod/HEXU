# 固定选择与候选的明确整合应用

这是 HX-DEV-13-05 的实际写入路径，仍是部分实现。仅支持同项目/Task、本人 Linux 节点、干净普通 Git 目录。旧“选择文件应用”仅新增普通文件及必要父目录；已在本地扩充的“确认写回此候选”另行绑定固定候选，才能新增、替换和移出普通已有文件。实际字节均来自完整、独立、当前有效的保留/接收对象，不能从显示 diff 补齐。当前精确版本的验证范围见[实现状态](../development/21-implementation-status.md)。

## 仅新增文件的原入口

1. 按[整合预检](integration-preflight.md)完成固定成果、目标提交/恢复副本和完整对象三方预检。80项/48 KiB有省略的计划不能用于应用。
2. 打开原Task的整合记录，点“选择文件应用”。只选择明确标为新增的普通文件；修改、删除、冲突、目标已有文件不能在本轮选用。未选范围保持原目标。
3. 核对固定来源版本、目标提交、恢复副本和所选文件，勾选确认后点“确认所选应用范围”保存。请求固定预检报告指纹、目标/Task修订和规范化选择，不能被后来的方案选择或新报告替换。尚未写入；此时可在Task内取消。
4. 在原目标节点构建后运行：

```sh
npm run build:server
npm run runner:integration-apply -- --operation <整合ID> --state <节点状态目录>
```

节点展示固定来源、目标、恢复点、本机目录和选择。输入 `APPLY <应用ID>` 才授权本次所选文件、必要的新父目录及阶段报告共享。应用ID由命令展示，和整合ID不同；未确认不会写入。

节点重新核对源/目标完整对象、coverage/指纹、共同起点、完整原报告、选定子集的路径碰撞，以及目标HEAD、索引、全部文件。目标未跟踪/忽略内容也会阻止应用。选择新增不能借未选择的删除避开大小写或Unicode别名冲突；必要且原固定目标中缺少的普通父目录可排他新建；不接管确认后后来出现的目录。每次最多256个新目录，目录相对路径合计最多64 KiB；超预算在写入前拒绝。

## 固定候选的已有文件写回

1. 先按[私有试应用](integration-trial.md)在全新独立目录组合候选，再[核对并共享候选差异](integration-trial-differences.md)。原目标仍不变。候选记录不可改；显示正文有界，不是完整补丁。
2. 在原Task中选择确定的候选，查看其差异、完整路径、trialId与指纹，点“确认写回此候选”。这会另行打开应用确认：固定整个候选选择，不允许在确认中偷偷换子集。旧ADD-only请求不会升级覆盖权限；新的候选标识/报告与清单指纹和明确确认一起进入应用输入指纹。
3. 勾选另行授权新增、替换/移出和私有备份，保存一次请求。临时错误保留固定选择；任务/操作修订变化必须重新核对；丢失回执沿用原候选、原body/key，关闭重开不会改用新候选。撤权清空编辑。
4. 原节点使用页面生成的命令，替换带引号的占位符：

```sh
npm run runner:integration-apply -- --operation '<整合ID>' --state '<原节点状态目录>' --backup '<全新私有备份绝对目录>'
```

备份必须是尚不存在的绝对目录，位于同一文件系统，且在所有登记代码目录、节点私有状态和已有候选目录之外。路径只在本机指定/保存，不上传到控制端。不接管已存在备份或偷偷扩大节点目录范围。

5. 先停止目标中的全部执行、编辑器自动保存及其他写入者，再输入 `STOPPED_AND_APPLY <应用ID>`。节点重查本机已共享候选的原身份/清单/字节、完整源/目标对象、固定预检和当前权限。原目标必须仍严格匹配原提交；候选被编辑/移动、材料到期或目标变化时拒绝。
6. 本机新建0700私有备份目录，逐项保存意图。修改通过Linux `RENAME_EXCHANGE`交换所选文件与已核验新材料，原文件完整inode留在备份；删除通过`RENAME_NOREPLACE`移入空备份槽，不unlink。普通已有文件限定600/644/700/755、单链接、本人所有、无扩展属性/ACL，单文件8 MiB以内。普通读取权限不扩大，明确执行位按原读取权限调整。特殊文件/权限/属性或不支持的文件系统拒绝，不降级为普通覆盖/copy。
7. 每次后续应用及最后完成核验原目标与已确认变更的精确并集，并重验原文件备份的真实哈希/身份、候选与短时身份/时间戳观察。保留未选文件、原HEAD/index、完整候选与恢复副本，不自动commit/reset/stash、运行代码或调用模型。

每个文件的改名是原子的，整组文件不是一个原子事务。Linux rename不提供“内容仍相同才交换”的CAS；持久锁仅协调HEXU受管写入者，不能阻止不合作的编辑器/外部进程。停止其他写入者是实际前提；若仍发生竞态或结果未知，保留目标与备份两处材料和意图、报告需处理，不交换回去、不删除、不猜成功。

## 写入与证据

- 同一节点应用进程有持久进程守卫，目标另持有与执行器共享的工作区写锁；原目录即便被改名，同inode也不能启动第二写入者。
- 每个新增前先保存意图。Linux组件在固定父目录创建匿名inode，精确写入有界字节、设普通Git模式并同步，再用 `linkat` 排他挂名，最后同步父目录。目标若出现文件/目录/悬空链接一律拒绝；不支持匿名文件或本地文件系统时不降级为覆盖。
- 新父目录先持久保存所选文件意图、目录路径和唯一暂存名，再在已固定父目录创建0700私有空暂存目录，记录真实身份后以既有Linux不覆盖原语发布。原祖先身份冻结，本次新目录按逐项所有权核对；即使父目录被替换成相同内容也不接管。未知/拒绝发布保留暂存和原意图，不自动清理。
- 仅新增入口不修改既有文件；固定候选入口只改变其明确选中的普通文件。原HEAD与索引均保持，成功仍是未提交变更，不启动模型或自动commit/reset/stash。
- 每次后续写入和最后结算均核对原目标树、已确认新增目录和文件的精确并集、身份、内容哈希与模式。不会把任意untracked文件当本次产物。
- 应用意图、阶段报告、历史/outbox/幂等回执在各自持久边界先保存；原预检报告不可覆盖，且其中 `applied=false`、`writeAuthorized=false` 永不被改成写入许可。

## 中断和重复调用

| 状态 | 含义 |
| --- | --- |
| 等待本人确认应用 | 范围已保存，没有收到节点写入声明；可以取消请求 |
| 应用进行中 | 节点声明已进入应用阶段，可能已写部分文件；不能在浏览器直接宣布撤销 |
| 所选文件已应用 | 所选范围确实落地并经最终核验，本机完成证据已持久保存；不代表质量或Task完成 |
| 应用失败 | 本机确认本次应用未留下文件/目录或未确认暂存，保留固定历史；已证明无写入的本次锁可释放 |
| 需要本机处理 | 中断、可能部分写入或结果不明；保留文件、恢复点和写锁，不自动删除或回滚 |

共享阶段的已写数量只计文件，不含目录。即使显示0个文件，也可能已创建父目录或留下暂存；此时仍是需要处理并保留写锁，可用下方本机状态核对目录证据。

再次运行相同命令只对账原日志/报告，不重新确认、读取材料或续写。终态HTTP回执丢失只核对同一固定包；不能把已完成变回未执行。实际进程退出、启动回执未知或部分写入后重启不会重放写入。当前权限撤销时无法共享的证据仍保留本机，旧回执不能恢复权限。应用进行中、待决回执或未知现场时不能断开删除原凭证，也不能重新配对绕过证据；等待本机确认期间同样受进程守卫保护。

可用Ctrl+C/SIGTERM停止后续文件；已完成当前原子新增不能当作撤销。SIGKILL或系统崩溃后也保留原尝试。“需要本机处理”可在明确确认原应用及所有子进程已停止后，使用独立的[保留现场结算](integration-recovery.md)核对原锁收据并解除本次占用；不修复/删除文件，不把未知结果包装成已应用。不能用其他Run恢复命令、编辑数据库或自动清理来清锁。

## 只读查看本机证据

服务暂时离线或应用需处理时，可单独读取原节点持久日志：

```sh
npm run runner:integration-status -- --operation <整合ID> --state <节点状态目录>
```

本命令只打开已经存在的私有SQLite日志；不会初始化状态、取得应用进程锁、联系服务、读取代码/副本、扫描目标、改写阶段、重发报告或释放写锁。它可在应用进程仍运行时读取最后一次已提交的日志快照，不把“prepared/applying”自动改成“已中断”。

输出包括本机历史阶段、已确认/待决报告序号、最后一个未确认文件意图及已确认新增的文件身份；新目录格式还返回`confirmedCreatedDirectories`和`intendedDirectory`，包括可能留存的暂存名/身份。候选写回格式另含`existingChanges`，记录私有备份位置/目录意图、原文件备份归属、已确认替换/移出与未确认文件意图；它同样只是原日志，不读取当前备份。旧日志不会补造未知目录归属。`directoryChecked`、`currentServerAuthorityChecked`、`processStoppedConfirmed`、`writeAuthorized` 均为false；旧目录已移动、文件被修改、节点已撤权或服务离线时，这些日志都不是当前安全/权限证明。没有每条记录的观察时间时不从文件mtime补造时间。

原凭证/目录登记绑定必须仍匹配；日志缺失、损坏或路径被替换时明确报错，不重新配对或伪造一条状态。文件名和本机路径仅在原节点显示，不作为新共享报告上传。该命令帮助核对证据，本身不是恢复或解锁；需要解锁时另走[明确停止后的保留现场结算](integration-recovery.md)。
