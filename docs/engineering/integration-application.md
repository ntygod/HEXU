# 选择新增文件的明确整合应用

这是 HX-DEV-13-05 的首个实际写入切片，仍是部分实现。仅支持同项目/Task、本人 Linux 节点、普通 Git 目录，在已经存在的父目录中新增所选普通文件。新增内容来自完整、独立、当前有效的保留/接收对象，不能从显示 diff 补齐。

## 使用

1. 按[整合预检](integration-preflight.md)完成固定成果、目标提交/恢复副本和完整对象三方预检。80项/48 KiB有省略的计划不能用于应用。
2. 打开原Task的整合记录，点“选择文件应用”。只选择明确标为新增的普通文件；修改、删除、冲突、目标已有文件不能在本轮选用。未选范围保持原目标。
3. 核对固定来源版本、目标提交、恢复副本和所选文件，勾选确认后点“确认所选应用范围”保存。请求固定预检报告指纹、目标/Task修订和规范化选择，不能被后来的方案选择或新报告替换。尚未写入；此时可在Task内取消。
4. 在原目标节点构建后运行：

```sh
npm run build:server
npm run runner:integration-apply -- --operation <整合ID> --state <节点状态目录>
```

节点展示固定来源、目标、恢复点、本机目录和选择。输入 `APPLY <应用ID>` 才授权本次新增与阶段报告共享。应用ID由命令展示，和整合ID不同；未确认不会写入。

节点重新核对源/目标完整对象、coverage/指纹、共同起点、完整原报告、选定子集的路径碰撞，以及目标HEAD、索引、全部文件。目标未跟踪/忽略内容也会阻止应用。选择新增不能借未选择的删除避开大小写或Unicode别名冲突；所有父目录必须已经存在，不自动mkdir。

## 写入与证据

- 同一节点应用进程有持久进程守卫，目标另持有与执行器共享的工作区写锁；原目录即便被改名，同inode也不能启动第二写入者。
- 每个新增前先保存意图。Linux组件在固定父目录创建匿名inode，精确写入有界字节、设普通Git模式并同步，再用 `linkat` 排他挂名，最后同步父目录。目标若出现文件/目录/悬空链接一律拒绝；不支持匿名文件或本地文件系统时不降级为覆盖。
- 原HEAD、索引和既有文件不修改；成功仍是未提交的新增文件，不启动模型，不自动commit/reset/stash。
- 每次后续写入和最后结算均核对原目标树与已确认新增文件的精确并集、inode、内容哈希与模式。不会把任意untracked文件当本次产物。
- 应用意图、阶段报告、历史/outbox/幂等回执在各自持久边界先保存；原预检报告不可覆盖，且其中 `applied=false`、`writeAuthorized=false` 永不被改成写入许可。

## 中断和重复调用

| 状态 | 含义 |
| --- | --- |
| 等待本人确认应用 | 范围已保存，没有收到节点写入声明；可以取消请求 |
| 应用进行中 | 节点声明已进入应用阶段，可能已写部分文件；不能在浏览器直接宣布撤销 |
| 所选文件已应用 | 所选范围确实落地并经最终核验，本机完成证据已持久保存；不代表质量或Task完成 |
| 应用失败 | 本机确认没有文件已写入，保留固定历史；已证明无写入的本次锁可释放 |
| 需要本机处理 | 中断、可能部分写入或结果不明；保留文件、恢复点和写锁，不自动删除或回滚 |

再次运行相同命令只对账原日志/报告，不重新确认、读取材料或续写。终态HTTP回执丢失只核对同一固定包；不能把已完成变回未执行。实际进程退出、启动回执未知或部分写入后重启不会重放写入。当前权限撤销时无法共享的证据仍保留本机，旧回执不能恢复权限。应用进行中、待决回执或未知现场时不能断开删除原凭证，也不能重新配对绕过证据；等待本机确认期间同样受进程守卫保护。

可用Ctrl+C/SIGTERM停止后续文件；已完成当前原子新增不能当作撤销。SIGKILL或系统崩溃后也保留原尝试。当前还没有“需要本机处理”的明确恢复/锁结算命令；保留现场，不能用其他Run恢复命令、编辑数据库或自动清理来清锁。这是下一步待交付范围，不把未知结果包装成已恢复。

## 尚未支持

修改/删除已有文件、新建父目录、文本自动合并、冲突选择、linked worktree、Windows/macOS、多来源、跨电脑部署和未知现场的明确恢复均未交付。Linux文件/协议夹具不代表真实Claude/Codex账户联调。本地实现和实际验证见[应用记录](../development/history/2026-09-30-integration-application.md)。
