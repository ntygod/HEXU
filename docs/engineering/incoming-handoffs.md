# 发给我的待接手邀请

真实账号模式的Workbench增加当前空间待接手入口，按邀请接收者读取，与Task负责人无关。仅显示本人收到、当前项目Task仍可读、状态为offered且尚未到期的邀请；摘要不是材料可用、节点授权或可以直接接受的证明。

`GET /api/v1/incoming-handoffs` 返回 `items` 和 `nextCursor`，默认20项、最多50项，严格接受 `limit`/`cursor`。游标绑定当前用户/空间和仍可见的边界，原创建插入顺序向后分页；边界过期、关闭或失权需明确刷新，不静默换回第一页。

`GET /api/v1/incoming-handoffs/:taskId/:handoffId` 在同样条件下直接读取确切摘要，不受原Task邀请列表首20项限制。无权、错误接收者、其他空间/Task、不再待处理或已过期统一不可访问；不在此处扩展终态邀请历史。摘要只投影当前Task身份、可见发送者、邀请原文字与时间/修订，不带材料、节点、传输对象或操作能力字段。

新列表与定位均在同一只读快照内按当前权限和一次捕获的时间过滤，不调用旧邀请list/get/history/expire/view、材料或接受方法。过期过滤不持久化expired事件，原生命周期计时器保持原行为；读取不改变邀请、待接受操作、Task、事件、回执或执行。

链接 `/tasks/:taskId/handoffs/:handoffId` 只挂载当前可见Task的轻量身份/链接与纯摘要抽屉，不在背景启动完整工作区的详情、代码或执行呈现。刷新及浏览器返回/前进保留目标，关闭回到Task。只有明确“查看并处理邀请”才进入原完整邀请Card；接受、准备和执行仍由原独立界面和当前条件控制，不因发现或打开摘要自动发生。处理模式与待处理摘要分开，不让摘要到期或后续接受状态重置旧完整流程。

当前权限/期限失效清除摘要；旧读取与关闭、导航、明确重试不能串会话。重获权限不借旧回应恢复已经清除的目标。普通后台读取保留当前同会话内容，暂时失败可明确重试；确实拒绝和失效不当作暂时故障。
