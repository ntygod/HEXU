# 提交文件对象的本机核验与明确保留

本批为 HX-DEV-12-02 的 team-local、项目任务、原本人节点、单提交切片。它在原 `git_commit_reference` 上建立**单独请求、单独同意、独立对象副本**，不把旧引用升级或覆盖，不是远端备份、Git 全历史镜像或已完成的文件恢复。

## 使用

在原任务“代码检查点”中，找到已经核对的提交引用，点击“核验与本机保留 → 保留对象副本”，选择 1、7 或 30 天并确认范围。只有该引用原节点的本人且仍具有任务编辑权限时可以发起；网页创建的只是有效期 30 分钟的请求，不读取本机文件、不启动模型。

原节点本机在 HEXU 已构建工程执行：

```sh
npm run runner -- retain-checkpoint --request <保留请求ID> --state /path/to/private-state
```

`--state` 为原配对状态目录。终端显示真实来源目录、完整提交和期限，需逐次输入 `RETAIN <完整提交ID> <天数>` 才进行核验和复制。会读取此提交的原始树/文件对象，**已经提交到 Git 的敏感内容也会被复制到本机私有数据库**；应先核对材料，不把目录权限、旧摘要配对或网页同意当作本次本机同意。不需要模型账户。

成功后任务面板显示对象数量、字节、文件/树条目和外部内容排除项。公开记录只包含完整 commit/tree、清单指纹、原本机仓库指纹、数量、时间及范围，不上传原始内容、文件名、绝对路径、Git 作者邮箱或节点凭证。记录遵守当前原任务访问权限。

## 实际保留范围

保留原提交对象和该提交根树向下可达的全部受支持 tree/blob 对象，并逐一检查原始类型、长度及 Git SHA-1/SHA-256 内容哈希。包括二进制和可执行文件的原始 blob；树里保留文件模式与原始名字字节，不把名字当成本机路径来写文件。祖先提交和其他分支的历史不保留。

LFS 文件仅保留 Git 中的指针 blob，不下载或包含 LFS 实体；子模块只在树中保留 gitlink，不进入子模块仓库；符号链接只留原始链接文字，不跟随或展开。面板分别显示这些条目数量，不能据此声称完整外部内容可恢复。工作区的暂存、未提交、未跟踪和忽略文件内容不被收集；已提交文件即使后来被忽略仍属于该指定提交。

每份最多 10,000 个独立对象、50,000 个树/文件/链接条目、64 MiB 原始对象总量，单 blob 8 MiB、单 tree 4 MiB、commit 64 KiB、树深度 64。遍历时间上限 120 秒，每次 Git 命令最多 4 秒；对象过大或缺失、格式不支持、重复名字、危险路径片段及哈希不符均拒绝整份保留，不截断或跳过后发布成功。原始对象语义见 [Git cat-file](https://git-scm.com/docs/git-cat-file)，LFS 范围见 [Git LFS 指针规范](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md)。

沿用原本机 Git 身份检查、隔离元数据、允许列表环境和禁止自动 fetch/replace/hooks/filter/helper 的读取方式，普通和标准 linked worktree 的授权不扩大。复制不依赖来源工作区干净，也不更改 HEAD、索引、原文件、分支、任务修订/负责人/状态、活动 Run、Operation、原冻结材料或未知目录锁。

## 保留副本与生命周期

对象原始字节、固定清单、来源绑定及待确认报告存于 `<state>/retained-checkpoints/journal.sqlite`。目录为当前 POSIX 用户独占 0700，数据库文件 0600，独立进程锁不阻塞主 Runner；一次只允许一个副本管理进程。副本写入采用 SQLite 事务和 FULL 同步，写入成功后再从**实际持久副本**完整复核，才发送首份公开记录。单节点最多 16 份未删除副本及 1,000 份生命周期元数据；每原引用最多 32 个请求。

这是独立复制，不是源仓库 ref/pin、符号链接或 alternate；源仓库移动或 Git 清理不会直接删掉已保存的副本。但本机磁盘损坏、人工删除或恶意程序仍可能损坏它，界面仅陈述**最后一次本机报告**，不作连续在线/磁盘可用性保证。私有权限不是加密、操作系统沙箱或 DLP；不防同一 OS 用户持续恶意竞态，服务端也不能仅凭元数据排除恶意节点伪报。

期限从成功保留时计算。到期后不再标为有效材料，**不会自动续期，也不会由计时器删除字节**；需明确执行删除命令。到期再次核验只更新观察时间，不改变原到期时间。

重新核验只读取已保存对象，不读取来源仓库、不自动修补或重新采集：

```sh
npm run runner -- verify-checkpoint --request <保留请求ID> --state /path/to/private-state
```

可报告核验通过、对象缺失或对象损坏。原绑定凭证/目录配置发生改变时拒绝借新身份管理旧副本。整个副本管理数据库不在时命令明确报不存在，不伪造缺失对象详情；任务上的旧报告不是实时保证。

明确删除这一份副本：

```sh
npm run runner -- forget-checkpoint --request <保留请求ID> --state /path/to/private-state
```

输入 `DELETE <保留请求ID>` 后删除相应对象行，保留原提交引用和不可变保留清单/生命周期记录，不删除原仓库或其他副本，不运行 Git cleanup。数据库开启 `secure_delete` 清理删除行，但不承诺底层存储、备份或 OS 缓存的取证级擦除，也不通过 VACUUM 操作其他记录。首次报告加后续核验最多使用序号 1—99，序号 100 专用于删除，不因核验次数耗尽而无法清理。

## 回执、取消与权限

迁移 21 建立 `checkpoint_retentions` 和不可变 `checkpoint_retention_reports`，不为旧引用补造任何副本证据。每次创建、取消、节点检查、首次发布、后续核验和重复回执均复查当前任务范围、原节点所有者及 revision；节点重新加入不复活旧授权。原任务只读成员可以读公开记录，不能发起/取消或借用本人以外节点。

公开请求与 ID-only 回执/outbox 原子提交；固定 manifest、顺序报告、当前状态与任务范围 outbox 原子提交。序号跳跃、同序号不同内容、来源/期限替换和删除后复活全部拒绝。旧成功请求返回当前投影，不重放原状态。

本机在发送前持久保存唯一待确认报告。掉线或服务端保存成功后回执丢失，再执行同一命令仅确认原报告，不重新采集、不续期、不偷偷执行不同动作。删除字节和待发布删除证据同事务保存，丢失删除回执不会恢复对象。

取消尚未发布的请求不代表已删除本机数据。确认期间与对象遍历后重新检查服务端权限/取消；在核验后而发布前发生取消/超时，可能已在本机保存对象但未公开，须明确删除。未知回执先确认原请求；如果服务端确认请求从未发布且已关闭，可清除待发报告再明确删副本。若原节点撤销导致尚未确认的报告无法核对，本机保留不确定证据，不抹掉它或换凭证重发，此类清理仍需本机维护。

已确认发布且没有待决报告的副本，即便控制服务不可达或节点撤销，仍允许原本机身份明确删除字节，保留未确认删除报告并报出发布失败，不假称服务端已确认。网页取消、退出或归档不会自动删本机数据。

## API

浏览器 Cookie 与 Runner Bearer 通道分离；保留操作不增加普通摘要 RPC 权限。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET/POST | `/api/v1/tasks/:taskId/checkpoints/:checkpointId/retentions` | 当前可读者列出最多32条；原节点本人创建独立保留请求 |
| POST | 上述路径加 `/:requestId/cancel` | 当前任务编辑者取消本人未发布请求；body 为空对象 |
| POST | `/runner/v1/checkpoint-retention-inspect` | 原节点凭证核对指定请求与当前权限 |
| POST | `/runner/v1/checkpoint-retention-report` | 发布严格有界的顺序报告，不传对象字节或路径 |

创建只接受 `days, expectedTaskRevision, confirmLocalRetention:true`，沿用幂等键。报告只接受 `requestId, requestHash, sequence, report, confirmPublication:true`；首份为 retained+manifest，后续只能核验状态或删除，不改 manifest。临时页面读取失败保留期限/勾选但禁用新提交；任务变更需明确核对新修订；降权清除编辑，未知请求保留原参数供确认。
