# 项目Task状态与关注内容筛选

本切片沿用同一个Task、原项目列表/看板和当前权限下的API。状态只取原todo、in_progress、done、cancelled；关注内容只判断当前Task.attention去空白后是否存在文字。present/absent不等于等待、阻塞或暂停，也不从Run或Operation推断。搜索仍只搜原标题、编号和说明，与负责人、当前参与者、状态、关注条件全部取交集。

兼容既有默认：项目页面未指定status时继续排除已取消；任务列表API未指定status时继续包含当前可见的所有状态。项目明确选择cancelled才展示已取消Task，看板使用只读列，保留原Task链接，不通过筛选顺便重新打开或停止执行。项目总览计数和全局工作台活动/unknown Run不受局部选择修改。

已取消的任务可从原Task详情或成果页面明确“重新打开”，沿当前编辑权限和所见Task修订调用原reopen，返回todo；这不会恢复、创建或停止Run，也不会改写已保存成果版本。只读成员入口禁用，撤权和旧修订仍由原API拒绝。取消列表/看板保持只读，不在筛选或导航时自动重开。

任务选择保留在URL，新增选择进入历史，搜索沿用原replace行为。切换列表/看板、刷新、返回/前进和Task深链接使用同一选择。新增枚举、重复和非法条件不能静默回退为全部；API明确输入错误，页面提示修正并避免展示被悄悄扩大的结果。清除任务条件保留合法视图与其他项目页定位，项目资料/约定/成果参数不被当作任务条件提交。

API保持当前权限、项目范围、当前参与投影、条件、游标/分页的顺序；不授予私有Task、跨项目或跨空间访问。参与历史不冒充当前参与关系，读取筛选不写状态/Task修订，不发执行。文字标签与精确交集已另在PR46验收；结构化attention、持久排序/拖拽和独立Requirement仍在原工作包剩余范围。

筛选本身已在PR42验收；取消Task重开入口修正的验证见[本轮记录](../development/history/2026-10-02-cancelled-task-reopen.md)。准确状态见[当前能力](../development/21-implementation-status.md)与[本切片记录](../development/history/2026-10-01-task-state-filters.md)。
