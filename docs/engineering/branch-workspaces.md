# 方案独立现场与首轮执行

适用：同服务、同项目、同机 Linux 的项目任务。先按[方案定义](work-branches.md)固定共同说明与提交；本轮由原提交节点本人使用仍有效的保留副本，为各方案准备独立目录与独立节点。每个 Run 需要另行确认，不批量启动模型。

## 从方案卡开始

1. 在「方案分支」选择一条待准备方案，点击「准备独立现场」。选择与共同提交一致的本人对象副本；没有可用副本时，先到「代码检查点」请求保留并在原节点确认。
2. 「创建现场准备请求」固定分支、共同起点、原节点、本人身份、对象指纹及期限。请求最长30分钟，且不超过材料期限。当前 Git 现场支持16 MiB、2048对象以内的普通文件快照；不含未提交内容、祖先历史、LFS实体、子模块或符号链接。
3. 在原节点使用原私有状态目录、新的绝对目标路径运行：

```bash
npm run runner:branch-workspace -- --operation OPERATION_ID --state /path/to/source-state --target /path/to/new-branch-directory
```

终端分别确认 `BRANCH`、`RESTORE`、`PUBLISH` 和 `GIT` 所展示的本次标识。复用不覆盖恢复和单提交浅 Git 准备，只新建本次拥有的文件，不改原仓库、旧凭证或原生会话。准备成功返回独立 `nodeState`、`configPath` 和 connect 命令，并报告有界现场证明；绝对路径、文件名和代码不上传。

## 独立配对与登记

在方案卡生成自己的原项目配对码，执行终端给出的 connect 命令，输入配对码并确认 `CONNECT`。配置固定原本人、空间和项目，其他身份或项目的码不能替代。原节点的目录列表与凭证保持不变。

配对后在新节点状态目录执行：

```bash
npm run runner:branch-bind -- --state /path/from/nodeState
```

核对原方案并确认 `BIND BRANCH_ID`。本机会再次检查新目录、实际文件、Git提交和原准备记录，服务将原准备证明与本人新 Node/WorkingCopy 原子绑定。每个方案必须使用独立目录；同一已登记目录不能再绑定另一个方案。登记回执未在本机确认前，该节点不会发布模型执行许可。

之后按[节点执行指南](runner-execution.md)为新 `nodeState` 配置自己的工具、模式、预算及 `方案代码` 目录别名，单独 `enable-execution`/`EXECUTE`，再 `start`。配对、登记和执行授权是不同步骤。

## 首轮 Run 与并发

方案卡的「准备方案首轮执行」打开原执行面板，固定已登记节点和目录。默认带入该方案目标，可补充本次要求；预览包含原共同任务说明、该方案目标与本次要求，不自动加入后来的讨论、其他方案目标、项目材料或发送者会话。完整执行文本上限20000字符，超限明确拒绝，不截断固定说明。

确认后在原 Task 创建 Run，并原子记录分支关联、派发、事件和回执。节点在许可前与实际启动前核对真实代码和 Git 树，不仅相信历史报告或 Git 变更数量。准备后改动/替换文件、改换HEAD或损坏对象都会阻止首轮启动，保留用户现场。

同组的不同方案可分别授权 Claude/Codex，使用不同独立节点/目录并行；每节点仍只运行一个进程，每方案当前只创建一次首轮 Run。普通运行、不同组运行及未知原现场保留原限制。同组首个实际启动引起的自动 Task 状态修订可同步给仍排队的同组方案，人类改动仍会阻止旧许可。

卡片区分现场最后报告、节点可用性、Run接单/许可/实际启动/结束。只在真实启动事件后记录 active；Run结束不设置 ready 结果、选中、整合或 Task完成。可单独停止某方案，其他方案继续；未知进程保留目录占用，不向旧PID发信号。

方案Run的后续执行不走普通任务接续入口。终态后可明确[保存成果并比较选择](branch-results.md)，原本人另行确认[从所选代码提交继续](branch-continuation.md)。新会话要求原目录与该固定提交一致，不改动用户现场；完整产物、方案原生恢复/自动等待、整合及已登记目录清理仍待交付。普通节点接续与会话恢复保留原规则。

## 失败、取消与回执

```bash
npm run runner:branch-workspace-status -- --operation OPERATION_ID --state /path/to/source-state
npm run runner:branch-workspace-cleanup -- --operation OPERATION_ID --state /path/to/source-state
```

状态命令读取本机最后记录，不作实时文件核验，也不授予模型权限。写入前保存意图，重启把未完成准备记为 needs_attention，不续写或重做目录。重复成功命令只返回原记录；只有待确认报告/登记会重发原固定包，不重新采集、不重放模型执行。

网页可取消尚未登记的准备；取消不删除文件或停止其他工作。先取消原请求，再在本机按 `CLOSE_BRANCH` 及必要的 `CLEAN_GIT`/`CLEAN` 提示处置完整归属的失败材料。没有发出报告的失败允许本机独立处置，网页原请求仍需取消。用户新增/修改、链接、未知写入或归属缺失时不猜测删除；已发布目录和已成功 Git 仓库始终保留。

未处置准备或未知回执阻止原凭证删除/重新配对。已登记现场不能用“取消准备”或“放弃定义”解除绑定。准备失败需要新尝试时，明确处理原准备记录，再使用新请求与目录；一旦已关联首轮Run，当前不提供同方案自动或隐式重试，需保留原现场并另行定义新方案。失败不会重做同组其他方案。

## 验证边界

仅同机 Linux、回环服务；独立目录不代表OS、数据库、端口或账户沙箱。各 Run 使用自己的节点预算，尚无通用资源分配、组级预算/队列或跨电脑调度。真实 Claude/Codex 账户互操作另行验证；协议替身只证明实际进程、文件、HTTP与回执机制。当前证据见 [21](../development/21-implementation-status.md)，下一项见 [22](../development/22-next-delivery.md)。
