# E2b4｜下一轮要求与节点持久化继续

2026-09-26（UTC+8）。在已有 team-local 账号、节点配对及本机 enable-execution 基础上使用；默认摘要节点不会因此获得执行能力。只限同一机器的回环服务。

## 正在执行时先记下要求

在任务的“下一轮工作”填写要求并保存。项目可编辑成员可以添加；只有作者能编辑或撤回自己仍待选的要求。这些记录对当前任务的获准成员可见，不是个人私密草稿，不要填写 Key 或敏感账户资料。

保存仅返回 queued_for_next_turn，不向活动模型输入、不停止原执行、不自动开始新执行。每任务最多 20 条待选/已绑定记录，每条 2000 字符；面板优先显示待处理记录和最近历史。刷新、重启保留。暂未提供浏览器未提交文字的自动草稿恢复。

## 看过结果后继续

点击“沿原目录继续”。来源必须为当前任务最新节点 Run；可以在原执行活动时安排等待或请求停止后的接续，真正创建新 Run 前须已确认结束。状态未知时显示原因，不强制清锁。

源节点与目录固定，不可在接续中改为另一节点。目标工具/模型/预算来自该节点当前本机授权。切换 Claude/Codex 时须先结束原执行，在节点本机重新配置 enable-execution，并重启节点发布授权；本轮不在网页代为更换工具或账户。

明确选择本次要带入的要求（默认不全选），输入本次要求，展开完整发送文本，再确认目录、费用和共享输出。最多 6 条所选要求，含作者名的合计不超过 6000 字符，整个材料不超过 20000 字符；超限明确提示，不偷偷删选中的要求。

上下文包含最多 8000 字符的任务/近期人工讨论、1000 字符的来源要求和 2000 字符的来源共享输出，最终结果优先于过程文本。各处明确为摘录，不是全历史、原生 resume 或 diff 上传。节点仍检查原目录身份和持久化互斥，代码与未提交修改不会被 reset、stash、commit 或上传。

提交先保存持久化 Operation，条件满足后创建普通新 Run 并关联 previousRunId。已完成任务的按钮明确写“重开任务并接续”；模型结束不完成任务。另一成员改变材料、源 Run 更新、选中要求被编辑/撤回或节点授权变化时，旧请求被拒绝，须重新核对。

## 要求状态如何理解

“待下一轮选择”尚未发送；“已绑定派发，未收到启动确认”已固定到某次命令，不能再改写；“已随新执行启动”只依据实际 spawn，不保证模型读懂或完成了要求。记录一直保留来源和目标 Run。

明确未发启动许可就取消的派发，选中要求会退回待选，但不自动重发。若已经发出许可且启动历史不明，保留绑定，需要操作者检查原记录；可在确认后另写新的下一轮要求，不能通过删状态重跑旧命令。未选要求一直保留。

节点现可明确安排等待/停止后继续，详见下面的 E2b4 说明；不会在异常或重启后自动重试。preview 的既有持久化接续保持原行为。

## 本机待处理列表

先结束节点同步进程，再使用同一私有状态目录：

```bash
npm run runner -- pending-executions --state /absolute/private-node-directory
```

列表显示派发 ID、Run/Task/目录 ID、日志阶段、待 ACK 数。不显示任务原文或 Key；这是磁盘记录，不证明进程实际状态。命令使用已有状态目录互斥，运行中的节点占用时会拒绝并行操作。它不清理锁、不杀旧 PID。

需要恢复时仍应核对原进程及子进程是否全部停止，再用已有 recover-execution 的明确 STOPPED 确认保存证据，随后 start 同步。没有待处理记录也不证明机器没有平台外进程。


## E2b4：运行中安排下一次继续

“沿原目录继续”现在可以在原执行仍活动时打开。填写本次要求并明确选择下一轮条目，然后选择“等待原执行自然结束后继续”或“请求停止原执行后继续”，确认本次数据/费用范围后保存。

节点接续与 preview 都使用 `/tasks/:id/continuations` 的 **202 Operation**：页面显示独立的安排进度。关闭面板、刷新或关闭网页不取消；服务持续运行时，在原执行已确认结束后自动派发。Operation 成功只表示新 Run 已创建，后续接单/启动/结果见执行记录。

本轮固定本次预览文本。等待时新的来源输出不自动加入，未选择的要求不自动发送；源执行对同一 Git 目录的修改正常保留。要采用最新最终结果，在源执行结束后重新配置。手动 `/runs` 的 201 接续接口仍保留，但同样受活动安排预约限制。

每个任务和节点只能有一个活动安排；此限制符合当前节点一次一个执行的能力，不宣称是最终调度模型。等待自然结束上限 11 分钟，停止后等待上限 60 秒。过期只暂停安排，不释放原进程占用。节点自身仍遵守其本地执行超时。

“取消接续安排”阻止尚未创建的新 Run，不撤销已发出的停止请求或已有文件修改。新 Run 已创建后使用它自己的停止按钮。任务编辑者可取消，只读成员仅可查看；仍只有节点所有者可以创建安排。

人工讨论/任务、选中要求版本、节点策略或访问权变化会暂停，不扩大旧授权。所选条目等待时仍可编辑/撤回，但安排随即需要重新配置；新保存未选条目不影响已确认材料。控制服务重启将待安排转为需要处理，不自动重放付费工作；历史保存原要求、材料、来源和结果关联。

本功能不是原生 resume，不是跨机器恢复。节点运行中即时输入、原生会话迁移、远程部署和有效账户生成仍未实现或未验证。

## E2c1 原生恢复与新会话分开

自动等待 Operation 保持本篇的新会话语义。Codex 节点已明确开启保留且来源成功结束时，可改选实验性原生恢复，走 201 Run，继承私有原生历史；不是仅发送本次公开选材。失败不静默新建。见 [Codex 会话](codex-sessions.md)。
