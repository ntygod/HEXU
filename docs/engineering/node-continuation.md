# E2b3｜下一轮要求与节点同目录继续

2026-09-26（UTC+8）。在已有 team-local 账号、节点配对及本机 enable-execution 基础上使用；默认摘要节点不会因此获得执行能力。只限同一机器的回环服务。

## 正在执行时先记下要求

在任务的“下一轮工作”填写要求并保存。项目可编辑成员可以添加；只有作者能编辑或撤回自己仍待选的要求。这些记录对当前任务的获准成员可见，不是个人私密草稿，不要填写 Key 或敏感账户资料。

保存仅返回 queued_for_next_turn，不向活动模型输入、不停止原执行、不自动开始新执行。每任务最多 20 条待选/已绑定记录，每条 2000 字符；面板优先显示待处理记录和最近历史。刷新、重启保留。暂未提供浏览器未提交文字的自动草稿恢复。

## 看过结果后继续

点击“沿原目录继续”。来源必须为当前任务最新节点 Run；原执行和目录必须已确认结束。未结束或状态未知时会显示原因，允许返回记录要求或使用原有停止操作，不强制清锁。

源节点与目录固定，不可在接续中改为另一节点。目标工具/模型/预算来自该节点当前本机授权。切换 Claude/Codex 时须先结束原执行，在节点本机重新配置 enable-execution，并重启节点发布授权；本轮不在网页代为更换工具或账户。

明确选择本次要带入的要求（默认不全选），输入本次要求，展开完整发送文本，再确认目录、费用和共享输出。最多 6 条所选要求，含作者名的合计不超过 6000 字符，整个材料不超过 20000 字符；超限明确提示，不偷偷删选中的要求。

上下文包含最多 8000 字符的任务/近期人工讨论、1000 字符的来源要求和 2000 字符的来源共享输出，最终结果优先于过程文本。各处明确为摘录，不是全历史、原生 resume 或 diff 上传。节点仍检查原目录身份和持久化互斥，代码与未提交修改不会被 reset、stash、commit 或上传。

提交创建普通新 Run 并关联 previousRunId。已完成任务的按钮明确写“重开任务并接续”；模型结束不完成任务。另一成员改变材料、源 Run 更新、选中要求被编辑/撤回或节点授权变化时，旧请求被拒绝，须重新核对。

## 要求状态如何理解

“待下一轮选择”尚未发送；“已绑定派发，未收到启动确认”已固定到某次命令，不能再改写；“已随新执行启动”只依据实际 spawn，不保证模型读懂或完成了要求。记录一直保留来源和目标 Run。

明确未发启动许可就取消的派发，选中要求会退回待选，但不自动重发。若已经发出许可且启动历史不明，保留绑定，需要操作者检查原记录；可在确认后另写新的下一轮要求，不能通过删状态重跑旧命令。未选要求一直保留。

本轮节点接续没有自动等待原执行结束后启动，也没有 Operation 自动重试；preview 的既有持久化接续保持原行为。两种模式不要混为一谈。

## 本机待处理列表

先结束节点同步进程，再使用同一私有状态目录：

```bash
npm run runner -- pending-executions --state /absolute/private-node-directory
```

列表显示派发 ID、Run/Task/目录 ID、日志阶段、待 ACK 数。不显示任务原文或 Key；这是磁盘记录，不证明进程实际状态。命令使用已有状态目录互斥，运行中的节点占用时会拒绝并行操作。它不清理锁、不杀旧 PID。

需要恢复时仍应核对原进程及子进程是否全部停止，再用已有 recover-execution 的明确 STOPPED 确认保存证据，随后 start 同步。没有待处理记录也不证明机器没有平台外进程。
