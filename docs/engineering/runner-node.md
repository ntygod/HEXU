# E2b1｜独立节点配对与本机目录摘要

2026-09-26（UTC+8）。**这是同一机器上的独立节点进程，不是远程执行服务。** 仅在 team-local 控制服务启用；不接受模型任务、任意命令、文件读取或代码编辑。

## 实际启动

先使用 Node 24 启动 HEXU `team-local`（参考 [账号模式](team-local.md)），登录并创建或进入有编辑权限的项目。打开“空间与账号”下的“独立节点与授权目录”，点击“连接我的节点”，选择项目并生成配对码。

在本机、仓库之外建立 `runner.json`：

```json
{
  "controlUrl": "http://127.0.0.1:4310",
  "name": "我的开发电脑",
  "workspaces": [
    { "name": "项目工作副本", "path": "/absolute/path/to/git-root" }
  ]
}
```

地址使用实际 API 端口而不是 Vite 网页端口。当前只接受显式 `127.0.0.1` 或 `[::1]` 的回环 HTTP，不接受 localhost 别名、外部地址、凭证 URL、查询参数或重定向。控制服务继续只监听回环，不要通过代理或隧道公开。

在 HEXU 仓库构建后运行：

```bash
npm run build
npm run runner -- connect --config /absolute/path/to/runner.json
npm run runner -- start
```

connect 隐藏读取配对码，展示控制地址、所有者、空间、项目与本地目录；输入 `CONNECT` 才注册。不要把配对码、节点 token 或模型 Key 放入命令参数、shell 历史、配置样例或截图。配对码有效 10 分钟，只能绑定一个客户端，网页只显示一次；关闭面板不会取消，可在网页待配对列表撤销。

默认节点状态目录为 `~/.hexu/runner`。多节点或自定义目录时，每条命令都加相同的 `--state /absolute/private-node-directory`。状态目录必须在所有授权仓库之外、由当前用户拥有且为 0700；凭证文件为 0600，不使用全局共享默认密钥。当前没有系统钥匙串集成。只使用自己控制、没有敏感业务资料的试验目录。

## 同步内容与授权边界

最多授权 8 个 Git 根目录，不能用不同符号链接或父子目录重复注册。根目录与 Git 管理目录身份保存在本机；被替换时标为需重新授权，不自动读取新仓库。浏览器不能通过路径参数增加目录。

只上报公开别名、平台/架构、采集时间、已暂存/工作区修改/未跟踪条目/冲突数量。**不发送绝对路径、文件名、文件内容、分支、Git 远程地址、CLI 配置、环境变量或模型密钥。** 未跟踪目录按一个条目计数，submodule 不在本轮统计内；数量不等于可合并代码或不可变成果。

Git 通过参数数组调用，不启动 shell；禁用 fsmonitor、hooks、全局配置及可选索引写锁，不执行仓库安装/构建脚本。该约束不是操作系统沙箱。控制服务只接受注册目录 ID 的有界摘要，拒绝新增字段或目录。

节点绑定一个所有者、空间和项目。本机确认表示该项目的获准成员可以看到这些摘要，不表示他们能启动任务或取得文件。只有节点所有者可以撤销该节点；空间管理员不自动获得其他项目可见性。节点所有者失去项目编辑权或空间成员资格时，节点与待配对码立即永久失效，重新加入必须重新配对。

## 在线、离线、刷新与恢复

正常约每 5 秒采集和同步。连接租约为 20 秒，超过显示心跳陈旧，超过 60 秒显示离线；页面约每 5 秒刷新。离线不修改任何 Task/Run 状态。服务重启时旧连接显示待确认，节点会重新握手。

本地 SQLite 保留最多一条未获 ACK 的完整摘要，服务落盘后才返回 ACK。响应丢失重放同一序号和同一内容；跳号、同序号内容变化、服务端数据回退都停止并保留现场，不伪造成功。重连采用有界间隔退避。服务与节点的序号冲突需要核对/重新配对，不自动覆盖历史。

connect 在兑换前先保存节点凭证。服务已消费配对但响应丢失时，使用同一状态目录 `start` 可通过凭证找回节点，不再生成第二个节点。若兑换根本未成功，会明确显示节点身份未确认；核对网页后可 `disconnect --local-only` 清除本机凭证并重新配对，不能声称服务端已撤销。

同一状态目录使用进程级 SQLite 锁，不重复运行两个节点，不根据旧 PID 杀进程。异常退出由操作系统释放锁；节点不会自动启动任何付费或写代码进程。连接代次阻止旧连接迟到覆盖新连接。

`Ctrl+C`/SIGTERM 请求结束节点同步并上报断开；请求失败时网页按心跳老化，不能伪称已确认离线。再次 `start` 沿用已有身份。`--once` 只完成一次获 ACK 的同步后断开，适合本机检查。

## 状态与撤销命令

```bash
npm run runner -- status
npm run runner -- disconnect
# 仅在已核对风险、无法联系服务时删除本机凭证；仍需到网页撤销旧节点
npm run runner -- disconnect --local-only
```

status 只查看本机配置，不探测或声称节点在线。disconnect 正常情况下先在服务端撤销，再删除本机凭证；日志/游标与代码不会被删除。再次 connect 经过新的明确确认后重置旧摘要传输游标。网页撤销会阻止下一次上报并使运行中的节点退出，不撤回已被他人查看或另存的摘要。

账号退出或会话撤销不等于撤销独立设备凭证；需要停止共享时使用节点撤销或 disconnect。凭证轮换目前通过撤销后重新配对实现。

## 平台与未实现内容

Linux / Node 24 已运行工程测试，macOS 尚未实测；Windows 当前明确拒绝启动，不能将 POSIX 文件权限当作 Windows 保护。没有自动安装服务、升级分发、WSS、TLS 远程部署或系统凭证存储。

后续 E2b2 才实现独立节点 Run 派发、执行授权、接单/启动 ACK、受管写入锁、停止和恢复。当前“在线”“已配对”“目录可用”均不代表 Claude/Codex 已接通或模型账户有效。真实模型生成仍未联调。

## Git 配置隔离补充

Git 状态采集使用临时隔离的 Git 元数据目录和只读复制的有界索引，不加载原仓库的可执行配置；仅通过允许的核心布尔/换行设置读取现有对象。配置中的 clean/smudge/process 过滤器会使摘要显示“不可用”，不会执行过滤器来换取精确数字。配置在预检后变化也不会进入状态进程；采集后再次核对。稀疏工作区、分割索引等尚未覆盖的形式可能显示不可用；临时元数据随后清理，不改写原索引。这仍不是操作系统沙箱。

## E2b2 可选执行扩展

本页前述“不执行/不共享代码”仅针对默认摘要能力。E2b2 新增独立的 enable-execution，须节点本机再次明确确认；允许模型按受限文件策略读取授权目录，并把输出共享到项目。只有节点所有者可派发，不自动授权项目成员。执行/恢复与数据范围见 [节点执行说明](runner-execution.md)，不是把摘要端点改成任意命令。
