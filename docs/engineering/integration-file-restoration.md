# 明确恢复原应用文件

这是 [选择性整合](integration-application.md) 的有界逆向操作：仅处理原本人节点上**已完成、全部文件有归属证据、完成报告已获ACK**的一次应用。恢复其全部选定文件，不是通用备份、Git回滚或未知现场修复。

## 实际操作

1. 在原Task整合卡中打开“恢复原应用文件”，核对固定原应用、完成报告指纹与全部文件名。另行勾选确认后保存一次恢复请求；不能改为部分路径，也不能借原应用/候选确认直接写入。
2. 回到原节点运行页面命令，显式指定另一个**全新绝对路径**保留当前文件：

   ```sh
   npm run runner:integration-restore -- --operation <整合ID> --restoration <恢复ID> --state <原节点状态目录> --backup <新的当前文件保留目录>
   ```

3. 停止目标目录的所有执行、编辑器自动保存及其他写入者，再输入 `STOPPED_AND_RESTORE <恢复ID>`。确认同时允许读取原备份、写入全部选定路径和共享恢复阶段/文件名。只保存网页请求不代表本机写入已发生。
4. 查看独立恢复状态和最后报告。原应用仍保留“已完成”及原阶段历史；恢复完成不代表Task完成、代码质量验收或可以删除所有备份。

未开始的恢复可以另行明确取消。关闭表单只是关闭；未知回复保留原请求body与幂等key，重开只对账该请求。不能通过改body、重新创建请求或取消旧应用来猜测是否写入。

## 文件范围

- 原新增：把仍匹配原应用字节、Git执行位和inode的文件排他移到新的当前文件保留目录，不unlink。
- 原修改：从原私有备份读取已确认原文件，核对完整字节/对象ID和归属；交换回目标，同时把当前文件inode保留到新目录。
- 原删除：原路径必须仍不存在，才从原私有备份排他新增原文件。本人独占的0600/0700可见性保持，不变成组/其他人可读；写入后再次核对实际字节、身份与普通模式。
- 原备份和候选始终不变；HEAD、索引、未选文件不变。原应用新建的空父目录保留，不做目录清理。

恢复的是内容与Git执行位；不承诺恢复原inode、所有POSIX权限/ACL/扩展属性、文件时间或空目录形态。支持普通Linux本地Git目录与普通文件；相同文件权限边界沿用写回原语。不支持linked worktree、符号链接、硬链接、特殊文件/属性、Windows/macOS或跨电脑部署。

原应用必须完整完成并已确认两阶段回执。原应用部分成功、未知写入、缺日志/备份、后续用户编辑或原删除路径重新出现时，当前入口拒绝并保留现场；不强行覆盖、自动合并、从相似文件猜归属或从显示diff拼正文。必须明确处理后续修改；不能用恢复当作忽略用户编辑的捷径。

## 授权与材料

每次开始、后续文件边界和报告/旧回执都重新核对目标节点所有者、Task/项目/空间、原目标检查点与目录授权。来源已撤回或原保留对象到期不应妨碍本人恢复自己精确备份；本路径只读取原本机日志、原备份和原目标Git对象，不使用来源凭证、不读取/重建保留或接收副本，不续期。

新保留目录必须不存在、同文件系统、与所有登记代码/Git/节点私有状态、已知候选及备份互不重叠。固定父链、私有暂存、目录发布意图和真实身份均先持久记录。不能接管后来出现的目录或退化为普通覆盖/copy。

## 中断、重复与保留结算

复用原节点应用进程守卫与工作区租约。恢复使用独立claim；旧应用/旧结算的重放不能释放此次恢复或后续写入者的锁。新恢复记录写在既有应用日志中且带独立类型；旧runner无法解析时必须保留凭证，不能误认原应用已完成就清掉恢复证据。

每文件先记意图，再执行既有匿名inode排他新增或保留原inode的交换/移出；每个边界重新验证原目标提交加“尚未恢复的应用文件/已恢复文件身份”的精确并集。整组文件不是原子事务；Linux rename不是内容条件CAS，停止非受管写入者仍是前提。检测到竞态、同步未知、进程退出或部分恢复时，保留原备份、新保留目录、目标文件、原意图与锁。

重复相同命令只对账原包，不再次读取备份、确认、续写、回滚或清理。完成后的未知ACK不重写；启动ACK未知也不盲目续写。原应用、恢复阶段与保留结算报告分开，不互相覆盖。

只读查看原节点最后日志：

```sh
npm run runner:integration-status -- --operation <整合ID> --state <原节点状态目录>
```

`restorations` 显示历史确认文件、待决意图、ACK和新保留目录；仍然不读目标/备份、检查进程、联网或授权写入。`directoryChecked`/`writeAuthorized`保持false。

若恢复被中断，只有操作者明确确认原恢复进程及全部 `integration-add` / `integration-change` / `restore-publish` 子进程/孤儿进程停止后，才可**保留文件并只结算此次恢复的占用**：

```sh
npm run runner:integration-recover -- --operation <整合ID> --restoration <恢复ID> --state <原节点状态目录>
```

输入 `STOPPED <恢复ID>`。这是既有保留结算的恢复主体入口，不恢复任何文件、不读材料、不猜成功。原目录/.git/claim身份与不可变释放收据同事务核对；已释放收据重放先于目录读取，不碰后来写入者。网络或目标授权不可用时可保存本机释放结果，报告仍待发；所有相关待发包或未知证据未结算前，凭证守卫继续阻止删除/替换。

结算绑定当时唯一待发阶段包的hash；之后只允许该包或已接受的精确旧回执对账，不能再提交新开始报告。界面“占用已结算”与“文件已恢复”严格分开。
