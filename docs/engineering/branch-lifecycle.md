# 放弃方案并保留现场

在同一 Task 的“方案分支”中，已登记独立现场的方案可以明确标记为放弃，同时保留目录、未保存修改、节点权限、Run 和成果历史。它是方案生命周期动作，**不是停止进程、清理目录或完成任务**。

## 使用流程

1. 打开待放弃方案，核对独立现场和原执行当前观察。尚未准备/执行的定义仍使用原“放弃此方案”；未完成的现场准备先按原准备流程核对或取消。
2. 如果这个方案仍被选用，先到“比较与选择方案”明确取消或替换选择。放弃操作不会替你清除选择，也不会修改原选择历史。
3. 点“放弃方案并保留现场”，确认固定方案、原 Run、工作区与修订。勾选已理解只放弃方案、不会停止执行或删除文件，再明确保存。未确认或关闭未提交窗口不产生变更。
4. 已放弃卡片继续显示独立现场和原执行状态。若仍在运行，可单独点“停止此方案执行”；要等节点报告真正结束，不能把请求已保存或方案已放弃当成停止证据。状态未知时继续保留占用，并按既有节点核对流程处理。
5. 原已授权请求的迟到启动/终态仍归属原 Run，不会重新打开已放弃方案。明确终止后仍可另行保存成果版本，原输出边界和权限照常检查；保存不会把方案改回 ready，也不会选中方案或完成 Task。
6. 原成果、反馈、选择历史继续可读。已放弃方案不能新选用或新建执行；保留的固定代码成果仍可另行明确整合。没有自动“撤销放弃”或恢复执行。

放弃后会显示本次固定方案组，可返回全部组。保存回复未知时，原请求体/幂等键在关闭编辑器、关闭列表、分页与重开期间保留，通过“继续确认放弃请求”只确认同一操作，不重新构造范围。短暂读错保留确认并禁止新提交；方案/任务/当前选择变化时明确重核并重新同意，当前撤权或身份变化清除输入。

## 不改变的边界

- 不执行 Git、文件删除/移动、目录解绑、节点撤销或工作区 claim 释放，不调用模型、不重放已有执行
- 保留现场是这次动作的处置范围，不证明当前文件完整、进程已停或目录现在空闲；后来的用户修改仍由原节点核对
- 不暗中取消现有 Run，也不放宽原许可、选择变化检查、费用/超时或节点权限。既有尚未许可的接续继续按既有规则核对当前选择
- 只有原 Run 已确认终止、来源可靠且当前 Task 权限有效时才能保存成果；未知现场不能变成固定成果
- 保留原 WorkingCopy 绑定；普通执行入口不能绕过方案绑定重用目录。新工作需另行明确安排，不能借原放弃回执获得执行权限
- 已登记目录实际清理、未保存文件处置、未知现场自动恢复和解除绑定仍未支持，本轮不删除真实用户目录

## 接口与原子性

`GET /tasks/:taskId/work-branches/:branchId/discard-preview` 在当前 Task 编辑权下返回固定分支、任务修订和能否放弃的原因。`POST .../discard-preserving` 仅接受 expectedRevision、expectedTaskRevision、confirmPreserveWorkspace:true 和 confirmExecutionContinues:true，不接收任意路径、Run、停止、删除或代为清除选择字段。

当前权限在旧回执前检查；事务内重新核对修订、当前选择和已登记现场。仅分支状态/修订、discard_preserving 历史、outbox 和幂等回执同事务变化。原 Task、Run、dispatch、工作区/节点、成果/版本和选择表不变；原 `/discard` 的 planned-only 许可没有升级。旧回执重复不复活分支、不再执行一次动作。
