# 明确停止后的保留现场结算

这是整合新增应用的独立本机结算：操作者确认原应用及其所有 `integration-add` / `restore-publish` 子进程/遗留孤儿进程已经停止后，只释放本次应用的原工作区占用，并保存独立历史观察。**不修复或验证文件，不续写，不回滚，不删除文件，也不把原应用改成成功。**

## 先查看，再明确确认

```sh
npm run runner:integration-status -- --operation <整合ID> --state <原节点状态目录>
npm run runner:integration-recover -- --operation <整合ID> --state <原节点状态目录>
```

只支持原凭证/目录登记下准备中、应用中或需要处理的 Linux 普通 Git 目录。命令展示原Task/应用、固定来源版本与提交、目标提交/检查点/恢复副本、原目录和已记录数量/未确认意图。它们是历史上下文，不是当前文件检查结果。

确认前自行检查原应用进程和所有 `integration-add` / `restore-publish` 子进程/孤儿进程确实已经停止。取得应用进程守卫只能排除另一个持有该守卫的父进程，**不能证明孤儿进程已经停止**；命令不会根据旧PID发信号，也不会替你作此判断。核对后输入命令要求的 `STOPPED <应用ID>`。此确认同时允许把有界结算观察送到原Task；不授予新的模型执行、代码写入或文件共享权限。

未确认不释放锁。原根目录或`.git`被替换/移动、原绑定改变、出现其他重叠/同inode占用，或者锁已缺失而没有匹配释放收据时均拒绝。租约registry必须在原私有路径且位于代码目录之外；符号链接重定向、多硬链接文件或把registry搬入工作区都不能借本命令写入。

## 保留哪些内容

- 所有当前工作树文件、额外/忽略文件、后续人工修改、HEAD和索引原样保留；不会扫描内容或要求先丢弃修改
- 原应用阶段、已确认新增记录、未决写入意图及原待发应用报告保持独立历史。一个“看起来符合来源”的文件不会被补记成应用成功
- 新应用在写入前固定恢复上下文。旧记录只能通过当前获授权且指纹完全一致的原整合回复补齐上下文；离线/撤权且缺少旧上下文时拒绝，不猜测来源或借用新身份

完整原上下文已经保存时，来源/恢复副本过期、撤权或服务离线不妨碍这次仅保留文件的本机结算。命令不打开、续期或重新取得那些材料。当前目录内容、源材料可恢复性与代码质量仍未验证。

## 崩溃、回执和后续写入者

本机先持久保存固定停止确认与释放请求，再在租约registry的同一事务中保存不可变释放收据并删除**匹配的原目录/原应用/原身份**那一行。只有收据证明此前结算，不能从“锁不见了”推断成功。

若registry已提交而应用日志来不及更新，再次运行同一命令只核对原收据，不再次确认或释放。即使原目录后来移动，或后来有另一个合法写入者占用，旧收据的重放也不访问/清除后来占用。结果只表示本次旧占用曾被释放，不能宣传“目录现在空闲”。

原应用待发包与新结算待发包各自保存。原应用命令在已有恢复记录时只确认原待发包的精确回执，不续写、不合成新的完成/中断报告或操作租约。原包当前无权送达时继续保留，不能拿新结算观察清除它。

## 原Task里的观察

新观察只包含原整合/应用标识、固定指纹、操作者停止确认时间、旧占用释放时间、原已记录数量/未决意图标志。没有绝对路径、文件名、代码、目录身份或凭证。

共享前核对原目标节点和所有者当前Task/项目权限、原节点修订及目录授权。只共享本机租约处置，不依赖来源当前权限，也不借被撤销的目标节点凭证获得新权利。目标/Task撤权或网络失败时，本机可以已经释放，但共享仍明确显示pending并保留原包。

Task在原整合记录旁显示独立“保留文件结算观察”，保留原应用状态/报告/历史，不自动完成Task或标记代码质量通过。有结算观察后不能新发取消请求来声称“写入前取消”；此前已经提交的取消回执仍可在当前权限下精确对账。

断开/重新配对仍必须等原应用和新结算两个送达流均已确认，且释放收据匹配。已结算的历史不会因断开删掉旧凭证而永久阻止以后重新配对。尚有无法送达的旧包时保留原状态目录，不通过删除凭证绕过证据。

## 边界

本轮没有恢复旧文件、自动清理、替换/删除应用、解决冲突或自动继续执行。目录移动、遗失原凭证、缺失旧恢复上下文等情形不会自动搜索/修复。实际验证见[结算记录](../development/history/2026-09-30-integration-recovery.md)，原应用见[新增应用](integration-application.md)，下一项仍以[22](../development/22-next-delivery.md)为准。
