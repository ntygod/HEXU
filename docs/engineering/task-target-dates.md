# Task 可选目标日期

从任务详情“编辑工作说明”设置或清空目标日期；普通新建仍只需要标题、说明和项目。日期为`YYYY-MM-DD`的日历日，范围0001–9999，不转换成UTC时间戳。非法闰日、不存在日期、空白字符串和时间戳均拒绝，API以`null`清除，省略字段保留。

## 展示与筛选

详情、工作台任务行及项目列表/看板显示原日期。项目日期筛选可选全部、有日期、无日期、今天和未完成逾期，并与人员、状态、标签、关注和关键词取交集。今天采用当前浏览器本地日历；逾期仅指todo/in_progress且日期早于今天，done/cancelled保留日期但不标逾期。今天筛选本身不隐含状态条件。

日期存于URL的`targetDate`条件；空白、重复、未知值显示错误并取空结果，不静默扩大。切列表/看板、返回/前进保留条件，清除保留其他URL信息。跨本地午夜、窗口重新聚焦或恢复可见时重新计算今天，不改变Task。

## 编辑、并发与数据

日期纳入原工作说明固定修订基线、冲突对照及明确重定基线。外部更新不静默覆盖草稿。未知写回执只确认同键同正文，关闭不撤销已发请求；原请求实际包含目标日期时，保存回执才核对该日期，包含明确清除的 `null`。

工作说明编辑保留缺失日期投影 `undefined` 与明确空值 `null` 的区别。新请求中，`undefined` 始终省略；明确的 `null` 或日期字符串仅在相对用户所选提交基线有变化时发送。缺失日期草稿遇到新投影后，明确选择“保留草稿并使用当前版本”也不会把未知日期转换成清除指令；已知日期草稿的明确保留语义不变。既有待确认原包不按新规则重建，原体、原键及已有日期 ACK 约束保持。

这是组件缺失投影输入保护。正常 TaskPage 详情经 `Store.detail → taskForRead` 提供日期投影；本次没有证实正常入口发生日期丢失。复现与验证边界见[保护记录](../development/history/2026-10-08-task-target-dates.md#整合候选补充组件缺失投影输入保护)。

迁移35仅建立独立`task_target_dates`表，旧Task不补造记录。日期与原Task修订、outbox、回执同事务；旧原键返回原日期快照。内部getTask/tasks与持久Task JSON不带日期，只在workbench、detail和普通任务列表做人工读取投影；搜索游标不改。未对受限执行消费者做全链验证。

日期不是自动提醒、模型指令、停止或完成规则。日期修改使用原Task修订，已有按修订检测变化的行为仍适用。
