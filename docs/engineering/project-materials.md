# 项目材料选材与执行快照

`HX-DEV-05-05/06` 的确定性选材切片。沿用 Task / Run / ContinuationOperation，资料/约定仍是独立内容对象；选择它们不会增加工具、目录、节点或账号权限。

## 使用

在原生或本人节点的执行面板打开“选择项目材料”，选择当前项目资料或有效约定。初始不额外选择项目材料；任务说明、近期讨论以及既有接续材料仍按原规则准备。目录按当前 Task/项目权限过滤，私有任务没有项目选材，但可继续使用任务说明执行。查看资料不等于可以使用其他人的节点。

每项固定 kind/id/revision/contentHash/maxChars；可选择全文、前 3000 或前 1000 字符。最多 16 项，补充材料连同来源标识最多 10000 字符；超限明确报错，绝不自动截掉所选条目。摘录显示未包含字符数，并避免拆开 UTF-16 字符对。链接只发送引用及说明，不读取外部页面。材料按既有已知敏感格式遮盖规则处理，不能将其当成完整 DLP。

选材预览显示实际补充文本。节点完整输入上限 20000 字符，当前原生预览路径上限 60000 字符；这些是当前应用上限，不是模型 token 窗口或费用保证。超限可减少选项、缩短摘录/要求。改变选材、版本、要求或执行配置会使原执行确认失效。采用最新版本仍需重新确认，不会自动启动。

资料变更后保留已选版本与本次要求；旧版本不可提交，需要取消选择或明确核对并采用最新版本。新保存且未选择的资料不会悄悄加入。原生恢复会继承节点保留的原会话，取消本次选材不清除原历史；近期讨论中已有的相同文字也不因取消补充选材而删除。

## 保存与启动

预览是无持久副作用的读取，不保存草稿。用户实际提交时，快照与 Run 或 Operation 在同一事务保存。迁移 15 新增 `context_bundles`；已有运行/安排不补造选材或送达记录。

原生直接执行固定并记录实际完整输入；等待接续固定项目补充材料，停止后仍按原规则重建本地代码/输出摘录，然后与同一快照绑定。节点等待安排在保存时固定完整输入；创建后续 Run 复用同一 bundle，不重复追加项目材料。取消或暂停保留快照。

创建执行、等待协调、最终 Run 事务和原生 spawn/节点一次性许可前重新核对当前权限、所选资源版本及状态。所选材料变更会阻止未启动工作；等待计划会先暂停，再决定是否需要发停止信号。已发停止请求不撤销，未知进程占用不释放，已获许可的工作不被假装收回或自动重试。

运行记录区分“材料已固定，尚无启动确认”“执行器已确认启动”“启动状态待核对”。只有真实原生 spawn 或节点 running 事件才记录启动确认；队列、节点 ACK、许可和 Operation.succeeded 都不能代替它。**这仍不是 provider receipt 或模型已理解证明。** 后续资料编辑不修改已固定输入。历史记录在当前 Task/项目权限下读取。

执行 HTTP 回执不确定时，面板保存原请求的要求、选材、配置与幂等键，只能确认该请求或关闭后检查记录；确认不会生成另一份付费执行。关闭页面不撤回已提交工作。

## 接口与边界

- `GET /tasks/:id/project-materials`：有界目录，q/kind/cursor/limit，默认 20、最多 50。
- `POST /tasks/:id/project-materials/preview`：`{items:[{kind,id,revision,contentHash,maxChars}]}`，返回补充文本、截断/遮盖标记与 hash。
- 原生/节点的 `POST /tasks/:id/runs` 和 `/continuations` 可带 `projectMaterials:{items,expectedHash}`。新增界面同时提交 `expectedTaskContextHash`，防止人工要求预览过期；旧调用不带选材时保持原路径。
- `GET /runs/:id/materials` 与 `GET /tasks/:id/material-bundles/:bundleId`：固定版本、实际输入和启动记录。

模拟执行不接受模型选材参数，不冒充真实发送。节点服务仍不接收 provider key，Cookie 与 Bearer 通道分开。真实模型联调、AI 总结、自动按目的推荐材料、持久选材偏好、附件/文件上传、跨项目共享和跨电脑部署仍未交付。实际检查见 [21](../development/21-implementation-status.md)。
