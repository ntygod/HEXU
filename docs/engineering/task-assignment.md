# 任务负责人改派与身份记录

本轮是 04-01 的本机项目协作切片。真人负责人、创建者与执行发起者分别记录；改派不是代码接手、共享授权或原生会话迁移。

## 使用

在项目可见任务头部点击“更改负责人”，选择当前具有项目编辑/管理权限的成员并保存。任务编辑者和管理者均可操作；只读成员只能查看改派历史。preview 的候选人明确为示例成员，不代表真实账号。归档项目仍可进行这类人工协作，但归档的执行限制不变。

候选人需同时具备当前空间和项目成员关系，不能选择其他项目成员、已移除成员或只读成员。已有负责人转为只读或退出项目时，显示当前不可分配状态，不自动换人、不自动补权限；有编辑权的人可以重新安排。退出者的姓名只从本任务已记录历史保留，无已知姓名时明确未知。

抽屉固定打开时的任务修订。其他页面更改任务后，保留本页选择并展示冲突，需要明确载入最新负责人或在核对后保留选择。网络回执不确定时，“确认上次改派结果”复用原载荷与幂等键，不新增一次改派。关闭并不撤销已发请求；关闭、刷新、身份/空间切换或任务编辑权被撤销时清除抽屉内存，重新授权不复原旧选择。

## 对执行的影响

已经运行、已经获得一次性启动许可或状态未知的 Run 保留原身份和运行状态，不因改派转移节点、账户、原生历史或目录锁，也不会被自动停止。新负责人想执行时仍须单独具备节点所有权和本机明确授权。改派不发实时模型输入，不承诺修改正在处理的原要求。

等待或准备接续的 preview/node Operation 同事务转为 `needs_attention`，显示 `TASK_ASSIGNMENT_CHANGED`，保留原材料、选择的要求、原发起者和已发出的停止请求。把负责人再改回去也不会重新启动旧安排。尚未许可的旧派发保持原始命令，在请求许可时因任务修订变化被拒绝，不能自动用新责任信息重发。

每次真正的新执行单独保存发起者；Task 的创建者不跟随负责人更改。Task 完成仍是人工操作，改派不改变状态，不自动重开已完成任务或创建新 Run。

## 接口与事务

`GET /api/v1/tasks/:id/assignment` 返回任务修订、当前负责人的成员状态以及允许分配的人（仅 ID/姓名，不含邮箱或凭证）。

`POST /api/v1/tasks/:id/assignment` 严格接受 `{expectedRevision, ownerUserId}`，使用现有 Cookie/空间上下文和幂等请求头。先核对当前任务编辑权，再读取旧回执；事务内再次检查权限、修订和候选人的当前成员关系。无改动不制造修订或改派记录。同键异内容、旧修订或失效候选人明确冲突。普通任务创建/PATCH 不接受负责人、创建者或访问范围注入。

`GET /api/v1/tasks/:id/assignment-history?limit=10&before=12` 以任务修订倒序分页，最多 50 条。只能按当前父任务权限读取；记录改派前后身份、当时已知姓名、操作者与时间。私有任务拒绝本轮改派/历史入口，不会因此共享给目标用户。

迁移 11 新增 `task_assignment_events`。任务 owner/revision、改派记录、待接续暂停、任务范围 outbox 和回执原子提交。新 Task/Run 保存 `createdByUserId`；旧记录字段缺失时补 null，不把当前负责人当成历史创建者，也不补造过去改派记录。原 Task、Run、Operation、成员与目录 ID 不变。

## 验证与剩余

结果见 [21](../development/21-implementation-status.md)。测试使用虚构用户及原生协议替身，不调用真实模型。参与者关系、完整负责人/参与者筛选、跨空间/私有选择性共享、实际代码接手仍未实现。部署仍只支持同机回环；不因任务改派宣称远程节点、桌面宿主或真实 Claude/Codex 模型联调完成。
