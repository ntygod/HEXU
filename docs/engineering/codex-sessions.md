# E2c1｜Codex 节点私有会话与显式恢复

2026-09-26（UTC+8）。只适用于同机回环中的本人独立节点。默认新会话行为保持不变。**实验性实现：有效账户下真实模型生成及历史恢复仍未联调。**

## 开启和使用

先停止该 Runner，在既有本机 execution.json 中为 Codex 添加 `"retainSessions": true`，执行 `enable-execution --config /absolute/execution.json --state /absolute/private-node-state`，阅读原生历史保留提示后确认 EXECUTE，再 start。配置仍要求仓库外的工具绝对路径、已配对目录、只读/编辑模式、时间上限；Codex 的美元硬预算不受支持。密钥只从节点本机 OPENAI_API_KEY 读取，不放入配置或仓库。

第一次开始任务时仍调用 thread/start，但本次可选择保留的会话不是 ephemeral。只有该次执行有成功协议终态、有效 thread/turn/model 引用和已确认进程退出，任务卡才显示“节点已保留原生会话引用”。这表示节点曾报告保留，不保证随后文件、账户或提供方状态仍有效。

要恢复，打开该任务最新一次成功执行的“沿原目录继续”，选择“恢复 Codex 原生会话（实验性）”，核对模式、材料与费用后发起。本轮走原有 201+Run 单次派发；自动 wait/request_stop 的 202 Operation 仍只用于新会话。原生恢复必须先成功结束，不能对活动、未知、失败或取消的源执行自动接管。

新会话继续只发送本次选择的公开材料；**原生恢复还会沿用 Codex 私有原生历史**。下方文本预览只代表新增材料，取消勾选不能删除已经存在的原生历史。没有导入个人 Codex HOME、跨任务、跨工具、跨节点、跨账号或跨模式的恢复。第一次开启保留前的历史也不能补救成可恢复会话。

## 绑定与失败

恢复使用 thread/read 元数据核对，再调用 thread/resume，最后独立调用 turn/start。检查 ID、目录、权限与模型；不会在恢复失败时悄悄调用 thread/start。节点恢复准备期间取消后，不发送后续 turn/start。

本机绑定包括控制地址、节点/项目/任务/目录 ID、本机目录文件身份、工具路径、版本和完整授权策略、运行模式以及 API key 的带节点密钥 HMAC。原始 Key 和指纹不上传。**换 Key 即使属于同账户也要新建会话**；重新 enable-execution 会产生新策略，旧会话不再符合绑定。工具版本变化同样需要重新授权，不承诺自动兼容升级。

会话缺失、到期、含符号链接/特殊文件或超过检查上限时，执行明确失败，不改代码、不清除未知进程占用来强行恢复。恢复派发成功与模型成功分开；没有真实完成事件不能标为恢复成功。节点意外退出会将 active 会话标为 blocked，不自动恢复付费工作。普通 ready 会话可以跨 Runner 进程重启保留。

## 本机存储、期限与清理

每个会话在同一节点私有状态目录的 `codex-sessions/<opaque-ref>` 下持久化，父目录权限 0700，必须位于所有可写授权根之外。thread/turn/model 与绑定摘要留在节点 SQLite。控制服务只保存不透明引用、创建/恢复动作和截止日期，不提供下载原生历史的接口。原生程序可能在私有文件中存储完整历史；输出脱敏不是通用数据防泄漏系统，文件策略也不是操作系统沙箱。

恢复期限为首次创建起 7 天。**超过 7 天并不自动删除历史文件**，本地持久存储仍需操作者清理。每节点最多 32 个未清理记录；准备/结束时检查每会话不超过 4096 项、64 MiB，运行中不是连续磁盘配额。超限会拒绝本次保留/恢复；需按实际磁盘策略清理，不以此声称无限会话归档。

停止 Runner 后执行：

```bash
npm run runner -- native-sessions --state /absolute/private-node-state
npm run runner -- forget-native-session --session <列表中的ref> --state /absolute/private-node-state
# 核对目标后输入 FORGET <同一ref>
```

列表只有不透明 ID、状态和期限，不打印原生 thread ID、历史正文或 Key。清理先检查对应执行已确认终态，再写删除标记并清理该私有历史；不会删除 Git 文件和 HEXU 的共享任务记录。未知执行要先按原恢复流程核对进程，不能靠清会话解除锁。持有本机文件系统管理权限的人仍可读取文件，本功能不提供跨 OS 用户安全隔离或加密备份。

## 验证范围

自动化使用明确的 Codex 协议替身和随机私有历史：首次结果不输出该随机历史，第二个独立进程只能从保留文件恢复。验证 read/resume 而非 start、新会话独立、重复派发去重、缺历史/错 ID/换 Key/到期/异常重启不恢复，以及权限和取消。真实提供方的成功恢复必须另用授权账户验证，不能从替身成功推断。

官方无模型协议检查命令：`npm run check:codex-protocol -- /absolute/path/to/codex`。它只做握手、受限配置与不存在会话的 read/resume 拒绝，不认证、不启动 turn、不调用模型。具体执行结果以 [21](../development/21-implementation-status.md) 中的实际记录为准。
