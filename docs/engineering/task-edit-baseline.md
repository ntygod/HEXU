# 工作说明编辑的固定基线与原请求确认

「编辑工作说明」仍只修改同一个Task的标题、说明和关注事项，不建立独立Requirement、说明历史或新的执行命令。本切片修正旧表单将已输入的文字与SSE更新后的Task修订号混合提交的问题。

编辑从明确的Task ID、修订号和原始内容开始。外部任务更新可以提示并展示原/当前内容，但不静默改提交基线或替换草稿。冲突或暂时故障保留当前输入；丢弃草稿、载入新基线必须由成员明确选择。

未知写入仅确认同一个原PATCH正文、修订号和Idempotency-Key；确认不是重新编辑提交，也不把最新Task投影冒充原保存回执。旧回应不能清掉另一份新草稿、关闭后来打开的编辑器或把页面导航抢回来。完成/取消已发送HTTP请求不是撤回服务器写入，界面需区分未提交草稿与原请求待确认。

临时草稿/原包按既有身份、空间和Task的Provider内存隔离，不写浏览器持久存储。暂时任务读取失败仅在当前Workbench仍可见时保留已有详情/编辑器并提示重读；成功Workbench移除Task或详情明确拒绝时清除旧内容、上下文抽屉及Task编辑草稿与原包，即使旧Workbench快照尚未刷新，也不能在重授或重读后复活旧内容。

后台仍使用原Task PATCH语义、当前编辑权限、expectedRevision、Task/outbox/回执事务。旧回执之前也核对事务内当前权限；Task状态、负责人、访问范围、Run、Operation及冻结材料不受内容表单扩大修改。标题160、说明12000、关注事项300字符限制保持，路由只为这些已有上限提供对应的有界请求字节预算。
