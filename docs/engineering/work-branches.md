# 同一任务的方案分支定义

当前支持真实账号的项目任务，围绕一个目标定义2—6条独立方案，固定共同代码提交和当时任务说明。定义后的状态为「待准备」，尚无独立目录、Run 或结果；它是后续隔离探索的输入，不等于已启动并行执行。

## 使用

1. 先通过本任务「代码检查点」记录一个真实、完整的提交引用，参见[提交检查点](commit-checkpoints.md)。当前起点选择列出最近50份已记录引用，不接受 HEAD、未完成请求或其他任务的检查点。
2. 打开「方案分支 → 定义一组方案」，核对共同任务标题/说明和提交，分别填写各方案名称与独立目标。每组名称不得重复，目标最长3000字符。
3. 「保存方案组」固定当时任务修订、说明、完整提交引用和共同起点指纹；各方案一起保存，没有半组创建。后续 Task 变化只提示原组版本较旧，不重写起点。
4. 需要重新考虑时，可明确放弃某条待准备方案；其他方案保留。展开历史可查看定义/放弃的操作者和时间。放弃定义不删除代码、不停止任何 Run，也不完成任务。

共同内容仅包括保存时的任务标题/说明与所选提交引用，不自动包含全部讨论、项目资料或当前未提交文件。引用是历史核对结果，不保证对象仍存在，也不授予目录/材料使用权；实际准备目录时仍需验证来源和授权。工具、模型与预算留待实际执行配置，不虚构已安排的工具。

## 冲突与回执

编辑期间任务变化会显示新版说明，保留已填方案，并要求明确核对后才采用新基线。短暂读取失败保留草稿；失去编辑权限清除临时编辑，仍有阅读权限时保留历史。身份/空间切换不带走草稿。

回复未知时「确认上次方案请求」使用完全相同的正文/幂等键。刷新从服务读取原组，重复成功请求返回当前状态而不重新创建或复活已放弃方案。关闭编辑窗口不会撤销已发送请求。

当前项目编辑者可定义和放弃，查看者只能读；所有列表、直接 ID、历史与回执受父任务当前权限保护。每任务最多200组，列表按组分页，每页10组，组内方案完整显示。归档项目仍允许人类整理方案，执行许可按原运行规则单独处理。

## API 与后续范围

`/api/v1/tasks/:taskId/work-branches` 的 GET 返回按组分页的定义，POST 接受 `expectedTaskRevision`、`checkpointId` 和 `branches:[{name,goal}]`，需幂等键。`GET .../options` 读取编辑基线与引用选择；`GET .../groups/:groupId` 读单组；`GET .../:branchId/history` 读方案历史；`POST .../:branchId/discard` 接受 `expectedRevision`。

迁移27只增加方案组、方案和事件，不从旧执行/引用补造方案。各方案的 `workingCopyId`、`runId`、`resultId` 当前保持 null；仅支持 planned/discarded，其他产品状态将在对应真实能力交付时加入。

独立现场准备、实际并发/预算、Run/Result 绑定、对比选择、整合与清理仍按 [13工作包](../development/13-parallel-exploration.md)推进，唯一下一项见 [22](../development/22-next-delivery.md)。
