# 固定版本反馈转后续任务

在项目可见成果详情的“此版本的反馈”下选择一条反馈，再点“建立后续任务”。新任务草稿带入成果标题、原任务编号、所看版本的固定链接、反馈ID/作者和完整反馈。修改标题或说明后，点击“创建任务”才保存。

## 范围与行为

- 仅当前可编辑的项目可见Task；目标固定为同一项目。个人或私有成果入口禁用，不能借此跨项目携带材料。
- 只允许属于同Task、同Result、明确绑定所看ResultRevision的反馈；未指定版本的历史反馈不自动归入当前版。
- 后续Task沿用普通创建：负责人为本人，状态todo，不启动Run，也不完成、重开或修改原Task/成果/反馈。
- 来源保存在可编辑工作说明中；不是结构化父子任务、依赖、双向关系或自动同步。用户可以编辑来源说明，不据此声称系统建立了关系模型。
- 原文与来源说明超过12000字符时保留全文并阻止保存，须由人明确精简；标题遵守原160字符上限，不切断代理对。选项预览有省略，实际草稿不省略反馈。

## 取消、变化和未知结果

未提交时取消、离开页面或切版本会放弃本地草稿，不发送写入。来源任务不再可见、移到其他项目、变为私有，或反馈被移除/改变时，未提交编辑关闭，不悄悄采用新的来源。

首次提交后复用原创建控制器。若已有任何未确认创建，从此入口优先恢复它，不能把所选反馈覆盖到旧请求；其他新建入口同样可恢复后续任务的原包。未知结果只重发同键同正文；有效ACK后刷新失败仅重新读取。关闭弹窗不撤销已发请求，不跨硬刷新保留。
