# 已知未发布试应用暂存的明确处置

私有试应用在已记录的失败/中断后，可能留有 `.hexu-restore-<试应用ID>` 暂存并阻止节点断开。仅当暂存身份与全部现存文件归属已知、没有未决写入意图、从未确认发布时，可在**原本人 Linux 节点**明确删除这份失败材料。

```sh
npm run build:server
npm run runner:integration-trial-cleanup -- \
  --operation '<原整合ID>' \
  --trial '<原试应用ID>' \
  --state '<原节点状态目录>'
```

不接受任意目标路径、force 或递归清理参数。原 `runner:integration-trial` 失败输出会在符合历史范围时提示此命令；提示本身不证明当前暂存仍可清理。

命令先取得原日志的进程守卫，并展示固定整合/试应用、失败历史、原暂存完整位置、不会删除的候选目标、已记录文件/字节和归属数量。只有本人已确认原试应用、全部子进程/遗留孤儿进程以及所有其他暂存写入者停止，且同意永久删除这份暂存时，才输入：

```text
STOPPED_AND_CLEAN <原试应用ID>
```

取消或不同输入保持文件。此确认不停止任何进程，不自动发送信号，不保证所有外部写入者确实停止；操作者必须自行核对。目标代码、已发布候选、对象副本、应用备份及 Task/Run/Result 都不在删除范围。

## 只处理已知归属

- 本机原凭证绑定与日志身份必须保持；不初始化缺失日志，不读取服务/来源材料，不续期或请求新授权。副本到期、服务离线或远端撤权不阻止原本人明确处置自己的这份暂存。
- 原历史必须 failed/interrupted、materialState:staging、有精确 stageIdentity、intent:null、publishedAt:null，且没有共享候选差异。已发布、疑似发布、未知意图/归属和此前清理中断均拒绝。
- 固定父链与目录描述符核对、原目标仍不存在、所有注册代码/Git/节点状态隔离；暂存须为原私有目录。先完整核对所有权清单，再删除精确文件和目录。用户新增/编辑、同内容换inode、符号链接/硬链接、父链/暂存身份变化或目标后来出现均保留，不递归扫描删除“看起来多余”的文件。
- 等待确认后重新核对全部现场；清理意图先持久化，再复用既有精确归属清理原语。删除前逐项重查，异常立即停止；它不是应对未停止外部写入者的内容CAS。
- 原试应用阶段、计数、材料历史和所有权条目保留不改写；进度中另有绑定原证据指纹的 cleanup 回执。原 materialState 仍是历史，不表示清理后暂存继续存在。
- 成功回执仅让当前版本的凭证守卫认可这一次材料已处置，其他待发差异、应用、恢复和活动守卫照常检查。旧runner仍会因原未结算材料历史拒绝删除凭证，不能降级绕过。

完整成功后的重复只返回原清理收据，不检查或删除后来同名目录。删除或最终回执未知时保留 cleaning/needs_attention、完整原所有权证据和原凭证；不能仅因为暂存已不存在就推断成功，也不自动重试剩余删除。此版本不接管这些未知处置。

本命令不释放原目标工作区锁，不恢复文件、不重新生成候选，也不清理已发布候选。需要再次试应用时另选新的输出目录，原记录不会因删除而变成可重新写入。
