# 项目任务的持久排序

在项目“任务”的列表或看板中选择“整理顺序”，通过上移/下移、更多排序菜单或拖动安排任务。菜单选择参照任务及之前/之后，键盘可完成同样操作；看板只在同列移动，拖到另一状态列不会修改状态。已取消任务继续只读，原Task链接可打开详情。

排序保存在项目中，刷新及另一个当前同项目页面沿相同顺序读取。人员、状态、关键词与关注筛选仍取原交集；筛选隐藏项彼此顺序保持。列表可以跨主状态排序，看板按状态分组后取同一顺序。项目总览、成果、工作台和全局搜索保持原顺序，Task标题/说明/状态/修订和Run不随排序改变。

未进行手动排序的项目沿原任务顺序；迁移不伪造旧移动。开始排序后新增Task排在已排序任务之后，新任务彼此仍沿原创建顺序倒序。项目自己的排序修订与Task修订独立。

## 冲突和中断

菜单和拖动固定开始时的排序基线。另一个页面移动任务、任务集合或状态改变后，过期移动明确返回冲突；页面重新读取顺序并保留提示，须重新选择位置，不自动把原移动套到新顺序。内容编辑不改变排序基线。

普通连接中断、回包丢失或无法识别ACK时，页面保留原Task、参照、前后位置、基线和幂等键。“确认上次排序”只发送完全相同的包，其他移动暂时禁用。收到有效ACK后读取失败，“读取最新顺序”只GET，不再POST。

关闭整理控制、切换同项目列表/看板或筛选不会撤回已发送操作；重开可确认同一未结包。临时包仅在当前项目页面内存，离开项目或硬刷新会丢失；回来先核对实际顺序。旧读取或移动的普通迟到结果不得覆盖新项目/新交互。当前权限继续来自既有项目和Task投影，不增加身份逻辑。

短暂后台读取失败保留同一集合最后读取的行顺序、未提交菜单和选择，明确提示并暂停实际移动；成功重读后才允许新移动，菜单原基线仍固定。集合改变时不以旧排序宣称当前顺序。
