# E2b2｜独立节点本人授权执行

2026-09-26（UTC+8）。本说明接续 [节点配对](runner-node.md)。仍只支持回环地址上的独立进程，不是跨电脑部署。默认摘要配对不会开放执行。

## 1. 在节点本机明确启用

先配对并停止正在同步的 Runner；命令都使用相同 `--state` 目录。安装需要的 Claude Code 或 Codex，以该工具自己的 API key 环境变量供给 `enable-execution` 和 `start`：Claude 使用 `ANTHROPIC_API_KEY`，Codex 使用 `OPENAI_API_KEY`。Runner 不自动读取 HEXU 的 `.env`，不继承控制服务账户，也不复用个人订阅登录。不要把 Key 放进 argv、JSON、网页、任务或截图。

在仓库和节点状态目录之外准备本机配置，例如 Claude：

```json
{
  "tool": "claude-code",
  "executable": "/absolute/path/to/claude",
  "mode": "edit",
  "workspaces": ["项目工作副本"],
  "timeoutSeconds": 300,
  "maxTurns": 8,
  "maxBudgetUsd": 1
}
```

目录使用已经配对的公开别名，不接受网页传入路径。工具必须是仓库外的本机绝对路径，不能来自获准编辑目录。可选 model 为工具实际支持的模型名称，不提供永久推荐列表。只读分析用 mode=read-only。Codex 配置 tool=codex 和对应 executable；maxBudgetUsd 必须为 null，不能承诺美元硬预算。

```bash
npm run build
npm run runner -- enable-execution --config /absolute/path/execution.json --state /absolute/private-node-state
# 查看工具、模式、项目、目录和费用范围，输入 EXECUTE 后才保存
npm run runner -- start --state /absolute/private-node-state
```

工具缺必要受限能力或版本变化时拒绝发布，不自动降权/升级。API key 存在和工具检测成功不代表账户余额、模型权限或真实生成已经验证。每个节点当前配置一个工具/一份策略，可停止节点后重新启用另一工具，但不是自动跨工具接续。

本机授权文件为 0600，保存在私有状态目录；其中没有 API key。普通配对只允许摘要；可选执行明确允许模型按工具文件策略读取授权目录，并把有界输出共享到项目。这是范围增加，必须单独确认。

## 2. 网页派发

登录节点所有者账号，进入同项目任务 →“在节点上执行”→选择本人已启用的节点、目录和本次只读/编辑模式。工具/模型和限额来自本机策略，网页不能替换可执行文件、添加目录或换另一个人的账户。

查看任务材料、填写本次要求并确认共享输出与费用。系统保存 Run 和派发；任务页分别展示接单、启动许可、实际进程开始及结束。排队中的任务修订/人工讨论变化会取消启动，不静默发送新要求。已完成任务需明确重新打开；工具完成不会自动把任务设为完成。

本轮只有节点所有者可派发。项目编辑者可以对项目中已有执行请求停止，只读者不能停止；任何项目成员都不会因为能看摘要而取得本机运行权。节点绑定一个项目，个人私有任务不会发送到该项目节点。

## 3. 重复请求、断线与恢复

命令、接单和事件先落盘。服务端启动许可只返回一次；回应丢失时不会再发可重复的启动许可。节点发现已有 accepted/preparing/running/unknown 日志，不会第二次 spawn。这个保守策略可能要求手动重建一次没有实际启动的任务执行，但避免重复付费与重复写入。

每个节点一次处理一个执行。preview 与各独立节点在同一 OS 用户下共用 `~/.hexu/workspace-leases/registry.sqlite`，同时保护相同及父子重叠目录。不能把租约超时当作原进程已退出；未知占用会保留。不要删除锁数据库或改变 HOME 来绕过锁。它不协调不同 OS 用户、其他工具或外部 IDE，不是 OS 沙箱。

通信失败会请求停止本机当前进程，恢复后只补发已保存事件，不自动重跑。服务重启取消尚未取得许可的派发；已发许可的记录标未知直到节点证据到达。节点重启不根据旧 PID 发信号、不自动恢复原生会话。

未知执行应由本机操作者检查原工具及其子进程。确认全部结束后：

```bash
npm run runner -- recover-execution --dispatch <任务页中的派发ID> --state /absolute/private-node-state
# 确认现场后输入 STOPPED <同一派发ID>
npm run runner -- start --state /absolute/private-node-state
```

恢复命令保留文件并保存停止证据，start 负责送达，不重新执行。目录被移动/替换或状态损坏可能需要人工恢复原授权现场；不要以清库/重新配对伪造停止。未核对执行或终态证据未获服务 ACK 时，disconnect（含 local-only）会拒绝删除凭证，以免失去结算原派发的能力。

## 4. 停止、关闭和撤权

网页“停止节点执行”先保存请求，只有节点确认受管进程结束才显示已停止。Ctrl+C/SIGTERM 会请求停止并尽力送达证据。取消/停止不 reset、stash、提交或删除代码。

先结束节点进程，再 `disable-execution --state ...` 关闭本机策略。已经退出的旧连接按心跳到期停止可用；需要立即阻止服务接新请求时在网页撤销节点。重新 start 后不发布执行授权。账号退出或 Cookie 撤销不等于设备撤销。

项目/空间权限撤销使节点凭证永久失效，不能重新加入后复活。旧节点仅能对已经绑定的派发排空序号和提交终态确认，不能读取新命令或共享新的输出。已被成员看到/另存的历史内容不能追回。

## 5. 输出和边界

每个执行最多共享 60 段常规文本，另存截断提示和最终摘要；不是完整原生日志。已知 API key、设备 token 和本机根路径会被脱敏，但不能识别所有业务敏感内容。请只使用明确允许共享的非敏感试验目录。模型输出可能包含读取到的代码，不能把摘要模式的“不上传代码”承诺套到已授权的执行模式。

原生 CLI 的联网仅用于自身模型调用，未开放任意 Shell、MCP、仓库 Hooks、额外网络工具或自动账户兜底。文件策略不替代 OS 沙箱。Codex 不支持美元硬预算；此版本不提供完整用量账本、费用准确性或生产安全审计。

本轮没有原生 resume/steer、运行中追加要求、节点跨工具继续、远程 diff/终端/通用预览、指定其他成员操作权限和跨电脑服务。Linux 工程测试使用协议替身；有效账户的真实模型生成仍未联调。macOS 未实测，Windows 明确拒绝。
