# 成果的固定代码引用与只读对比

在[方案成果](branch-results.md)中可关联本人方案节点在来源Run结束后明确记录的提交引用，并选填该引用已有的对象副本。固定提交、对象保留、共享差异、可恢复现场分别记录；不从工作目录的变更数量或Run成功推断代码已经备份。

## 固定代码来源

1. 等来源Run确认终止。在该方案的已登记节点/WorkingCopy中，按[提交检查点](commit-checkpoints.md)明确记录希望作为成果的完整提交ID；请求本身也需在Run结束后创建。不会自动commit、stash、reset或包含未提交文件。
2. 如需保留对象，另按[对象保留](checkpoint-retention.md)在原节点确认。保留是单提交快照，不包含祖先、LFS实体、子模块仓库等内容。
3. 打开方案「保存成果版本」，从「成果代码引用」选择该提交，可选关联当前有效副本。保存新ResultRevision，不改写旧版本/反馈/选择。引用可能包含Run结束后的人工修改，不能把整份代码归功于来源Run。

只有原节点本人能新增代码关联。其他项目编辑者仍可保存文字、比较或选择已共享版本；查看者可读。旧起点记录、另一方案节点/目录、来源Run尚未结束、节点活动/未知或撤权均不能作为新代码关联。原保存回执也重新验证当前授权与所选副本状态。

## 核验并共享差异

保存带代码引用的版本后，在原方案节点执行：

```bash
npm run runner:result-code -- --revision RESULT_REVISION_ID --state /path/to/node-state
```

先核对共同输入提交与所选输出提交，输入 `DIFF RESULT_REVISION_ID`；命令从授权仓库原始Git对象核验两个快照，在本机展示待共享文件名与正文。核对后再输入 `SHARE_DIFF RESULT_REVISION_ID`，才向原Task的有权限成员共享。

- 支持同机Linux、SHA-1/SHA-256和现有标准linked worktree范围；复用隔离Git元数据读取。不会运行外部diff、仓库hooks/filters、模型或工作目录代码，也不会修改HEAD/index/文件。
- 不读入未提交、暂存、未跟踪或忽略内容。符号链接、子模块、LFS指针、歧义名字或超出快照边界时整份拒绝。节点私有状态不能位于代码目录内；本机执行日志或重叠目录仍有占用时拒绝。
- 共享包最多24 KiB、40个变化文件；单侧完整UTF-8文本最多8 KiB。新增、删除、内容/模式变化分别记录，二进制、大文件与正文预算省略明确显示。文件总数与未列出的数量保留，绝不把截断正文冒充完整文件。
- 成果页和比较页显示两侧文件内容，只作只读比较；这不是可直接应用的完整补丁。对象副本到期/删除不会重写版本或已共享差异，页面单独显示当前副本状态。差异命令重新读取授权仓库，不借过期副本取得材料读取权。

同一版本只能共享一份固定差异。待发包先保存在原节点私有日志，再发送；回复未知时重复原命令只对账原包，不重新采集。成功重放只返回既有结果。撤权后不能借旧包或新凭证继续发布；未确认包保留，本批没有增加待发包清理命令。关闭终端不撤回已经共享的内容。

## 数据与接口

ResultRevision来源的`code`可为`not_captured`或固定`commit_reference`；后者保存共同基线、完整提交引用、可选保留清单及指纹。迁移30增加每版本最多一份的不可变差异报告，报告与outbox原子保存；不会修改既有ResultRevision正文。

- 保存成果原接口额外接受可选`codeCheckpointId`和`codeRetentionId`。预览返回本人当前可选引用，最多最近50份；保留选择必须属于相同引用和目录。
- `GET /results/:resultId[/versions/:revisionId]`补充代码副本状态、共享差异和是否可由当前本人节点操作的投影。
- `/runner/v1/result-code-inspect`与`result-code-publish`只接受独立Node Bearer通道，不接收浏览器Cookie、路径或任意文件读取请求。发布严格校验原版本/引用指纹、预算、结构与文本blob哈希；源树遍历来自原节点核验，不把服务端校验称为再次读取了完整仓库。

原本人可在原目录核对实际代码后[从所选方案继续](branch-continuation.md)。仍未交付：未提交文件/补丁的明确捕获、完整文件下载与对象托管、行级差异/评论、真实预览、脏现场/跨目录接续和代码整合。当前材料不能直接作为恢复成功或代码已合并的证明。验证和下一项见 [21](../development/21-implementation-status.md)/[22](../development/22-next-delivery.md)。
